# packaging/m2ac5 — M2-AC5 Windows 打包链（build tooling only）

本目录是 M2-AC5 的最小可复现 Windows 打包链：PyInstaller onedir 自包含 Core
sidecar + Tauri NSIS 安装包。**全部内容仅为本 Task 构建工具**，不进产品运行时
依赖清单（产品 `requirements.txt` 零改动）；产物全部落在 gitignored 的
`apps/desktop/src-tauri/target/**`。

## 2. 构建步骤

### 2.0 fresh checkout：先跑 build_sidecar.ps1（M2-AC5-BUILD-FRESH-CHECKOUT）

> 注意（DSH r1 P3-2）：cargo 路径前置不止 sidecar——`frontend/dist` 同为 gitignored 构建产物（`frontendDist`），fresh checkout 需先完成 frontend build（§2a），否则 `generate_context!` 将以类似方式失败。


sidecar onedir 产物（`apps/desktop/src-tauri/target/core-sidecar/core-sidecar/`）
是 **gitignored 构建产物**：fresh clone / fresh worktree 里不存在，而
`tauri.conf.json` 的 `bundle.resources` 引用它，任何 cargo 驱动的构建
（`cargo check` / `cargo test` / `cargo build` / `tauri build`）在编译期都
需要它存在。

因此 fresh checkout 的第一件事（先于一切 cargo 命令）：

```powershell
# 若还没有构建 venv，先按 §1 建好（一次性）
powershell -NoProfile -ExecutionPolicy Bypass -File packaging/m2ac5/build_sidecar.ps1
```

然后即可正常 `cargo check` / `cargo test` / `npx --yes @tauri-apps/cli@2 build`。

防护语义：

- **漏跑先建直接 cargo 时 fail-closed 且可诊断**：`apps/desktop/src-tauri/build.rs`
  在 `tauri_build::try_build` 之前探测该目录，缺失时 panic，首行即
  `missing sidecar bundle: ...`，并给出修复指引（运行
  `packaging/m2ac5/build_sidecar.ps1`，详见本 README）。替代了此前
  tauri 内部报错 `resource path ... doesn't exist`（不可操作，M2-AC5
  integration i1 EXIT=101 根因）。
- **脚本幂等短路**：产物目录已存在时 `build_sidecar.ps1` 直接输出
  `build_sidecar: target exists, skipping (use -Force to rebuild)` 并
  EXIT=0（且不要求构建 venv 存在），可安全纳入自动化流程；需要强制
  全量重建时加 `-Force`。注意短路只判目录存在，不校验产物完整性；
  产物损坏（缺 exe 等）时全量构建路径的 layout sanity gate 会
  throw——此时手动 `-Force` 重建。

### 2.x 为什么不用 tauri.conf.json 的 `beforeBuildCommand`（方案冻结）

`beforeBuildCommand` 只在 **tauri CLI 流程**（`tauri dev` / `tauri build`）
里生效；开发者与 CI 的主路径是 `cargo check` / `cargo test`（不经 tauri
CLI），它们完全覆盖不到。而 build.rs 在**所有** cargo 驱动的构建路径都会
执行——单一探测点覆盖全部入口，无需为 tauri CLI 再维护第二套钩子，也不
必改动共享的 `tauri.conf.json`。故方案冻结选择 build.rs 前置探测 +
fail-closed 指引，不采用 `beforeBuildCommand`。

### 2.a–2.c 常规构建步骤

```powershell
# 2a. frontend（tauri::generate_context! 要求 dist 存在）
cd apps/desktop/frontend
npm install --no-audit --no-fund
npm run build

# 2b. sidecar onedir（产出 apps/desktop/src-tauri/target/core-sidecar/core-sidecar/）
#     M2-PROD-DETECT-2：PyInstaller 构建后自动把 pinned manga 权重三文件
#     （sha256 逐文件校验，失败即 throw）复制进 <bundle>/models/detector/...；
#     权重快照默认取 G:/CODEX/New Manga.task-envs/M2-DOCTR-QUAL-C4/weights/
#     ogkalu-comic-text-and-bubble-detector/，其他机器用 -WeightsSource 指向
#     本地快照（pin 校验不放宽）；-SkipWeights 跳过复制（debug only：装配期
#     stderr 警告 + detect 期 typed NOT_CONFIGURED，不崩启动）。
powershell -NoProfile -ExecutionPolicy Bypass -File packaging/m2ac5/build_sidecar.ps1

# 2c. NSIS 安装包（把 2b 产物打进安装目录 resources/core-sidecar/）
cd apps/desktop/src-tauri
npx --yes @tauri-apps/cli@2 build
# 产物：target/release/bundle/nsis/m2rc1-desktop_0.1.0_x64-setup.exe
#（体积口径：r0=26.62 MiB；M2-PROD-DETECT-2 起为数百 MiB 级，实测见
#  verification/M2-PROD-DETECT-2/release-notes.md）
```

注意：`tauri build` 每次会重写 `gen/schemas/**` 与
`permissions/autogenerated/**`（仅行尾表示、内容零变化）；按协作惯例交付前
`git checkout --` 还原。

## 3. 五个 frozen 入口

`core_sidecar.spec` 单 onedir 五入口（共享 `_internal` 依赖目录），exe 名即
Rust host packaged 模式解析的稳定标识（`<install>/resources/core-sidecar/`）：

| exe | 对应 dev 形态 | 说明 |
|---|---|---|
| `host_bridge.exe` | `python -m infrastructure.resource_channel.host_bridge` | 资源通道控制面（M2-RC1/RC2） |
| `core_service.exe` | `python -m bootstrap.core_service` | production library sidecar（M2-IPC1） |
| `acceptance_bridge.exe` | `python -m bootstrap.acceptance_bridge` | M2-AC1 验收环（仅 `M2AC1_TEST_MODE=1` 启动配置） |
| `catalog_loader.exe` | `python -m infrastructure.resource_channel.catalog_loader` | launcher 侧 catalog seeding CLI——packaged 环境无系统 python 可跑 dev 的 `python -m` seeding；产品命令面零扩展（F-03 语义不变） |
| `sfx_detect_probe.exe` | `python -m bootstrap.sfx_detect_probe` | 一次性 SFX detect 证据探针（M2-PROD-SFX-PROBE-1）——frozen 进程内跑一次生产 `SfxDetectionProvider.detect` 打印 JSON 后退出；非 IPC 命令、产品命令面零扩展（catalog_loader 先例形；PYZ 含第二份 ML 闭包，DSH r1 P2-1 口径见 spec ENTRIES 注释） |

入口包装脚本（`entries/entry_*.py`）只 `from <module> import main; raise
SystemExit(main())`，与 `-m` 调用语义一致；PyInstaller 无法直接冻结 `-m` 形态，
故用薄包装（`packaging/**` 工具文件，`src/**` 零改动）。

Rust host 侧对接（packaged 判定与 fail-closed 语义见
`apps/desktop/src-tauri/src/main.rs` / `core_bridge.rs`，M2-AC5 实现 commit）：
`M2RC1_PACKAGED=1` 或 `M2RC1_SRC_ROOT` 缺失且
`<exe_dir>/resources/core-sidecar/host_bridge.exe` 存在时进 packaged 分支；
数据根缺省 `%APPDATA%\com.newmanga.m2rc1.desktop\{derived,managed,catalog,data}`
（`packaged_user_root()` 读 `APPDATA` 环境变量——验收 runner 以
`APPDATA=<lab>/roaming` 隔离，见 `run_clean_start_e2e.py`）。
