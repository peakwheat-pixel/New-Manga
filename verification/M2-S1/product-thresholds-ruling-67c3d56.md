## 逐项裁决

### T1 — 必须支持的最大页/tile 字节数

**裁决：单资源（单页或单 tile）必须支持上限 = 256 MiB；超过返回类型化拒绝（建议错误码 `RESOURCE_TOO_LARGE`），不得部分交付。**

- 依据：M2-S1 实测 85,310,202 B（≈81.4 MiB）媒体经路线 A 带外交付且宿主 WS 增量 ≈0（§4.1）；256 MiB 约为该实测最大值的 3 倍，覆盖超高分辨率页与超长 Webtoon tile 的可预期上界。
- 64 MiB 保持为 M2-S1 探针配置，不是产品阈值；产品可配置更高或更低，但"必须支持"承诺线为 256 MiB。
- 联动：S1-B7（真实压缩率字节量）仍需复测；若复测显示典型页分布远离该线，可在 runtime Task 修订配置默认值，但承诺线变更需新裁决。

### T2 — 最大并发资源数与订阅者数

**裁决：同时活跃引用（active references）≥ 32；单资源并发订阅者 ≥ 16。超限返回类型化限流错误，不静默排队无界。**

- 依据：probe E 实测 8 消费者并发读取 81,032,259 B / 11.6 ms 全部 PASS（页缓存热，§4.5）；32/16 为 2–4 倍余量，覆盖书架缩略图网格 + 阅读器当前页/预取的合理并发形态。
- 联动：probe E 的"页缓存热"限制不解除；冷缓存下的并发表现仍按 T3/S1-B6 归口。

### T3 — 首帧延迟预算

**裁决：热缓存（OS 文件缓存命中）典型页（≤ 25 MiB）首帧交付 ≤ 200 ms（P95）；冷缓存（首次触盘）目标 ≤ 1 s（P95）。**

- "首帧"约束通道层字节到达宿主的时刻，不含图像解码与 React 渲染。
- 依据：路线 A 解析实测 0.33–0.47 ms（§4.1）；probe B 吞吐 530.9 MB/s 意味 25 MiB 页传输约 47 ms（§4.2）；二者叠加远低于 200 ms，余量给磁盘抖动与调度。
- **诚实边界**：冷缓存 1 s 为目标值——S1-B6（冷缓存测量）在 M2-S1 为 `NOT_RUN`（页缓存热），在 S1-B6 复测完成前该值**不得表述为"达标"**；热缓存 200 ms 亦属预算承诺，产品实测验收在 runtime Task 执行。
- 联动：S1-B6 的解除条件增加"对照 T3 预算给出 PASS/FAIL"。

### T4 — Core 与宿主的峰值内存预算

**裁决：Core 侧单资源处理峰值额外内存 ≤ 资源字节数 + 64 MiB（流式分块实现下目标常驻缓冲 ≤ 32 MiB）；宿主（Tauri host）经路线 A 带外读取目标增量 ≈ 0，经路线 B 有界缓冲目标 ≤ 32 MiB。禁止为整份资源做 Base64/JSON 物化（Contract §10 已禁止，重申为产品验收线）。**

- 依据：probe D 实测 58 MB 载荷使接收端 WS +212.5 MB、naive 76 MB 路径 +265.6 MB（峰值 386.9 MB），Base64 物化不可接受（§4.4）；probe B 有界内存 60.77 MB 载荷 WS 增量 0.96 MB 证明流式可行（§4.2）。
- 进程级整体内存预算（含模型、SQLite、GUI）不在本裁决范围，归 runtime Task。

### T5 — 宿主资产协议形态与路径暴露（联动 S1-B12）

**裁决：分层信任模型。**

1. React/WebView 前端**不得**接触任何 OS 路径（用户源文件与派生缓存均不得）；字节一律经受限资产 URL 交付（Tauri asset protocol 形态，S1-B1 待验证）。
2. Tauri host 为可信层：允许持有受限引用并解析**派生缓存相对路径**，但不得把绝对路径转发给 WebView。
3. Core 批复不得返回用户源文件绝对路径（研究报告 §6.3 第 2 条升格为产品约束）；`user-source` scope 不得有任何前端可见实现（§6.3 第 7 条维持）。
4. **引用保密性：要求保密**——WebView 可见的引用部分必须为不透明映射 ID（Core 侧随机 ID 查表解析），不得可解码还原路径或资源标识；Core↔host 可信层之间的引用格式不受此限。

- 依据：研究报告 F-01 证明签名引用可无密钥解码出相对路径（§12 R-002）；M2-C1 Contract 的前端边界与 AD-001 分层一致；§6.3 第 4 条已预留映射 ID/加密两个选项，本裁决选择**映射 ID**（实现简单、可增量部署、避免密钥管理面）。
- 联动：S1-B12 解除路径确定为"Core 侧映射 ID"方案，其解除条件中的"由用户决定是否需要保密"已由本裁决回答（需要，仅对 WebView 层）；加密载荷选项关闭，除非映射 ID 方案在验证中被证明不可行（须新裁决）。

### T6 — 引用有效期与撤销语义

**裁决：引用绑定 resource_id + revision 指纹；默认 TTL = 300 s 滑动续期（活跃消费事件自动续期）；revision 切换、删除、pin 释放及管理操作触发立即撤销（下次解析返回类型化 `REF_REVOKED`）；已打开句柄/流的当次消费不强制中断。**

- 依据：与现有 current/pinned Revision 保护语义一致（AGENTS.md 产品边界：实现必须保护用户源文件、人工修改、Lock、current/pinned Revision 和任务可恢复性）；短 TTL 限制悬挂引用窗口，滑动续期避免正常阅读流频繁重取。
- 联动：S1-B5（跨 Core 重启/密钥轮换）与 S1-B10（revision 绑定与撤销）的验证目标按本语义执行；TTL=300 s 为默认配置，产品可配置。

### T7 — 模型权重通道

**裁决：模型权重走独立通道、独立生命周期；不与页/tile 共用引用通道，不适用 T1–T4 资源阈值与 T6 TTL/撤销语义。权重加载为 Core 侧启动/首次用时的受控读取（含 hash 校验），不经前端引用机制。**

- 依据：权重为 GB 级、只读、进程级缓存、无 revision 语义；混用会把短 TTL 撤销强加给长生命周期资产，且 T1 上限对权重无意义。
- 联动：S1-B9 从"由用户决定通道与生命周期"变为"独立通道已决，具体传输机制（直接受控文件读 vs 流式）与打包/沙箱影响（S1-B8）留给 runtime Task 验证"。
