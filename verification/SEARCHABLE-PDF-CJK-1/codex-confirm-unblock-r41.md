## 1. 解阻与 Coordinator 授权

审查采用 OS/2 `fsType` 机器可读值，结果覆盖报告所列 8 个字体，均可嵌入，且均允许子集化。`malgun.ttf` 的 cmap 检查另证明该审查环境的该字体覆盖韩文；因此 r40 指定的“字体嵌入许可审查”解阻条件已满足。

**授权：Coordinator 可执行解除 `SEARCHABLE-PDF-CJK-1` 的 blocked 状态，并按暂停前阶段恢复为 `proposed`，同时把 Plan 中相应节点由 `blocked` 改为待释放的规划节点。** 该授权不等于实现授权，也不授权跳过 §4 的 `ready` 门槛。Task frontmatter 与 Plan 的实际状态尚未由本文件改动；只有 Coordinator 在权威文件中完成更新后，状态才算变更。

当前 Task 的 AC 范围已有 r40 裁定（纯语种、混排缺字 fail-closed、AC3 实测口径），但 frontmatter 的 `allowed_paths: []` 与缺失的 Owner / Reviewer / 基线等信息未达到释放条件。Coordinator 应在恢复 `proposed` 后补齐并冻结这些字段，再决定何时设为 `ready`。字体在运行机器上缺失时仍须保持 fail-closed；审查环境存在字体不是所有目标机器都有该字体的证明。

## 2. AC3 最终措辞

建议将 AC3 定稿为：

> **AC3 字体体积：以实测体积及说明为验收，3 倍不作硬门槛。须在相同源页、导出选项和可比条件下，给出纯图片 PDF 与可搜索 PDF 的实际字节数，并说明是否做了字体子集化。若做了子集化，须给出子集化前后可搜索 PDF（或其字体对象，需明确测量口径）的实际字节数；若未做，须记录未做的具体技术理由及其依据。不得将许可限制作为理由，因为已审查字体允许子集化。**

这比 r40 的简写增加了可核查的分支证据，不恢复 3 倍门槛，也不把“许可允许”误写成“工程上必须实现”。若考虑后决定不实现子集化，技术理由应对应实际代码路径、正确性/兼容性风险或测量结果；“工作量大”可说明成本，但单独不足以解释技术决策。若实现子集化，前后尺寸须使用同一输入和测量口径，避免把图像差异误算成子集化收益。

## 3. 实施顺序

推荐先做韩文候选与纯韩文真实页端到端验证，再处理子集化：前者范围小且直接解除已确认的韩文缺口；后者需要字体表重写与独立正确性验证，风险和工作量明显更高。两者可以分阶段、分提交交付，但保持在已冻结的 Task 范围内；若子集化评估发现需要新增依赖、共享接口或更大范围，应先由 Coordinator 冻结变更，不自行扩范围。

子集化并非解除 blocked 或启动韩文阶段的前置条件。AC3 按第 2 节据实验收；AC4 继续验证跨页字体对象共享/增长特征，不预设必须由子集化实现。当前代码已有“每份 PDF 创建一次字体对象”的 r40 证据，但多页尺寸仍需按 AC4 实测，不能把源码观察当作测试通过。

## 4. 字体清单 JSON 的入库边界

该 JSON 不含字体二进制或用户名，但 `font_dir` 暴露了审查机器的 Windows 系统目录；这是低敏感度的环境元数据，却没有跨机器代表性。更关键的治理风险是读者把“本次机器盘点结果”误当成“项目运行前提”，从而错误假设微软雅黑或 Malgun 一定存在。

因此：

- 不将**当前带绝对路径的原样 JSON**当作稳定项目契约、字体可用性保证或跨机器事实；建议脱敏/改写后再作为审计附件入库，或移出版本化仓库。
- 若保留其余字段，文件及引用处应注明 OS/环境、采集日期、它仅代表该次盘点，并标明字体必须在运行时探测；任何字体缺失都按 Task 契约 fail-closed，不得静默假定字体存在或网络下载替代字体。
- 字体文件名、大小、`fsType` 本身不是字体数据，也没有显示个人身份信息；它们可以支持审计追溯。是否保留这些字段取决于需要的复现性。绝对路径没有必要，可删去或规范化为 `Windows system font directory`。

**本轮只作裁定，没有改写或删除该 JSON。** 依用户限定，Task、Plan、STATUS 与其他既有文件也未修改；实施上述状态或证据整理须由 Coordinator 在各自授权范围内单独操作。
