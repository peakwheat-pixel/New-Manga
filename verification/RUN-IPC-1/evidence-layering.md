**交付**：Tauri host 接线 P13-C1 §5.5 冻结的 Run 命令面（6 条 production-only 命令）。
**被测 commit**：见 `doc/handoffs/RUN-IPC-1-dsh-*.md` 的 `delivery_head`。
**环境**：Windows；Rust（`--locked`）；frozen 2.3 bundle 经 `target/core-sidecar` **junction** 引用主仓 bundle（未删除/未重建）；Python `C:\Python314\python.exe`。

## 层 2：通道覆写与 fail-closed 默认（缺陷会被放大而非隐藏）

| 证据 | 内容 |
|---|---|
| 测试 | `tests::run_channel_defaults_are_fail_closed`：未覆写 Run 六法的实现者一律返回 `CORE_UNAVAILABLE`，**证明漏写覆写会显式失败**，不会静默成功 |
| 实现 | 真实路径由 `StdioLibraryChannel` 覆写（`round_trip("StartRun"|"ControlRun"|"ResumeBlockedRun"|"GetRunSnapshot"|"GetTaskProjection"|"RetryFailedTargets", …)`），并经 `SequencedRerenderLibrary` 与 `Arc<SequencedRerenderLibrary>` 两层转发 —— 两者都必须存在，否则生产落到默认实现 |

## 层 3：frozen 2.3 Core 上的**真实往返**（免夹具但有证明力）

`packaged_sidecar_tests::run_command_wire_reaches_the_frozen_core_run_family`（`M2RC1_PACKAGED=1`，真实 frozen bundle，原始输出见 `rust-packaged-tests.log`）：

| 命令 | Core 返回 | 说明 |
|---|---|---|
| `GetRunSnapshot("no-such-run")` | `TARGET_NOT_FOUND` / `not_found` | 域级拒绝 |
| `GetTaskProjection("no-such-run")` | `TARGET_NOT_FOUND` / `not_found` | 域级拒绝 |
| `ControlRun("no-such-run","pause")` | `TARGET_NOT_FOUND` / `not_found` | 域级拒绝 |
| `ResumeBlockedRun("no-such-run")` | `TARGET_NOT_FOUND` / `not_found` | 域级拒绝 |
| `RetryFailedTargets("no-such-run", key)` | `TARGET_NOT_FOUND` / `not_found` | 域级拒绝 |
| `StartRun("detect", {book_id:"missing-book"})` | `INVALID_REQUEST` / `validation` | scope 不可解析 → 校验层拒绝 |

**这条证据证明了什么**：断言 `code != CORE_UNAVAILABLE`（排除落到 fail-closed 默认）且 `code != PROTOCOL_MALFORMED`（排除 wire 名/形状错误）。若命令名不是冻结的 PascalCase，或 payload 形状与 §5.5 不符，Core 不会走到域级查找。因此**六条命令的 wire 名、payload 形状、通道覆写与端到端可达性均被证明**。

**诚实缺口（不得改写为 PASS）**：本层**没有**构造一次**成功**的 Pipeline Run（需要真实 book/chapter/page 与 Provider 夹具），因此**未**验证"成功 Run 的 `RunAccepted`/`RunSnapshot`/`TaskProjection` 正常结果形状"与 `ControlRun` 的合法状态迁移表。缺失段须在具备真实夹具的 Task（P14 实现时）补齐。
