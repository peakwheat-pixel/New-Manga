# L-F1-3-PERF-1：大文件压测（首次实测）

基线 `344c4e83c`。`L-F1-3` 的裁决是 `KEEP-NOTRUN`，重开条件（`MAINT-1-GATE-CONDITION-1-FINDING-ADJUDICATION` §1 #4）：
**"大文件样本、并发注入、文件占用锁"**。其中**占用文件**子项已由 `W4`（导入页面渲染消歧）覆盖。

**本卡做「大文件」子项。**

## 1. 夹具（与"真实漫画页"同构）

第一版夹具**是错的**：用纯色 `Image.new("RGB", (3000,4500), 纯色)` 生成，结果
**11.3 MB**（30 页）—— 因为**纯色 PNG 几乎被压缩殆尽**。真实漫画页是噪声图像。

**修正后的夹具**（`fixture1g/huge.zip`）：

- 120 页，每页 `1600×2400` RGB；
- 像素用 **`os.urandom` 随机噪声**（不可压缩）；
- PNG 用 `compress_level=0`（不额外压缩）；
- zip 用 `ZIP_STORED`（不再压缩）。

**结果：1319.1 MB（≈1.3 GB），生成耗时 13.0 s。**

## 2. 实测（本机，NVMe）

| 操作 | 耗时 | 吞吐 |
|---|---|---|
| 容器整体 SHA-256（Host 发 grant 前的身份指纹） | **0.85 s** | **1555 MB/s** |
| 枚举 120 条目 + 每页 SHA-256（scan 必做） | **0.89 s** | **1486 MB/s** |
| **合计** | **1.74 s** | — |

**对照**：43.7 MB / 400 页的中型夹具只需 **0.07 s 合计**（1234 / 1339 MB/s）——
**说明吞吐是稳定的，不随体积退化**。

## 3. 结论（大文件子项）

**1.3 GB 容器从"身份指纹"到"逐页摘要"全流程 1.74 s，吞吐 ~1.5 GB/s。**

- **没有发现**超线性退化、内存爆炸或超时；
- 唯一的量级风险是**磁盘带宽**（这是物理下限，不是产品缺陷）；
- 若要支持"数十 GB 单容器"，瓶颈会在磁盘与内存映射策略，而非本仓的摘要/枚举逻辑。

## 4. 未做（诚实）

- **并发注入**子项**未做**。说明：管线并发**已由 `CORE-PIPE-EXCLUSIVE-1` / `PIPE-EXCLUSIVE-TRANSPORT-1`
  覆盖**（`_pipeGate` 串行化 + `ExchangeLease`），但那测的是**正确性**（无错配），不是**吞吐**。
  真正的"并发吞吐压测"**仍未做**。
- **文件占用锁**子项：裁决说已由 `W4` 覆盖，**本卡未复核 W4 的实际覆盖范围**。
- 只在**一台机器**上测，未做跨盘（HDD/网络盘）对照。

## 5. 对 `KEEP-NOTRUN` 的影响

**不能**因此把 `L-F1-3` 判为已关闭：三子项只做了 1 个（大文件），且并发吞吐仍缺。
**建议**：把 `L-F1-3` 从"完全未测"更正为 **"大文件子项已测（1.3 GB / 1.74 s），并发吞吐与占用锁未测"**。
