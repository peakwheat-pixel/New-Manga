# 释放前复核（更正版）：样本**不缺**，缺的是那一张

**产出**: 2026-10-20 · **性质**: 释放前 Gate 核对 + 更正 · **结论**: **`DETECT-TILING-1` 可以释放**

## 一、我上一版写错了

**上一版 `DETECT-TILING-1-preflight-20261020.md` 的结论是**：

> **样本已丢失** → AC4 的前提不成立 → **不能释放 Task**

**这个结论错了一半。**

**错在**：我只查了 `verification/P18/raw/**` 和那一个 content-addressed 路径，
发现都空了，就断定「真实页样本已丢失」。

**而实际上 `G:\CODEX\New Manga.workspace\test-materials\objects\sha256\` 里有 147 个对象，
其中 120 张可解码图像，78 张超过 `MAX_DETECT_PIXELS`。**

## 二、实测数据

```
decodable images: 120
OVER the 11,184,810 limit: 78
  690x131289  = 90,589,410 px    <- 8.1x the limit  (Webtoon 长图，多份)
  690x100674  = 69,465,060 px    <- 6.2x
between 50-100% of limit: 7
  600x18401   = 11,040,600 px    <- 98.7%，接近但未超
```

**对象类型分布**：PNG 86 / JPEG 34 / ZIP 5 / 其它 22。

**所以 `test-materials` 里不仅有超限样本，还有比原目标页极端 7 倍的。**

## 三、丢失的确实只有那一张

- 原目标页 `2946×4167 = 12,275,982 px` 的 content-addressed 路径：**`Test-Path` 返回 False**
- `verification/P18/raw/**` 下：**无任何 PNG/JPEG**

**所以那张页面确实没了。但它的替代品多的是。**

**而且替代品更好**：`690×131289` 是 90.6 M px，比 12.3 M px **更能证明分块的必要性**。

## 四、因此 AC4 不需要改成合成页

**我上一版建议「用合成页替代」，并在三条改法里推荐了它。那个建议的前提已经不存在。**

**AC4 可以直接用现成样本**，而且应当**同时覆盖两个量级**：

| 样本 | 尺寸 | px | 与限制的关系 |
|---|---|---|---|
| 原目标页（已丢失）| `2946×4167` | 12,275,982 | 1.10× |
| **实际可用（近界）** | `600×18401` | 11,040,600 | **0.987×（不超限，对照用）** |
| **实际可用（超限）** | `690×100674` | 69,465,060 | **6.2×** |
| **实际可用（极端）** | `690×131289` | 90,589,410 | **8.1×** |

**`690×131289` 恰好也覆盖 AC6 的 `SEC-FMT-005` 场景**——虽然它未达 `>10000×20000`
的宽高，但**像素量是同一量级**。这一点需要 Codex 裁定：
`SEC-FMT-005` 的 `10000×20000` 是**宽高**要求还是**像素量**要求。

## 五、一个必须记录的副作用：Pillow 自己报了 decompression bomb

本次实测时 Pillow 输出：

```
DecompressionBombWarning: Image size (90589410 pixels) exceeds limit of 89478485 pixels,
could be decompression bomb DOS attack.
```

**`89478485` 是 Pillow 的默认 `MAX_IMAGE_PIXELS`（约 89.5 M px）。**

**这意味着**：

- `690×131289 = 90,589,410 px` **已经超过 Pillow 自己的默认保护线**；
- **在 Pillow 里读它，会先触发 Pillow 的 bomb 警告**，而不只是本项目的
  `MAX_DETECT_PIXELS`；
- **所以 `core.detect` 处理这类输入时，会先遇到 Pillow 的保护，再遇到本项目的保护。**

**这对 `DETECT-TILING-1` 的实现是一个真实约束**：
如果只在 `convert("RGB")` 之后按本项目阈值判断，**Pillow 可能在更早的地方就拒绝或警告**。

**AC1 要求「实测选定解码方式的峰值内存行为」——现在多了一个必须先确认的因素：
Pillow 自己的 `MAX_IMAGE_PIXELS` 在哪个环节生效。**
