# AC5：外部验证器互操作（不是「用户视角」）

**产出**: 2026-10-20 · **对应**: `SEC-FMT-IMPL-1` AC5
**AC5 原文**：
> 至少用**一个**外部阅读器打开导出的 CBZ 与 PDF，记录结果。
> **若本环境无法安装外部阅读器，必须如实登记为 limitation，不得以结构验证充当**（r33 已禁止）。

## 一、本机有什么

| 工具 | 能否验证 PDF | 能否验证 CBZ | 性质 |
|---|---|---|---|
| **`fitz`（PyMuPDF）** | **能** | 否 | **独立 PDF 实现（MuPDF）** |
| **7-Zip** | 否 | **能**（独立解压）| **独立 ZIP 实现** |
| Chrome / Edge | 能（渲染 PDF）| 否 | 浏览器内置 PDF 查看器 |
| 专用漫画阅读器（CDisplayEx / YACReader）| — | 能 | **未安装** |
| Adobe Acrobat / SumatraPDF / Foxit | 能 | 否 | **未安装** |

## 二、一个必须说清楚的区分

**r33 禁止「以结构验证充当外部阅读器验证」。**

**我用 `fitz` 和 7-Zip 做的验证，属于哪种？**

| 方式 | 独立性 | 是否用户视角 |
|---|---|---|
| 用项目自己的 `zipfile` 读回 | **零**（同一实现）| 否 |
| **用 7-Zip 解压** | **高**（完全不同的实现）| **否** |
| **用 `fitz` 解析 PDF** | **高**（MuPDF，独立实现）| **否** |
| 用 Chrome 渲染 PDF | 高 | **接近**（真实渲染器）|
| **用漫画阅读器打开** | 最高 | **是** |

**所以 `fitz` + 7-Zip 是「独立第三方实现验证」，强于自验证，但**不是**「用户视角」。**

**本文件如实写成后者。**

## 三、我做了什么

### 3.1 导出一个真实的 CBZ 与 PDF

**用项目自己的导出服务**（`src/application/export/service.py`），
**生成真实的 CBZ 与 PDF**，不是手工拼的。

### 3.2 用 7-Zip 验证 CBZ

**7-Zip 是独立的 ZIP 实现。若 CBZ 结构有问题，7-Zip 会报错或列出异常条目。**

### 3.3 用 `fitz` 验证 PDF

**PyMuPDF 是独立的 PDF 实现（基于 MuPDF）。若 PDF 结构有问题，`fitz` 打开会抛异常。**

### 3.4 用 Chrome 渲染 PDF（额外）

**Chrome 有真实的 PDF 渲染器。若它报错，说明 PDF 有渲染层问题。**

## 五、必须登记的限制

| # | 限制 |
|---|---|
| **L1** | **未用专用漫画阅读器验证 CBZ**——本机未安装 CDisplayEx / YACReader |
| **L2** | **未用桌面 PDF 阅读器验证**（Acrobat / SumatraPDF / Foxit 均未安装）|
| **L3** | `fitz` 与 7-Zip 是**独立实现**，但不是**用户视角**——它们报错的内容与用户看到的可能不同 |
| **L4** | **未验证「在别的机器上打开」**——只在本机 |

**所以 AC5 记为 `PARTIAL`，不是 `MET`。**

**理由**：AC5 要求「外部**阅读器**」，而本机有独立**解析/解压**器，没有**阅读器**。

**这两者的差别是：解析器告诉你「文件结构合法」，阅读器告诉你「用户能看」。**

## 六、如果将来要补齐

**两条路**：

1. **安装一个漫画阅读器**（例如 YACReader，开源、可静默安装）
2. **请用户在自己的设备上打开导出文件并反馈**

**第 2 条是唯一真正的「用户视角」验证**——而它需要用户参与，不是 Agent 能替代的。

**所以 AC5 的完全满足可能需要用户配合。这应该写进 Task 的 limitation，而不是假装做到了。**
