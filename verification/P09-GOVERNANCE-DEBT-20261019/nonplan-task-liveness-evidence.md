# 非终态 Task 的活性证据（r38 §2.3 要求的审计层）

**产出**: 2026-10-20 · **工具**: `tools/governance/task_liveness.py`
**依据**：r38 裁定「状态字段只记录生命周期历史，不证明 Task 仍有人执行或已僵死」。

**本文件不写「死」或「活」的判定。它只把仓库里**能查到的东西**摆出来。**

## 一、四个证据等级

| 等级 | 判据 | 含义 |
|---|---|---|
| **AC 全勾但状态未更新** | 全部 AC 勾选 | **最可处置**：内容看起来完成了，记录没跟上 |
| **有提交痕迹** | 有 commit 在消息边界处提到该 id | 曾有人动过；不证明现在还在动 |
| **无可见工作** | 未勾 AC 且无提交 | **只证明本仓库没有痕迹** |
| **未定** | 以上都不是 | 状态之外，仓库里没有别的信息 |

## 二、结果：40 个非终态 Task

| 等级 | 数量 |
|---|---:|
| **未定** | **20** |
| **有提交痕迹** | **17** |
| **AC 全勾但状态未更新** | **3** |
| **合计** | **40** |

## 三、这个数字改过一次，必须记录

**第一版工具用 `git log --grep <id>` 计数，得到「有提交痕迹 24 / 未定 13」。**

**那是错的。`--grep` 匹配任意位置的子串**，所以：

- **`P22` 的「20 个提交」里混进了 `docs(P04): release task after P22 convergence` 这类**别的任务**的提交**
- 以及 `P22` 作为**路过提及**出现的文档提交

**修正为「id 必须出现在消息的词边界处」后**：

| | 修正前 | 修正后 |
|---|---:|---:|
| 有提交痕迹 | 24 | **17** |
| 未定 | 13 | **20** |
| **`P22` 的提交数** | **20** | **12** |

**7 个 Task 从「有痕迹」变成了「未定」。**

**我把两个数字都留在工具输出里**（`commits` 与 `commits_loose`），**因为差异本身是信息**。

## 四、最可处置的 3 个

### 4.1 `M2-SFX-ANNOTATE-R2`（`in_review`，AC 6/6）

**最后一次提到它的提交**：

```
a85d88532  2026-10-04  close(M2-SFX-ANNOTATE-R2): done @merge 84f952b3 —
DSH r1 approved_with_conditions 条件全闭…integration_commit 回填 84f952b3；
STATUS/PLAN 收口
```

**已核实**：`84f952b3` **是主线 `antigravity/P09-AC3-DELETE-HARDEN-1` 的祖先**（`git merge-base --is-ancestor` exit=0）。

**所以这个 Task 的交付确实进了主线，提交信息也明确说 done。**

**而 frontmatter 现状是 `status: in_review`。**

**这是本文件能找到的最强的一处「记录与事实不一致」。**

### 4.2 `M2-SFX-SYNTH-BG-AUTO`（`in_review`，AC 6/6）

**有两条明确的收口提交**：

```
da645b4ea  gov(M2-SFX-SYNTH-BG-AUTO): STATUS/PLAN 终态 — done（全 AC 闭合含真实冒烟留证）
```

**但其中一条 AC（AC5）的正文写着「真实冒烟=manual 待人工登录后代跑」**——
**即：AC 被勾选了，但里面写着一个未完成的人工步骤。**

**这是一个「勾选与内容矛盾」的实例，值得单独看。**

### 4.3 `M2-TA2B`（`proposed`，AC 8/8，`owner: null`，`branch: null`）

**没有 owner、没有 branch 的 `proposed` Task，AC 却全勾了。**

**这个组合本身是矛盾的。**

## 六、20 个「未定」的特征

**其中 6 个是 `blocked`，4 个是 `proposed` 的 `TASK-02x`，其余是 `P02PRE-*` / `T3.2.1-REPAIR-1x`。**

**它们在本仓库里既无提交痕迹也无 AC。**

**这个工具能说的只有这一句。它不能说「没人做过」。**

## 七、这个工具**不做**什么

**它不给任何 Task 贴 `abandoned` / `superseded` / `historical`。**

**因为 r38 §2 判定：**

> **「`superseded` 也必须有明确替代 Task 或架构裁决作依据。」**

**而「无提交痕迹」这个证据，与「已废弃」之间有很长的距离**：

- 从未开始
- 在别的 worktree 做过但未合并
- 由别处完成

**本仓库只能回答「本仓库里有什么」。**
