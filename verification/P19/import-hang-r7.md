## 判定依据（为何倾向产品缺陷而非工具限制）

1. UI 进入 **`正在导入中`** 状态 —— 该状态由**前端在选择器返回路径后**设置；若选择器未返回，不应进入此状态。
2. **两种不同的选择器 + 两种不同的驱动方式**得到**完全相同**的卡死结果 → 与"驱动方式"无关。
3. `library_import_file` 在 host（`main.rs:860`）与 Core（`core_service.py:1811 handle_import_pages`）均有实现 → **不是能力缺失**，而是**执行不返回**。
4. 无 stderr 错误输出（`app-err.log` 仅正常 title 日志）→ 疑似**阻塞**而非异常。

## ⚠️ 撤回与更正（同日，用户两次纠正后）

**本文件前述"倾向产品缺陷"的判定已撤回。** 用户指出两个具体事实，均成立：

1. **"文件地址没有正确黏贴到文件浏览器上"** —— `WScript.Shell.SendKeys` 对含反斜杠/引号/中文的路径不可靠，`AppActivate` 成功不等于焦点在目标框。
2. **"黏贴到搜索框了"** —— 第三次实测（`verification/P19/ac2-run3/trace.log`）打印了对话框 73 个 `Edit` 的真实身份：前 72 个是**列表列头**（`System.ItemNameDisplay`/`DateModified`/`ItemTypeText`/`Size`），唯一可写的编辑框是 **`SearchEditBox`（搜索框）**；该对话框的 UIA 子树**未暴露"文件名"编辑框**，所以我的 `ValuePattern` 与 `Ctrl+V` **全部落在搜索框**，对话框从未收到有效路径。

**因此：**
- 导入**未完成的原因是执行者的驱动落在错误控件上**，**不是**产品缺陷；此前"UI 进入导入中状态说明选择器已返回路径"的推断**不成立**（该状态在打开选择器流程时即置位）。
- 本文件标题中的"疑永不返回"**不成立**，应读作：**页面导入的完成动作未被成功驱动**。
- `library_import_file` 是否真会 hang **仍未被任何证据检验**（从未以有效路径调用过）。
