## 1. 目标与长期追踪背景

依据 P08 SCOPE_DRAFT 规范及 `01 功能架构 §1`、`03 数据模型`、`08 验收标准`，系统必须长期且稳定支持 5 大媒体格式。
为了支持下游消费者 **P16（导入与解析管道）** 与 **P17（导出与序列化管道）** 的安全开发与集成验证，本表对各类格式的技术契约、导入解析标准、导出生成规范、安全防御规则和验收追踪进行深度固化。

## 3. 异常与安全专项测试矩阵（Security & Robustness）

为确保 P16/P17 的生产级稳健性，下列安全与鲁棒性用例列入长期验收必跑项：

| 用例 ID | 测试场景与注入条件 | 预期系统防护行为 | 对应格式 |
|---|---|---|---|
| **SEC-FMT-001** | 恶意构造的 Zip Slip 压缩包（包含 `../../Windows/System32` 等相对跨目录文件） | 解压器立即识别非法相对路径，丢弃恶意条目并记录安全警告日志，解压严格限制在托管临时沙箱内 | ZIP / CBZ |
| **SEC-FMT-002** | 包含畸形超深嵌套实体的 XML 描述文件（Billion Laughs / XXE 攻击） | XML 解析器禁用外部实体解析（DTD/Entity Expansion 禁用），安全解析普通节点 | CBZ |
| **SEC-FMT-003** | 伪装成图像的无效二进制文件（如将文本或执行程序重命名为 `.png`） | 图像加载器执行文件头魔数（Magic Number）嗅探校验，识别非合法图片后报错隔离，不引发解码器崩溃 | PNG / JPG / WEBP |
| **SEC-FMT-004** | 文件名包含极端特殊 Unicode 字符、空格或超长路径（> 260 字符） | 路径适配器自动启用 Windows `\\?\` 长路径前缀，正常读取与转存，无路径截断 | 全部格式 |
| **SEC-FMT-005** | 单图尺寸超过 10000x20000 的极端 Webtoon 图像文件 | 内存管理器检查可用物理内存，分块处理或适当限制最大处理尺寸，提供清晰内存警告，防止程序 OOM | WEBP / PNG |

## 4. 下游消费者（P16/P17）前置 Gate 契约

1. **P16 消费前置依赖**：
   - 在实现导入与解析流水线前，必须严格依照本表规范实现 5 种格式的解码器；
   - 必须通过 `SEC-FMT-001` 到 `SEC-FMT-005` 的全部安全测试。
2. **P17 消费前置依赖**：
   - 在实现导出管道前，必须依照本表实现 PNG/JPG/ZIP/CBZ/PDF/JSON 的规范序列化；
   - 导出的 CBZ 与 PDF 必须经过至少一种外部标准阅读器（如 Adobe Acrobat、CDisplayEx 等）的兼容性验证。
