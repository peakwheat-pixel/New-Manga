## ★ 本轮唯一的新发现：条件 5 的端到端缺口是**功能缺口**，不是环境缺口

`MAINT-1-RELEASE-GATE-ASSESSMENT-2026-11-14.md` §6.2 原文：

> `HostCommandRegistry` 的翻译相关命令只有 **`save_manual_translation`**（手动保存），**没有自动翻译命令**。
> UI 侧 `Translate` 仅出现在批处理动作枚举（`StudioBatchActionKind.Translate`）与阶段标签中，没有调用 provider 的接线。
> **结论**：条件 5 的「端到端」**不能靠提供 API key 解决**，需先实现「自动翻译」的 Host 命令与 UI 接线；
> **那是独立功能卡，不是维护事项**。

**审计判断**：

- 这不是"等用户提供什么"，而是**代码里确实没有这条通路**。
- 但评估也明确说这是"**独立功能卡**" ⇒ **它超出 Release Gate 维护范围**（Gate 是验证既有实现，不是新功能开发）。
- **⇒ 不应把"条件 5 未满足"归因为"缺用户输入"**，而应归因为"**产品功能尚未实现端到端翻译**"。
  这两种归因的处置完全不同：前者等用户，后者要开功能卡。

**建议口径**（供裁决）：条件 5 = **部分**，其中
①「模型/API 适配」= 已验证（两条 provider 路径真实调用）；
②「代表性质量基线」= **NOT_RUN**（需人工 GT）；
③「UI 端到端」= **未实现**（需自动翻译功能卡，不在 Gate 范围）。
