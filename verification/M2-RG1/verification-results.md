## 披露事项

1. **M2-AC5 证据"运行→搬运→还原"**：clean-start runner 把证据写死到 worktree 的 `verification/M2-AC5/raw/`（P3-9(b) 已知行为，runner 禁改）。每次运行产出后复制改名 `rg1-m2ac5-*` 入 `verification/M2-RG1/raw/`（初交付与 r1 返修 v2 各一次，v2 覆盖同名文件），随后 `git restore verification/M2-AC5/`——该目录在本 Task 交付中零提交（scope audit 佐证）。
2. **warn 文件布局**：PyInstaller 6.22 对单 spec 多 Analysis 只产出一份合并 `warn-core_sidecar.txt`（覆盖全部 4 入口），非释放侦察时预期的"4 份 warn-*.txt"；审查对象（4 入口全部 missing 模块集合）不变。
3. **acceptance_bridge probe 配置与首跑 FAIL 的处置（r1 P1-1 更正）**：该 bridge 仅在其冻结的显式测试配置（`M2AC1_TEST_MODE=1`）下装配核心，裸 probe 按设计应答 `AC1_BRIDGE_MISCONFIGURED`（probe env 修正后与 M2-AC5 ac1_env 同口径；非放宽断言）。**更正**：初交付文档曾称首跑 FAIL transcript 保留在 `raw/rg1-gate-run.log` 首段——经复核（DSH r1 P1-1 指认，本次 grep 复证 `verification/M2-RG1/**` 内 `MISCONFIGURED` 零命中）**该 transcript 不存在于任何证据文件**：gate 复跑把 stdout 重定向到同名文件将其覆盖，从未入库。现仅以本条文字披露，不作任何伪造补充；三处引用（本文件、raw/README、Handoff）已统一改为本措辞。
4. **零触碰口径（r1 P2-3 改写；r2 P1-1(N) 再更正）**：zero-touch 依赖**双重机制**，非单一 pinning——① runner 侧逐轮 pin `APPDATA` 进 lab；② Rust host 侧由 packaged 逻辑派生并**显式传递** data root（`packaged_user_root()`，`main.rs:315-319,366-367`；下传点 `main.rs:446-452`、`library_bridge.rs:149-151`），而 core_service 在无该变量时的兜底根为 `%LOCALAPPDATA%\New Manga`（`src/bootstrap/core_assembly.py:562-568`）。**r2 P1-1(N) 更正**：app 轮（timed_app_cold_start）**不** pin `NEWMANGA_DATA_ROOT`——其零触碰由上述 APPDATA 逐轮 pin + host 侧派生并显式下传保证；`NEWMANGA_DATA_ROOT` 仅在 core/ac1/seed/DC1b/DC3 探针内显式 pin，app 轮不 pin（r1 版此处误称 app 轮亦逐轮 pin）。宿主真实 `%APPDATA%\com.newmanga.m2rc1.desktop` 全程只读（CS-Z4 files=2 byte-identical）。首次 gate run 曾以缺省 data root 短暂 spawn core_service 计时 probe（默认落在宿主 `%LOCALAPPDATA%\New Manga`）；该目录取证已入库（[raw/rg1-localappdata-newmanga-forensics.log](raw/rg1-localappdata-newmanga-forensics.log)）：**无持久新文件、无内容写入**——library.db（303104 B）与 managed 树 mtime 均停在 2026-09-26 01:22（早于本 Task）；唯一痕迹为目录节点 mtime 2026-09-29 12:50:09 与 run1 时间窗一致（SQLite 打开既有库的瞬态 WAL/shm 创建后删除），无数据变更。
