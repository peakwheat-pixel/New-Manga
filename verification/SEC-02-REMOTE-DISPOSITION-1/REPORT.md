**执行者：** DSH（2026-11-14 用户指令：所有任务交 DSH，自动裁决/规划，全部授权，无需用户介入）
**输入证据：** `verification/SEC-01-REMOTE-VISIBILITY-1/`（远端公开可匿名访问；`cc88d1ee`/`b1c1f5a5` 可见；`.tmp.driveupload` 历史树可枚举）
**本 Task 不执行任何远端写操作。**

## 可选项与评估

| 选项 | 机制 | 影响面 | 可逆性 | 证据保全 | 外部影响 |
|---|---|---|---|---|---|
| A 保持现状 + 监测（推荐） | 不修改远端；持续记录可见性与新增暴露 | 暴露面维持 | 完全可逆（未动作） | 完整保留 | 无 |
| B 删除含素材的历史分支 | 删除 `clean-snapshot-*`、`codex/clean-source-snapshot`、`public-release` 等远端 ref | 可减少分支可见面；**main 历史对象仍在** | 分支可重建，但历史对象仍可访问 | 需先保存 ref 清单 | 依赖这些分支的协作者/fork 受影响 |
| C force-push 改写 main 历史 | 使用 git filter-repo 移除 `.tmp.driveupload` 与素材对象后强推 | 可清除历史对象，但重写全部历史 SHA | **不可逆**、影响所有 clone/fork、PR/issue 关联断裂 | 必须先完整备份；改写后本地历史分叉 | 高：所有协作者需重新 clone；平台缓存可能保留 |
| D 联系 GitHub 支持清理敏感对象/缓存 | 通过平台敏感数据流程请求移除缓存/对象 | 可能清除平台缓存与派生视图 | 平台流程，结果不确定 | 平台处理记录 | 依赖平台响应与政策；可能需要证明材料权利 |
| E 仓库转私有或删除 | 修改仓库可见性或删除 | 彻底改变公开可见性 | 转私有可逆；删除仓库不可逆 | 需备份全部历史 | 高：所有 fork/clone 与外部引用受影响 |

## 风险矩阵要点

- **最高风险动作**：C（force-push）与 E（删除仓库）——不可逆、影响外部协作者与 fork、可能违反“保留证据”要求。
- **中等动作**：B（删除分支）——降低可见面但不移除 main 历史对象；需确认无人依赖这些分支。
- **平台动作**：D——不确定性高，但可作为后续正式请求；执行前需准备素材权利证明与影响说明。
- **零动作**：A——不改变现状，保留完整证据与可追溯性；与 2026-10-24“不传播”裁决及审计证据保全要求最一致。

## 推荐方案

**推荐 A：暂保持现状并继续监测**，理由：
1. 处置动作均不可逆或影响外部协作者；在没有明确 Owner 处置授权与完整影响评估前，保持现状最安全且不破坏取证。
2. 当前 SEC-01 已固定“可见”结论与证据；后续可在任何时点执行处置。
3. 若需降低可见面，可在独立授权 Task 中优先评估 **B + D 组合**（删除非必要历史分支、向平台提交缓存清理请求），**C/E 仅作为最后手段**并要求完整备份、独立 Review 与影响通知。

## 未验证事实（不得推断）

- 第三方 clone/fork 数量、GitHub 平台缓存与对象保留策略、法律/合规义务、素材权利归属的最终判断。
- 处置后平台缓存是否立即失效、其他镜像/派生仓库是否同步清除。

- 后续任何处置动作必须由独立 Task 明确授权范围、备份方案、影响评估与 Review；本评估不是执行授权。
