## FEA-D07-UNBLOCK

**目标**：解除 `G-DELETE-CONTRACT` 的 D07 缺口与 C-09↔Gate 循环。

**背景**：D07 的多项未冻内容全在 C-09 草案里，而 C-09 的条件③要求「两 Gate 关闭」→ 死锁。

**解环方案（用户 2026-11-01 裁决：采用方案①）**

| 方案 | 做法 | 结论 |
|---|---|---|
| **① 修正 C-09 的冻结前置并补齐其 D07 条款**（**已采纳**） | 把 C-09 §4 条件③从「两 Gate 关闭」改为**可核验的上游契约条件**（见下）；由 C-09 自身承载 D07 的备份/迁移/调度/命令面条款；C-09 冻结后 D07 才有承载 → 之后才重新判定 `G-DELETE-CONTRACT` | **采纳** |
| ② 拆独立小契约（原推荐） | 把 `backup/2` / 旧包 adapter / 调度归属 / `catalog` 归属拆成 C-15 先冻 | **不采纳**——用户指出它**拆得不够完整**：三路径统一 `ProtectionPolicy`、完整备份清单、软删/恢复命令面仍需承载，单冻 C-15 不能证明循环已解除，且会与 C-09 重复定义 |
| ③ 重定义 Gate 边界 | 在 Gate 定义中写「D07 备份/迁移面由 C-09 承载，Gate 关闭以 C-09 回归为后置」 | **不采纳**——等于自我放宽 Gate 定义 |

### 方案①的具体改法

**C-09 §4 条件③**：由

> ③ `G-DELETE-CONTRACT` 关闭（删除语义）+ **`G-CONTRACT` 关闭**（AD-003 存储契约）；

改为

> ③ **上游契约已冻结**：C-01b、C-04b、C-06、C-14 均已冻结（本契约显式依赖它们的 source/缓存/删除/授权面）；**`G-CONTRACT` 已关闭（2026-11-01）**。**本契约不再要求 `G-DELETE-CONTRACT` 关闭**——本契约正是 D07 的承载者之一；D07 的完整覆盖由「本契约冻结 + C-04b + C-01b 相关条款」共同满足，届时才重新判定 `G-DELETE-CONTRACT`。

**关键原则（用户明文要求）**：
- **不新增「部分关闭」这类含混的 Gate 状态**；`G-DELETE-CONTRACT` 只有 **OPEN / CLOSED** 两态，最终仍要求 **D04–D07 全部覆盖**。
- C-09 的依赖方向被纠正为「等上游契约」，而不是「等自己参与构成的 Gate」——循环由此消失，且没有放宽任何要求。

### C-09 需补的 D07 条款（范围）

| # | D07 声明范围（FEA-01 `:58`） | C-09 现状 | 需补 |
|---|---|---|---|
| 1 | 软删 / 恢复 / TrashEntry 新命令面 | 有 SC 列表但**命令面未写** | 补命令面（命令名/payload/结果/错误码） |

| 3 | 备份覆盖清单（`settings/*.json`、`catalog.sqlite` 归属） | SC-B01 定义但未冻；方案 `:901` 自写「catalog 归属待 D07 冻结」 | 补**完整清单 + 各项归属** |
| 4 | `backup/2` | **全仓无** | 补格式契约（与 `backup/1` 的关系、版本协商、旧包读取） |

**结论**：C-09 要从「草案」补成「D07 的完整承载者」，补的是第 1/2/3/4/6 五项。
