## 4. 用户确认后的执行序列（DSH）

**阶段 1：并行复核（1 轮）**
1. 派 `c01b-reviewer` 复核 C-02 / C-03 / C-11（可并行，三份独立）；若 findings → 修订 → 窄面复核。
2. 期间不冻结任何契约。

**阶段 2：C-01b 冻结（最先）**
3. **②b 动作**：在 C-01b 冻结记录中注明「SC-30/31/33 依赖 ADJ-001 的 PD 语义，`G-DELETE-CONTRACT: OPEN`；删除线实现仍受该 Gate 阻塞」。
4. 按 FEA-GOV-2 §6「若选 D」：不改 AD-002；在 C-01b 依据链落「用户 D 裁决记录」；把 C-01b §4 冻结条件③ 表述改为「责任表口径（零字节解释方案）与哨兵口径」。
5. `check.ps1` 复跑；C-01b 状态改 `FROZEN`（记录冻结日 / 裁决记录 / 被冻结 hash / ADJ-001 依赖声明）。
6. 关闭 C-01b 的冻结前置③；**Source 线（FEA-09/11/12/13）从 BLOCKED 释放为可释放候选**（仍需 DSH 逐个建 Task；删除语义相关实现仍受 `G-DELETE-CONTRACT` 阻塞）。

**阶段 3：C-02 / C-03 / C-11 冻结**
7. 按复核结论逐份冻结（同阶段 2 的模式：状态改 FROZEN + 记录 hash + `check.ps1`）。
8. **顺序约束**：C-03 必须在 C-02 之后冻结（C-02 §6）；C-11 依赖 C-01b/C-02 至少其一。
9. C-02 冻结后：Fluent 实现线的视觉例外边界确定（FEA-05/06/07 可评估释放）。
10. C-11 冻结后：候选 Task 表可直接用于建卡。

**阶段 4：释放第一个实现 Task**
11. 按依赖序选一个候选（建议 **FEA-01 稳定端口冻结**——它不受 Source/删除 Gate 阻塞；或 **FEA-04b 四页设计**——无生产写域，但需「有关用户取舍」+ 用户确认（方案 `:643`/`:925`）；**不建议** FEA-00a（其门 `G-SAFETY` 仍 `OPEN`，对应 F20 修复的 `NOT_RUN` 见 FEA-00 r7 `:149` / r2 技术复核 `:82`（缺陷成立见 r7 `:210`）；与双 UI 切换门关联，不宜作首个实现 Task）），建 `doc/tasks/<ID>.md`（合并方案 §12.1 + §15.6），STATUS 指向它，派独立 Review。

| 步骤 | 回退 |
|---|---|
