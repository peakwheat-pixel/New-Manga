## 1. 契约边界

本契约覆盖「存储侧」的六项反转：**新导入语义、旧 Managed 双读、备份完整性、迁移方向、资源通道信任根、删除授权**。不覆盖：UI 交互、主题、命令清单（分别见 C-02/C-03/C-07）。

条款状态标记：
- **[现行]**：当前代码已按此工作，契约冻结只做确认（回归保护）；
- **[新增]**：尚未实现，冻结后由实现 Task 落地；
- **[未实现]**：AD-003 §4 明确标注未具备，冻结**不**把它变成已实现。

## 2. 条款

### 2.1 新导入语义（AD-003 §3.2）

| ID | 条款 | 状态 | 实现落点 / 验证 |
|---|---|---|---|
| **SC-01** | 新导入只建立引用、索引与必要元数据，**不创建永久全尺寸输入副本**。 | [新增] | 导入命令；以「导入后 `derived/` 无全尺寸复制」为验收（大小分布 + 引用计数） |
| **SC-02** | `derived/`、缩略图、PDF raster、ZIP 解码页、tile 仅作**有上限的可再生产物**；cache key 至少含 `SourceVersion` / entry / decoder 版本 / 参数。 | [新增] | 资源通道 cache key 构造点；验证：改参数或 decoder 版本必产生新条目 |
| **SC-03** | 处理结果、人工版本与崩溃恢复所需文件**不是**缓存，不得按缓存清理。 | [现行]（需核对清理路径白名单） | Trash/GC 过滤器；验证：受保护 revision 不被 GC 命中 |
| **SC-04** | 源身份包含：内容 digest、授权、来源 lineage、Windows volume serial + file ID（同机身份，非跨机永久 ID）；**不得仅凭路径、mtime 或 size 断言同一文件**。 | [新增] | `SourceAccessRegistry` identity facts；验证：改名/同大小替换必须判为不同源 |
| **SC-05** | 同一物理来源可被多个项目引用；不同项目的阅读进度、处理结果、人工修改独立。 | [新增] | 绑定表 + 进度表的外键设计；验证：两项目引用同一源，进度互不影响 |
| **SC-06** | **未实现新源读取前，不得以「消除双份」为由删除现有 `derived/` 或 managed 文件。** | [现行] | 守卫断言；SAFETY-6 AC2 已给出「现阶段 derived 必需」的证据 |

### 2.2 旧 Managed 双读（AD-003 §3.1）

| ID | 条款 | 状态 | 实现落点 / 验证 |
|---|---|---|---|
| **SC-07** | 旧 Managed Copy 继续按既有读取路径工作（`pages.managed_original_ref` 等），**不自动迁移**、**不自动删除**，不受新导入策略回溯影响。 | [现行] | 读路径回归测试 |
| **SC-08** | 旧 Managed 副本是旧书可恢复的必要输入，备份与容量预览**须单列**，不能随新默认静默漏备。 | [现行]（备份清单需补） | 备份清单 + 容量预览；SAFETY-6 AC2 的 managed==derived 证据 |
| **SC-09** | 释放旧副本空间须**另行盘点**备份/任务/引用并形成可预览的清理任务；**不得**绑定到界面切换或 Schema 升级自动执行。 | [现行] | 清理入口只有显式任务 |

### 2.3 备份（AD-003 §3.3）

| ID | 条款 | 状态 | 实现落点 / 验证 |
|---|---|---|---|
| **SC-10** | 备份**默认不含外部原文件**；应用内数据（人工修改、处理结果、受保护 revision、草稿 journal、问题/阅读数据、Run 快照、源引用与授权元数据、恢复所需索引）**默认包含**。 | [新增]（需扩展备份清单） | `nmbak` 清单；验证：清点清单与默认项一致 |
| **SC-11** | 外部原文件与字体为**独立可选项**，开始前显示预计大小/位置/缺失项；备份期间源变化则该失败或重新确认，**不得**打包混合版本并标 verified。 | [新增] | 备份前预览 + 期间变化检测 |
| **SC-12** | 服务密钥首阶段**默认不备份**；跨机恢复凭据需另定加密/解锁方案。 | [现行]（需确认凭据条目不在清单） | 备份清单核对 |
| **SC-13** | 备份一致性**同时覆盖 DB 与文件集合**（DB 快照 → pin 文件集合 → 复制校验 → 原子发布 → 标 verified → 释放 pin）；`verified` **不得**覆盖未包含的应用内数据类别。 | [新增]（现为备份完整性缺口） | `nmbak` 流程 + verified 语义 |
| **SC-14** | 恢复默认逐项 `Defer` 冲突；选 `UseBackup` 前先把当前人工/结果保存为受保护可恢复版本；**不得整库覆盖**。 | [现行] | 恢复流程回归 |

### 2.5 资源通道信任根（AD-003 §3.5）

| ID | 条款 | 状态 | 实现落点 / 验证 |

| **SC-21** | 引用源读取需要**独立授权面**：Host 私有且持久化的 `SourceAccessRegistry`（locator、授权根边界、identity facts、授权 generation）+ 新 `source-read` grant；旧一次性 `ImportPages` grant（≤300 秒、直属成员、进程内 registry）**不得**当长期授权复用。 | [新增] | C-06 授权面 |

### 2.7 删除授权（AD-003 §3.7 / ADJ-001）

| ID | 条款 | 状态 | 实现落点 / 验证 |
|---|---|---|---|
| **SC-30** | **应用内删除**（软删、自动清理、用户显式彻底删除）**从不触点原文件**。 | [现行] | ADJ-001 PD-01–PD-10；SAFETY-6/7/8 已有并发与预览相关修复 |
| **SC-31** | **原始文件删除是独立流程**：独立选择 → 检查其他 live/trashed 引用与活跃 Run/lease → 明确列出确切文件 → 用户确认 → 经 Host 的 Windows 回收站桥执行 → 逐项验证结果；不可回收/被占用/网络盘/路径被替换时**保留并报告**，不得转为永久删除。 | [新增] | C-09 删除/备份 |
| **SC-32** | 共享源默认保留；「已删项目」不得自动视为不再保护；文件夹只处理实际引用文件与本次变空的子目录，不越过导入根。 | [新增] | C-09 |
| **SC-33** | 应用内删除项目**不因共享源而阻断**：删自有内容行/绑定/清单内自有文件，保留共享原文件与其他项目绑定；「无法安全拆分、关系图/归属不一致、存在未列明目标外引用」时 fail-closed，其余预检失败按现行契约处理。 | [新增] | C-09；与 ADJ-001 PD-08、`M2-C1:752,:764` 一致 |
| **SC-34** | OS 删除与 DB 无分布式事务：以 operation journal + receipt 记录，崩溃恢复先核对 OS 事实再决定是否重发。 | [新增] | C-09 |
