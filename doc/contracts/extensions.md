## 0. 总边界（适用于全部扩展条目）

1. 一级页面固定为书架/工作台/阅读器/设置（D01 §2、D02 §3）；任何扩展入口只能
   落在设置页既有分区、导入窗口（D05 §52）或工作台/书架既有面板内，
   **不得新增一级页面或常驻浮窗**。
2. 所有外部网络访问（插件下载、Sakura 探测、模型下载）统一经过
   Network / Proxy Manager（D02 §6.2），遵循 Provider 级覆盖与连接测试；
   不存在绕过代理策略的直连扩展通道。
3. 任何扩展不得破坏 Domain 不变量、不得绕过 Repository 直接写库、不得写入
   用户源文件（D02 §12、D07 §72；Managed Copy 链路不变）。
4. 可选依赖（D07 §83 口径）：扩展缺失时核心翻译链路必须完整可用；扩展崩溃
   隔离为"当前扩展失败、应用可运行"（D07 §72）。
5. 每条目释放前必须完成：本文件的边界行被用户批准 → 对应实现 Task 的
   `allowed_paths` 由 Codex 按本文件收紧 → AC 从 ACG 草案升级为编号 AC 并回写
   [08_ACCEPTANCE_CRITERIA](../08_ACCEPTANCE_CRITERIA.md)。

### 1.4 AI 生成插件 Agent（ACG-EXT-PLUGIN 的一部分，"如保留"裁决）

D02 §12 原文："Plugin Agent **如保留**，只负责生成/管理插件，不进入漫画翻译主链路。"

**U-4 决定**：Plugin Agent 不纳入首版。待 §1.3 本地插件格式与权限机制实现并验收后，
是否作为第二阶段引入须另行由用户裁决；这不是永久删除决定。

**保留条件（同时满足才保留）**：

1. §1.3 的本地插件格式与权限模型已实现并验收（Agent 生成物必须落在该格式内）；
2. Agent 产物一律**不自动加载**：生成/修改插件后必须经用户在设置页逐个审阅、
   确认权限声明并手动启用（fail-closed，与 D07 §88 远程数据提示同口径）；
3. Agent 的 LLM 调用走既有 Provider/网络代理栈，不新增直连通道，不进入
   Pipeline DAG 的任何 Step（主链路可观测性不被 Agent 污染）；
4. 有独立的启停开关与审计日志（生成 prompt 摘要、产物 diff、启用记录）。

**不保留的判据（任一触发即裁剪）**：上述任一条件无法在实现 Task 内验收；
或生成插件的历史故障率使审阅成本高于手写（实现后按 D07 §72 隔离指标评估）。

| 维度 | 设计内容 |
|---|---|
| 支持矩阵（草案，未纳入首版） | 仅为未来二阶段候选：入口=设置页 Plugin/Hooks 分区内"插件助手"按钮（弹窗，非一级页面）；输入=自然语言描述 + 目标 Hook；输出=manifest+hook 脚本草稿 + 差异说明。是否保留待 U-4 后续裁决 |
| AC 草案 | AC-EXT-AGENT-001（P3）：Agent 生成的插件不经用户确认不会出现在已加载清单；AC-EXT-AGENT-002（P3）：Agent 全部网络调用可在代理日志中审计 |
| 释放条件 | U-4 已决定不纳入首版；待 §1.3 本地插件格式与权限机制实现并验收、§1.4 四项条件可被验证后，须由用户单独批准是否进入第二阶段并将 AC 正式化。首版 TASK-025 不包含 Plugin Agent |
