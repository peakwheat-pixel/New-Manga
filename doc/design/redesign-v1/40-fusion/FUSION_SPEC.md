## 1. 融合原则（不是拼盘）

A 与 C 不是"取一部分功能放一起"，而是按**工作粒度**分层：两者回答的是不同粒度下的同一个问题。

| 粒度 | 用户问题 | 由谁回答 |
|---|---|---|
| 对象级（作品/章节/页） | 我要处理哪一章、有哪几页、导入/删除/阅读 | Library（A 的资料柜） |
| 单页 / 单 Region 级 | 这一页这一格怎么改才对 | Studio · **Page 模式**（A） |
| 批次 / 跨页级 | 240 页里哪里卡住了、一次能把哪些推进 | Studio · **Batch 模式**（C） |
| 系统级 | Provider / 网络 / 模型 / 缓存 / 备份 / 插件 | Console（A 的控制台） |

**三条硬规则**（违反即判实现不合格）：

1. **共享选择模型**：两种模式共用同一个 `selection`（当前作品 / 章节 / 当前页 / 当前 Region / 多选页集合）。在 Batch 模式框选 3 页，切到 Page 模式后作用域仍是这 3 页；反之亦然。任何模式不得私存第二份选择。
2. **下钻与上浮必须双向且保上下文**：
   - Batch 矩阵单元格 `Enter` → 进入 Page 模式并定位到该页该阶段，返回时矩阵滚动位置与筛选不变。
   - Page 模式流水线带点击某步骤 → 回到 Batch 模式并高亮该阶段列，高亮当前页行。
3. **统一状态语言**：全产品只用一套状态编码（色相 + 明度 + **符号**），Batch 矩阵与 Page 检查器/胶片条必须使用同一套符号与色值，不得各自发明。

## 2. 产品结构

### 2.1 空间（一级）

```
Ctrl+1  Library  资料柜   作品 / 章节 / 页 / 导入 / 回收站 / 阅读
Ctrl+2  Studio   工位     双模式：Page（画布中心，默认）｜ Batch（阶段矩阵）
Ctrl+3  Console  控制台   任务队列 / Provider / 网络 / 模型 / 缓存与版本 / 备份 / 插件
```

**为什么不是四页面**：旧版是四个"页面级平级入口"（书架/工作台/阅读器/设置），导航靠侧栏点击，页面之间跳转丢失上下文。本设计是**三个空间 + 一个空间内的两种工作模式**；主导航是键位与命令面板，切换不丢上下文；阅读不设独立页面（在 Library 内以浮层进入）。空间数量少一个，是因为"批次"不再被当成一个页面。

### 2.2 Studio 的双模式

沿用 A 的空间骨架，把 C 的能力作为 Studio 的第二种形态：

| | **Page 模式**（`Ctrl+2` 默认） | **Batch 模式**（`Tab` 切换） |
|---|---|---|
| 主视图 | 画布（页面 / 成品 / 分屏） | 阶段轨道 + Page×Stage 状态矩阵 |
| 主工作对象 | 当前 Region | 页 × 阶段 的状态单元 |
| 主操作 | HUD 环（8 动作位）+ 检查器 | 框选 + 批量动作条 + 阶段门禁 |
| 侧栏 | 胶片条 56/200px | 资源树 200px（作品/章节/批次/队列） |
| 右栏 | 检查器 40/320px | 详情抽屉 360px（下钻单元） |
| 底部 | 流水线带 28/240px（10 步骤点阵） | Run 状态带 24px + 概览计数胶囊 |
| 共存信息 | 顶部：breadcrumb · 作用域选择器 · 命令 · 状态演示 · 主题 | 同左 + 阶段轨道进度与门禁 |

**模式切换规则**：`Tab` 切换；切换时保持 `selection` 与滚动位置；首次进入 Batch 模式时，若已有运行中的 Run，自动聚焦该 Run 的批次行。

### 2.3 广播式信息（两个模式都常驻）

- **作用域选择器**（顶带右中）：本章 / 选中 N 页 / 当前页 / 当前 Region，任何批量动作都带作用域后缀。
- **需要我处理**聚合入口（顶带）：待确认 N / 失败 M / 阻塞 K / 过期 P，点击分别跳到 Batch 模式的对应筛选。
- **Run 状态**：有活动 Run 时，底部始终有一条 24px 状态带（Page 模式为流水线带、Batch 模式为 Run 带），两处渲染同一投影。

## 3. 导航与寻址

| 动作 | 键位 | 说明 |
|---|---|---|
| 空间切换 | `Ctrl+1/2/3` | 保留上下文 |
| 模式切换 | `Tab` | Studio 内 Page ↔ Batch |
| 命令面板 | `Ctrl+K` | 覆盖全部命令，标注「空间 · 模式 · 作用域」 |
| 快速跳转 | `Ctrl+P` | 作品/章节/页/Region 名称跳转 |
| 对象导航 | `J/K`、`[` `]`、`Shift+[` `]` | Region / 页 / 章节 |
| 下一个需要我 | `F5` / `Ctrl+Shift+F` | 待确认 → 失败 → 过期（按优先级） |
| 帮助 | `F1` | 当前上下文键位速查 |

**寻址唯一性**：`(book, chapter, page, region)` 与 `(run, page, stage)` 是两套稳定寻址；任何深链接（如从通知/日志进入）必须落到具体对象，不得只落到空间。

## 5. 视觉母语（融合后的唯一体系）

- **基底**：A 的暗房层级（`#0F1012` 画布 / `#141518` 应用 / `#1A1C1F` 面板 / `#22252A` 浮层），**无阴影**，只用亮度差 + 1px 描边。
- **强调**：A 的琥珀 `#D9A04B`，**只**用于当前焦点、激活态、正在编辑的字段、选中对象描边。
- **状态**：采用 C 的七态完备系统（queued / running / done / failed / blocked / stale / skipped），但按 A 的低饱和色调重新校准；**状态色与强调色严格分离**（状态不参与装饰，强调不表达状态）。
- **字体**：A 的三栈——UI `Segoe UI Variable Text / Microsoft YaHei UI / Noto Sans SC`；数据 `Cascadia Mono` + `tabular-nums`；少量衬线标题 `Georgia / Noto Serif SC`。
- **密度**：两档统一令牌——Page 模式行高 28px，Batch 矩阵行高 22px；字号 6 档（11/12/13/14/18/24）。
- **图标**：1.25px stroke，20×20 网格。
- **动效**：只有状态反馈（90ms），无位移、无循环；`prefers-reduced-motion` 全关。

精确数值见 `tokens.json`（DTCG）与 `DESIGN_SYSTEM.md`。

## 6. 响应式与 DPI

| 窗口宽度 | 行为 |
|---|---|
| ≥1600 | 完整布局（胶片条可展开 200px、检查器 320px、详情抽屉 360px） |
| 1280–1599 | 胶片条固定 56px；检查器默认收起为 40px；Batch 资源树可折叠 |
| <1280 | 胶片条折叠为 40px 缩略条；检查器改为覆盖式抽屉；矩阵横向滚动 |
| DPI 100/150/200% | 1px 线保持物理 1px（用 1px + `transform` 无关方案）；图标按整数倍缩放；文字不裁切 |

## 7. 与旧版及原方向的关系（回应复核意见）

复核提出 A 的视觉轮廓最接近旧 Shell。融合后明确差异：

| 旧版 | 融合版 |
|---|---|
| 四个页面级平级入口，侧栏点击切换 | 三个空间 + 一个空间内双模式，键位/命令面板切换 |
| 页面间跳转丢失上下文 | 上下文（selection/滚动/筛选）跨模式与空间保留 |
| 阅读器是独立页面 | 阅读是 Library 内的浮层 |
| 进度只在工作台底部 | Run 状态在两种模式常驻且同源 |
| Region 检查器展示原始字段 | 检查器按四轨组织（文本/样式/修复/锁定/历史） |
| 无全局批量与异常治理 | Batch 模式 = 矩阵 + 概览胶囊 + 批量动作 + 门禁 |
| 无命令面板 | `Ctrl+K` 覆盖全部命令并标注作用域 |
