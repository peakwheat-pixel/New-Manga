# 交互状态模型（实现级规范）

> 共享下限：任何方向实现这些状态时，必须同时满足「语义正确」与「可判定」。具体视觉形式由方向自定。

---

## 1. 状态基元

每个可异步对象（Page / Region / Run / Export）都由四组状态合成，UI 必须能分别表达：

| 组 | 取值 | 用户要回答的问题 |
|---|---|---|
| **执行态** | `not_started` `pending` `running` `interrupted` `cancelled` | 它跑过吗？在跑吗？ |
| **结果态** | `completed` `failed` `skipped` `stale` | 现在的结果能用吗？ |
| **审阅态** | `unreviewed` `needs_review` `confirmed` | 人看过吗？可信吗？ |
| **保护态** | `page_locked` `region_locked` `translation_locked` `inpaint_locked` | 自动化还能动它吗？ |

**硬要求**：不得把四组合并成单一"状态灯"。允许在列表里显示"主状态"，但必须可下钻看到四组。

---

## 2. 阶段矩阵（Page / Region 通用）

维度：阶段 × 状态。

阶段：`detect ocr color term_extract translate segment mask_refine inpaint render review export`

| 状态 | 视觉要求 | 交互要求 |
|---|---|---|
| `not_started` | 极淡占位（空心） | 可点击触发执行 |
| `pending` | 等待标记 | 显示排队位置或"等待上游"原因 |
| `running` | 进行中标记（唯一允许的循环动效，≤2s 周期，可被 prefers-reduced-motion 关闭） | 可查看当前 Step 与耗时 |
| `completed` | 实心/勾 | 可查看产出 Revision |
| `stale` | **必须有独立形态**（如斜纹/虚线/半透明 + 文字 "stale"） | 必须解释"哪个上游变了" |
| `failed` | 强标记 + 错误码前 8 字符 | 可查看错误详情、重试该阶段 |
| `skipped` | 短横 | 可查看跳过原因（Lock / 策略 / 无目标） |
| `interrupted` | 中断标记 | 可继续 |
| `cancelled` | 取消标记 | 可重新排队 |

**禁止**：`stale` 与 `not_started` 同形；`failed` 只靠颜色；`skipped` 无原因。

## 3. 十二个状态真相的实现要求

| # | 场景 | 必须出现的信息 | 必须可执行的动作 |
|---|---|---|---|
| 1 | 空工作区 | 数据根路径、导入入口、最近作品（若有）、首次使用引导入口 | 导入文件 / 导入文件夹 / 打开设置 |
| 2 | 导入中 | 每个文件的状态、总进度、已成功/失败计数、可取消 | 取消 / 查看失败文件 |
| 3 | 导入部分失败 | 失败文件列表与原因（格式/损坏/重复） | 重试失败项 / 跳过继续 |
| 4 | 章节无页面 | 明确"本章还没有页面" + 上一/下一章 | 导入页面 |
| 5 | 页面无 Region | 明确"未检测到文字区域" | 手动新建 Region / 重检测 |
| 6 | 流水线运行中 | 当前 Run、当前 Step、当前页、总进度、完成/失败/等待计数 | 暂停 / 停止 / 查看失败 |
| 7 | 暂停中 | "当前步骤安全结束后暂停"的状态说明、已完成计数 | 继续 / 停止 |
| 8 | 完成但有失败 | `completed_with_failures` 明确文案、"成果已保留"、失败聚合 | 只重试失败 / 查看报告 |
| 9 | 阻塞 | `blocked` + 阻塞原因（如 Provider 未配置/认证失败）+ 受影响范围 | 跳转修复配置 / 修复后恢复 |
| 10 | 中断恢复 | 上次中断的 Run 与范围、三选一 | 继续 / 重新开始 / 放弃 |
| 11 | 待确认积压 | 待确认条数、按页/按章分布、当前审阅位置 | 逐条确认 / 批量确认（显示影响面） |
| 12 | 危险确认 | 影响对象数量、是否可撤销、不可逆警告 | 确认执行 / 取消（Esc 可退） |

## 4. 状态转换的可见性

以下转换必须在界面上留下**可感知的反馈**（不只是数据变了）：

| 转换 | 反馈要求 |
|---|---|
| 任何动作开始 | 立即出现进行中标记 + 作用域计数；不得"点了没反应" |
| 动作完成 | 受影响单元的状态更新 + 一次性的结果摘要（成功/失败/跳过数量） |
| 上游变更导致下游 `stale` | 就地提示"因 X 变更，N 项已过期"，并提供"重跑过期项" |
| 乐观锁冲突（`INPUT_REVISION_CHANGED`） | 明确"数据已被更新"，提供刷新/覆盖选择，不得静默重试 |
| 暂停生效 | 说明"将在当前步骤结束后暂停"，生效后明确"已暂停" |
| 停止生效 | 说明"已完成成果保留"，并给出剩余未处理计数 |

---

## 5. 加载与占位的统一规则

- **首次加载**：骨架屏（保持最终布局的行高/列宽），不得用居中 spinner 替代整页。
- **增量加载**：保留旧内容 + 局部加载指示，不得整页闪白。
- **长任务**：进度必须有**分母**（"18/23 页"），不得只给百分比。
- **未知时长**：用不确定进度条 + 当前步骤名，不得假装有百分比。
- **空态**：一句话说明 + 一个主操作；不得使用插画占位。

---

## 6. 错误呈现的统一规则

错误分两级：

| 级别 | 呈现 | 内容 |
|---|---|---|
| **就地** | 对象旁的行内标记 | 错误码 + 一句摘要 + "详情"/"重试" |
| **汇总** | 任务态/状态栏的聚合入口 | 按错误码分组计数，可展开到对象 |

**禁止**：只用 Toast 报告可恢复错误；Toast 仅用于"操作已完成"类确认。

错误摘要文案规则：`错误码` + `面向用户的后果` + `建议动作`，例如：
`ProviderRateLimitError · 翻译被限流，2 次重试后停止 · 建议降低并发或更换 Provider`
