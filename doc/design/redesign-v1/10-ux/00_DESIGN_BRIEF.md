## 0. 这份文档解决什么问题

用户裁决：**彻底摒弃当前版本的全部 UI 和 UX，从零重新设计**。现有界面不得作为新设计的布局模板、视觉参考或交互流程依据。

因此本轮设计必须同时满足两个相反方向的压力：

1. **向下**：不能丢掉任何已核实的业务能力、业务规则、用户数据兼容性。
2. **向上**：不能被旧的页面划分、导航体系、组件习惯、样式体系所束缚。

本文件把这两个压力转换成可判定的设计约束，供三套方向共同遵守。

## 2. 必须保留（经过核实的能力，不得因重设计丢失）

分层能力清单的权威版本见 `00-facts/01_CAPABILITY_INVENTORY.md`（由 L1 能力盘点产出）。本文件只冻结**不可协商的保留边界**：

1. **业务实体**：Book / Chapter / Page / Region / RegionRevision / ArtifactRevision / PipelineRun / PipelineTask / StepRun / TranslationConstraint（术语表·不译表）/ TranslationMemory / ProviderProfile / ProviderBinding / NetworkProfile / SettingsOverride / ReadingProgress / Tag / ExportHistory / RecycleBinEntry / BackupRecord。
2. **业务规则**：四级文本（`ocr_text` → `machine_translation` → `edited_translation` → `final_translation`）；四级 Lock（Page > Region > Translation / Inpaint）；人工修改保护（`manual_edited` 自动置 `translation_locked`）；`review_state`（unreviewed / needs_review / confirmed）；SFX 三级继承（作品 → 章节 → Region）；StageState 含 `stale`；Run 状态含 `completed_with_failures` / `blocked` / `interrupted`；停止不回滚成果；暂停只在安全边界生效。
3. **底层能力**：OCR（多 Provider，含韩文专项与 Vision fallback）、翻译（多 Provider + 批量/逐条 + Sakura 本地）、文字检测、Text Segmentation + Mask Refinement + Inpaint Router（多级修复路由）、排版渲染（自动字号 + 溢出策略）、导出（单图 / ZIP / CBZ / PDF / 文本）、备份 `.nmbak`、插件运行时与 Hooks。
4. **用户数据兼容**：旧 SQLite 数据必须能读；Managed Copy 的 source 原图永不修改；current / pinned revision、Lock、阅读进度、人工译文、术语表、备份均不得因 UI 重建而丢失。
5. **稳定后端接口**：Python Core 命令面（约 70+ 个 Tauri 命令 + Core 命令契约）。新 UI 只能使用这些接口；如需新增接口，必须作为独立契约任务释放，不得在设计文档里假定其存在。

## 4. 目标用户与真实使用情境

设计必须服务下列真实情境，而不是"演示数据下的理想状态"。

### 4.1 三类主要使用者

| 角色 | 典型行为 | 设计压力 |
|---|---|---|
| **个人汉化者** | 单章 18–30 页，日漫/RTL，一人完成检测→翻译→修图→排版→校对→导出 | 全流程衔接顺畅、键盘效率、单章快速交付 |
| **流水线作业者** | 一次导入多章、批量跑任务、只处理失败页与异常 | 批量可见性、状态矩阵、失败定位与重试 |
| **校对 / 审稿人** | 只做「原文 vs 译文」核对，逐条确认或改译，需要术语一致性 | 对照阅读效率、行级跳转、确认批量操作、术语提示 |

### 4.2 不可忽略的客观条件

- **单次会话时长 2–8 小时**，界面必须支持长时间注视（对比度、色温、可读性、无眩光）。
- **真实屏幕**：2560×1440 双屏常见；主窗口通常 1600×1000 左右；必须 100%–200% DPI 可用。
- **多语言排版**：日文竖排 / 韩文横排 / 中文横排 / 英文字幕化；同一界面必须容纳 CJK + Latin 混排。
- **半自动现实**：自动流水线永远会失败一部分页面/区域。界面必须把"异常"当作一等公民，而不是异常提示。

### 4.3 一条硬性判断

> 如果一套设计只能在「一切顺利」的情况下好用，它在真实使用中不成立。

## 5. 设计质量门槛（可判定，不靠形容词）

### 5.1 视觉一致性

- 单一令牌源：所有颜色、字号、间距、圆角、阴影、动效时长必须来自该方向的 `tokens.json`；原型内不得出现硬编码色值。
- 字号层级 ≤ 6 档，且相邻档位差 ≥ 1px；字重最多 3 档。
- 语义色只表达状态（成功/警告/危险/信息/中性），不得用于装饰。
- 图标：统一线宽（1.25px 或 1.5px）、统一视觉重量、统一圆角逻辑；不得混用线性与填充风格。

### 5.2 信息密度与空间利用

- 主工作面上，**当前任务的三个关键事实必须同屏可见**：①当前处理对象（页/Region）②该对象的当前状态 ③可执行的下一步动作。
- 列表类视图：在 1600×1000 下，单屏至少可见 24 行数据（行高 ≤ 28px）或 12 条带操作的行。
- 不允许「大片留白 + 少量信息」的营销式布局。

### 5.3 操作效率（桌面专业软件基线）

- 任何业务操作：**键盘可达 ≤ 2 次动作**（快捷键或命令面板）。
- 全局命令面板为必备兜底（范围可达所有命令，带作用域提示）。
- 高频动作必须有单键快捷键：切换对象（上下/前后）、确认、重跑当前、拒绝/跳过。
- 文本编辑必须支持 IME（中日韩输入法）正常输入，不得因快捷键拦截丢字。

### 5.4 状态完整性

每个异步界面必须完整定义并可视化：

```
loading（含骨架/进度）→ ready（含空态）→ error（可定位、可重试）→ partial（部分成功）→ stale（曾成功但已失效）
```

`stale` 是本产品的关键状态（上游变化导致结果过期），任何方向必须显式表达，不得只显示"已完成"。

### 5.5 反馈与可恢复性

- 长任务：可暂停、可停止（不回滚成果）、可继续、可定位失败页、可只重试失败。
- 危险操作（永久删除、覆盖人工译文、清空回收站、恢复备份）：必须显示**影响面**（影响多少页/多少 Region/是否可撤销）与显式确认。
- 错误必须能从「它发生的位置」定位到详情：页 → Region → Step → Provider/Model → ErrorCode → RetryCount。

### 5.6 反 AI 塑料感清单

禁止：大面积渐变背景、玻璃拟态、20px+ 圆角卡片堆叠、彩色阴影、emoji 当图标、随机插画空态、"欢迎使用"营销文案、无意义的微动效、饱和度过高的主色、每块内容都装进卡片。

要求：以**线、密度、留白节奏、字体层级**建立秩序；用真实的数据密度和精确的 1px 分隔建立专业感；允许有隐喻性的细节（如裁切线、密度标尺、打印校色标记）但必须克制且与实际功能相关。

## 6. 评审判据（映射到 L4 十维）

| L4 维度 | 本项目的判据 |
|---|---|
| 1 目标可发现性 | 新手能否在无文档情况下 3 步内找到"导入并开始翻译" |
| 2 任务完整度 | `01_CAPABILITY_INVENTORY.md` 中标记「必须暴露」的能力是否都有可达路径 |
| 3 心智模型 / IA | 作用域 × 动作模型是否被 UI 一致表达；用户是否能预测操作影响范围 |
| 4 异常恢复 | 失败页/失败 Region 是否可从任务态直接定位并只重试该单元 |
| 5 连续性 | 切换对象/页面/视图后，上下文（当前页、当前 Region、当前任务、滚动位置）是否保留 |
| 6 键盘效率 | 关键高频操作是否 ≤2 动作；命令面板是否覆盖全部命令 |
| 7 视觉层级 | 三个关键事实是否同屏、是否有唯一视觉焦点 |
| 8 信息密度 | 单屏信息量下限是否达标；是否存在浪费空间 |
| 9 学习成本 | 首次使用是否有非侵入式引导；高级功能是否可渐进发现 |
| 10 专业场景适配 | 日漫 RTL / Webtoon 长条 / 韩漫彩页 / SFX 是否各有正确表达 |
