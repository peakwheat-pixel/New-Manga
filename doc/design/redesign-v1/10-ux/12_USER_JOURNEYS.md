# 核心用户旅程（以任务为中心，不继承旧流程）

> 本文件从「用户要完成什么」出发重写旅程。每段旅程给出：目标、起点、真实步骤、决策点、失败分支、完成判据、设计支撑点。
> 三套设计方向必须能完整覆盖这些旅程——但**如何组织界面、步骤顺序、视图切换方式由各方向自行设计**。

---

## 旅程总览

| ID | 旅程 | 主角 | 频率 | 对设计的核心压力 |
|---|---|---|---|---|
| J1 | 冷启动到第一页成品 | 新人 / 个人 | 一次性 | 首次使用的可发现性、不打扰的高级功能 |
| J2 | 单章标准作业（日漫 RTL） | 个人 | 每日 | 全流程连续性、键盘效率 |
| J3 | Webtoon 长条章 | 个人 / 团队 | 每周 | 超长内容浏览、切片、纵向滚动 |
| J4 | 批量生产日 | 流水线作业者 | 每周 | 批量可见性、异常聚合与批量重试 |
| J5 | 校对审阅（只核译文） | 校对 | 每日 | 原文/译文对照、逐条确认、术语一致 |
| J6 | 单气泡精修 | 个人 | 高频 | Region 级操作、四轨可见、不误伤邻居 |
| J7 | 中断恢复 | 全体 | 偶发 | 状态诚实、恢复路径明确 |
| J8 | 术语表维护 | 个人 / 团队 | 周期 | 约束的可见效果与回流 |
| J9 | 导出交付 | 全体 | 每章 | 选项明确、可预览、可追溯 |
| J10 | 版本回退 | 全体 | 偶发 | Revision 可读性、回退影响面 |

## J1 冷启动到第一页成品

**目标**：在没有任何既有数据的情况下，完成「导入一个作品 → 看到自动处理开始 → 看到第一页成品」。

**真实步骤**

1. 打开软件 → 看到空状态，但**不是空白页**：显示数据根位置、上次可见的最近作品（若有）、以及一个明确的"导入"入口。
2. 拖入文件夹或选择文件 → 系统识别出章节结构（或询问"作为一章导入"）。
3. 首次需要配置 Provider/模型（若未配置）→ **不可打断导入**，配置作为可并行的侧边任务，并在需要时给出明确阻塞原因（`blocked`）。
4. 导入完成 → 立即显示"这一章有什么"（页数、检测到的 Region、预计处理量），并提供「开始处理」。
5. 处理开始 → 界面进入工作状态：能看到当前页、当前步骤、总体进度，同时**不阻止用户查看已完成的页面**。
6. 第一页完成 → 可立即预览成品（原图/成品切换）。

**决策点**：导入为「新作品」还是「已有作品的章节」；是否立即自动跑全流程。

**失败分支**

- 导入失败（格式不支持 / 文件损坏）：逐文件报告，支持跳过失败文件继续。
- Provider 未配置：界面必须给出「配置 → 测试连接 → 重试」的一条完整路径，而不是一句 error。

**完成判据**：用户在不看文档的情况下，≤5 次交互完成导入并看到成品预览。

**设计支撑点**：空状态设计、可发现的主操作、导入进度的单元级可读、阻塞态的可修复路径。

## J2 单章标准作业（日漫 RTL）

**目标**：把一整章日漫从原图变成可交付成品。

**真实步骤**

1. 选择章节 → 看到**这一章的工作全景**（页网格 + 每页状态 + 任务态）。
2. 启动「全部翻译（跳过已翻译）」→ 批量任务开始。
3. 处理过程中用户可以：
   - 关注任务（进度、当前页、失败页）；
   - 同时打开任意已完成页检查；
   - 处理中途出现的阻塞（Provider 限流 → 换 Provider → 继续）。
4. 批量完成后进入**人工处理阶段**（这是真正耗时的部分）：
   - 逐页过：看原图/成品，找出错误（漏检、错译、排版溢出、修复糊）；
   - 逐 Region 修：改原文、改译文、调字号、换修复、重渲染；
   - 确认：`review_state → confirmed`，内容进入保护。
5. 全部确认 → 导出。

**决策点**：先批处理再人工修（标准），还是逐页处理（小批量）；哪些 Region 需要重新跑全链路。

**失败分支**：某页失败 → 从任务态直接定位到该页 → 只重试失败单元；译文可用但修复失败 → 单独重修复 → 单独重渲染。

**完成判据**：整章所有页 `review_state = confirmed`，无 `failed`、无 `stale`、无未确认；导出成功。

**设计支撑点**：页网格与状态、任务态与工作态的分离与并存、Region 编辑的最小操作成本、"确认"闭环的顺滑度。

## J3 Webtoon 长条章

**目标**：处理一张超长条图（一张图 = 一页）的韩漫章节。

**真实步骤**

1. 识别为 Webtoon（Vertical）→ 导入后页面按纵向连续呈现。
2. 处理：OCR 使用韩文专项模型；长条图需要切片/分区，切片只是缓存，**不是逻辑页**。
3. 校对：在长条上滚动定位 Region，不能因为图很长而失去"当前 Region 在哪"的空间感。
4. 修复：彩色背景、渐变、特效 → 走高质量修复路线，可能比黑白日漫慢，需要单独的可感知进度。
5. 阅读：纵向滚动，按宽度自适应，记住滚动位置。

**关键设计压力**

- 长内容的**空间导航**（缩略图导航条 / 段落标记 / 当前位置指示）。
- 切片与逻辑页的关系必须对用户不可见（不得让用户以为页数变多了）。
- 单页内 Region 数量可能极多，Region 列表必须可筛选/聚合。

**完成判据**：整章通过校对，阅读器恢复滚动位置，导出为常规图片序列。

## J4 批量生产日

**目标**：一次导入 10 章，批量跑，只人工处理异常。

**真实步骤**

1. 批量导入 → 得到 10 章的任务视图（每章页数、处理状态）。
2. 选中全部（或部分）→ 创建批量 Run → 排队执行。
3. 处理中：**按异常聚合查看**（哪些页失败、为什么失败、按错误类型分组）。
4. 批量处置：改了 Provider 配置后，一键重试所有"限流失败"的页。
5. 只对"需要人工判断"的（低置信度、SFX、排版溢出）逐条处理。
6. 批量导出。

**决策点**：并发度取舍（快 vs 稳）；失败是否值得重试（有些错误重试无用）。

**失败分支**：整批阻塞（全部因 Provider 认证失败）→ 界面必须明确"这是配置问题不是数据问题"，并给出统一修复入口。

**完成判据**：所有章节到达可交付状态；异常处置过程有记录可回溯。

**设计支撑点**：队列/批次的组织方式、异常聚合视图、批量重试、配置修复与任务重连。

## J5 校对审阅（只核译文）

**目标**：不做图像操作，只逐条检查译文是否正确、术语是否统一、语气是否符合，然后确认。

**真实步骤**

1. 进入审阅态（或"待确认队列"）→ 系统按顺序给出未确认项（按页/按 Region）。
2. 对照阅读：原文（OCR 结果）+ 机器译文 + （可选）上下文。
3. 判断：
   - 正确 → 确认（单键）→ 自动下一条；
   - 需改 → 就地编辑译文 → 保存即确认 → 下一条；
   - 不确定 → 标记 `needs_review`（留给后续/他人）；
   - 原文就错了 → 需要修 OCR（跳转到该 Region 的文本编辑，可能触发下游 stale）。
4. 批量确认某页/某章剩余项（需确认影响面）。
5. 完成 → 状态归零（无待确认）。

**关键设计压力**

- **连续流的效率**：一次按键从"看完"到"下一条"，不能有鼠标移动。
- **上下文**：单条 Region 的译文脱离上下文容易误判，需要能快速查看该页上下文/相邻 Region。
- **术语一致**：同一术语在不同 Region 的译法不一致时，必须能被提示。
- **原文错误**：校对者经常发现 OCR 错字，需要低成本的"改原文并让下游过期"路径。

**完成判据**：待确认队列清空；术语冲突为 0 或已人工裁决。

## J6 单气泡精修

**目标**：只修一个 Region。

**真实步骤**

1. 定位到 Region（画布点击 / 列表 / 跳转）。
2. 看到该 Region 的四轨状态：原文、译文、修复后底图、成品效果。
3. 修改（任意组合）：改原文 → 重译；改译文 → 重渲染；调整字号/溢出 → 重渲染；修复糊了 → 重修复 → 重渲染。
4. 确认；必要时加锁（不希望后续自动流程覆盖）。
5. 可选：把这条译文写入术语表 / 翻译记忆。

**关键设计压力**

- **影响面必须清楚**：改原文会让下游 `stale`；用户必须知道"改一个字段会导致哪些步骤重跑"。
- **不要误伤邻居**：所有单 Region 操作严格只作用于该 Region。
- **低成本试错**：重渲染要快，且旧版本可回退。

**完成判据**：Region 状态回到 `completed` + `confirmed`，成品页同步更新，其他 Region 未受影响。

## J7 中断恢复

**目标**：软件崩溃/被杀后，正确恢复。

**真实步骤**

1. 重新打开 → 界面必须明确指出"上次有任务被中断"（`interrupted`），列出受影响范围。
2. 三个选择：继续（从断点）/ 重新开始（重跑全部）/ 放弃（标记结束）。
3. 继续后，已完成的步骤与 Revision 必须保留，不重复跑。

**关键压力**：诚实（不能显示已完成）、不丢成果、选择明确。

**完成判据**：Run 状态从 `interrupted` 正确流转，页面状态与实际一致。

## J8 术语表维护

**目标**：维护作品级/章级术语与不译表，并让后续翻译遵守。

**真实步骤**

1. 查看当前约束表（术语 / 不译），来源区分：自动识别 vs 人工。
2. 新增/编辑/删除术语；设置作用域（作品/章）。
3. 看到**影响**：哪些已翻译内容与新术语冲突（需要重译或至少提示）。
4. 触发受影响范围的重译（显式操作，不自动覆盖人工译文）。

**关键压力**：自动识别与人工维护的权威关系必须清楚（人工优先）；约束变更的影响面必须可见。

**完成判据**：约束表更新生效，冲突可查看，重译可控。

---

## J9 导出交付

**目标**：把已完成章节导出为交付格式。

**真实步骤**

1. 选择范围（本章/选中页/整个作品）与格式（单图 / ZIP / CBZ / PDF / 文本）。
2. 看到预检：哪些页未确认、哪些页码缺失、哪些是 `stale`（可导出但会警告）。
3. 选择是否包含原文/译文对照、是否重命名、输出目录。
4. 执行导出 → 进度可见 → 完成可打开目录。
5. 导出历史可查（时间、范围、格式、结果）。

**关键压力**：导出前的**质量预检**（避免导出半成品）、导出过程不阻塞工作、历史可追溯。

**完成判据**：导出成功且产物可验证；未确认页被明确提示。

## J10 版本回退

**目标**：某次自动重跑把好结果覆盖了，需要回退。

**真实步骤**

1. 在 Region 或 Page 上打开版本历史 → 看到按时间的 Revision 列表（来源：机器/人工、步骤、时间、状态）。
2. 预览某个旧版本（尤其是成品图与译文）。
3. 恢复：把该旧 Revision 设为 current；说明对下游的影响（可能再次 `stale`）。
4. 确认恢复。

**关键压力**：版本列表必须可读（谁、何时、哪一步、什么变化），不能只是一串时间戳；恢复必须显示影响面。

**完成判据**：current 指向所选版本，成品页与译文同步，历史完整可再回退。

## 跨旅程的设计要求（汇总）

1. **上下文永不失联**：当前作品/章节/页/Region/Run 在任意视图切换后保持。
2. **任务与工作并存**：长任务运行中，用户可以继续做别的事（查看、编辑已完成内容），不能被任务界面锁死。
3. **异常优先**：任何时候都能一眼看出"哪里需要我"（待确认、失败、阻塞、stale 的聚合计数）。
4. **操作可预测**：任何动作的影响范围在执行前可见、执行后可追溯。
5. **键盘优先**：J2/J5/J6 的高频路径必须无鼠标可完成。
6. **状态诚实**：绝不显示比真实更乐观的状态。
