# New Manga 设计系统 · 六维规范（v2 · 三产品面）

> 状态：`FROZEN v2`（2026-10-25）。取代 `40-fusion` 的三空间结构，保留其令牌管线与组件成果。
> 产品骨架：**书架 · 工作台 · 阅读**（设置是附属抽屉，不是产品面）。
> 主题：**黑夜（默认）/ 白天**，两套完整等价的令牌，不是"适配"。
> 本文件与 `tokens.json` 是唯一权威；任何组件不得出现第三套定义。

---

## 0. 三产品面的职责与共有骨架

| 产品面 | 用户意图 | 主对象 | 默认布局 | 时间占比（典型译者） |
|---|---|---|---|---|
| **书架** Bookshelf | 找到要处理的作品、看进度、开始读或开始做 | 作品 / 章节 | 三栏：作品列 → 章节 → 页网格 | ~10% |
| **工作台** Workbench | 把页面做出来（识别、翻译、修复、排版、确认） | 页 / Region | 画布中心 + 胶片条 + 检查器 + 流水线带 | ~75% |
| **阅读** Reader | 通读成品、检查语感与节奏 | 成品页 | 无边框沉浸 + 极简浮层 | ~15% |

**跨面不变量**（三面都成立，实施时按此验收）：

1. 同一对象在三面中是同一个对象：书架里选中的章节 = 工作台正在编辑的章节 = 阅读正在读的章节。
2. 每面都能回答"我现在在哪、还有什么没做完"：书架给章节完成度，工作台给页与 Region 状态，阅读给本章完成度。
3. 任意一面都能一键到另两面：书架 →「进入工作台」「开始阅读」；工作台 →「阅读此页」；阅读 →「在工作台打开此页」。
4. 三面共用顶带 36px（身份与导航）与状态符号语言。

## 1. 配色：背景 / 文字 / 强调色的分工与占比

### 1.1 三层分工（不可越界）

| 层 | 职责 | 允许的颜色数 |
|---|---|---|
| **背景层** | 承托内容，建立空间深度 | 6 级明度（sunken / canvas / app / panel / raised / overlay），无彩色倾向 |
| **文字层** | 传达信息，建立阅读顺序 | 4 级（primary / secondary / tertiary / disabled） |
| **强调层** | 只标记"当前焦点、激活、选中、正在编辑" | 1 个色相（琥珀），5 个明度变体 |
| **状态层** | 只表达对象状态 | 7 个色相（queued/running/done/failed/blocked/stale/skipped） |

**硬规则**：强调色与状态色互不替代；同一元素上二者不能并用（选中 + 失败 = 强调描边 + 失败角标，是两个通道）。

### 1.2 面积占比（按屏幕像素计，1600×1000 基准）

| 主题 | 背景层 | 文字层 | 强调层 | 状态层 | 图像内容 |
|---|---|---|---|---|---|
| **黑夜** | **78%** | 11% | **≤ 2.5%** | ≤ 3% | 5–8%（画布页面） |
| **白天** | **80%** | 12% | **≤ 2%** | ≤ 2% | 5–8% |

推导依据：专业工具的主体是内容不是装饰。强调色超过 3% 会从"指示"退化为"装饰"，这是廉价感的第一个来源；白天主题因为纸面反光更强，强调色占比必须再降 0.5%。

**背景层的 6 级明度分配（黑夜）**：

```
sunken   #0B0C0E   4%   画布凹槽、代码块、输入框内底
canvas   #0F1012  46%   画布、阅读器背景（最大面积）
app      #141518  16%   应用底
panel    #1A1C1F  10%   顶带、检查器、侧栏
raised   #22252A   1.5% hover 行、按钮底、浮层项
overlay  #2A2E34   0.5% 命令面板、模态、菜单
```

相邻两级明度差 ≥ 4%（Lab 亮度），保证在暗环境低亮度屏幕上仍可分辨层级；这是"不靠阴影也能分层"的前提。

**白天主题的关键差异**：不是把暗色反相，而是重新定调——
- 背景不用纯白（`#FFFFFF` 只用于浮层），避免长时间阅读的刺眼；
- 画布用暖灰 `#F4F3F0`，与"纸"建立联系；
- 强调色加深到 `#B4791F`（暗色下是 `#D9A04B`），因为浅底上原色对比不足；
- 文字不用纯黑，用 `#1C1E21`，减少锐利感。

### 1.3 对比度下限（两主题都必须满足）

| 用途 | 下限 | 备注 |
|---|---|---|
| 正文 primary | 7:1 | 长文阅读 |
| 次要 secondary | 4.5:1 | 标签、说明 |
| 辅助 tertiary | 3:1 | 只用于非关键信息 |
| 状态符号 | 4.5:1 | 且必须配符号，不得单靠颜色 |
| 焦点环 | 3:1 | 相对相邻背景 |

## 2. 布局与留白：区域划分、疏密、对齐、间距

### 2.1 三面的区域划分

**书架（三栏递进）**

```
顶带 36
├ 作品列 240px        （作品条目、封面 2:3 缩略、进度）
├ 章节列 minmax(0,1fr)（章节账本：名称 / 页数 / 完成度 / 状态）
└ 页网格 320px        （当前章节的页缩略 96–120px，2:3）
底部 28：本章统计 + 「进入工作台」「开始阅读」
```

**工作台（画布中心）**

```
顶带 36
├ 胶片条 56 / 200px   （页缩略 + 状态点）
├ 画布 minmax(0,1fr)  （页面居中，四周留白 32–48px）
├ 检查器 40 / 320px   （五页签：文本 / 样式 / 修复 / 锁定 / 历史）
底部 28：流水线带（10 阶段点阵 + 当前页 + 进度 + 控制）
```

**阅读（无 UI 优先）**

```
浮层顶 40（可自动隐藏）：返回 / 章节 / 页码 / 形态 / 内容 / 方向
主体 minmax(0,1fr)：页面居中，左右留白 ≥ 24px，最大宽度按高度约束
浮层底 30（可自动隐藏）：本章完成度 + 键位提示 + 出口
```

### 2.2 间距刻度与用法

刻度：`2 / 4 / 8 / 12 / 16 / 20 / 24 / 32`（2 的幂 + 12/20，覆盖中文行高节奏）。

| 场景 | 值 | 理由 |
|---|---|---|
| 顶带内元素间距 | 12 | 36px 高里最舒适 |
| 面板内边距 | 12 | 与行高 26–28 配合 |
| 表格单元格左右 | 8 | 密集但可读 |
| 卡片内边距 | 12–16 | 书架作品卡 |
| 区块之间 | 16–24 | 建立节奏 |
| 画布外边距 | 32–48 | 内容必须"呼吸"，这是专业的信号 |
| 阅读页左右留白 | ≥ 24 | 阅读舒适 |

**两档密度**（同一套刻度，不同组合，由产品面决定）：

- **工作台 = 密集档**：行 26–28px，字号 12–13px，按钮 24px 高。
- **书架 = 中等档**：卡片 gap 12–16px，标题 14px。
- **阅读 = 稀疏档**：无 UI 占用，只有页面与 24px 留白。

### 2.3 对齐规则

1. **左对齐为默认**（中文与日文都是左起阅读；RTL 仅影响图像页翻页方向，不影响文字排版）。
2. **数字右对齐 + tabular-nums**：页码、百分比、计数、耗时、坐标。
3. **表头与内容同列对齐**，不用居中列（除矩阵单元格）。
4. **三面顶带的 breadcrumb 位置固定**（左起第 2 区），保证视线落点一致。
5. **禁止居中布局**（除空态与模态）：桌面工具居中会破坏扫描效率。

## 3. 字体与层级：区分方式与阅读顺序

### 3.1 字体栈（三条，各有明确用途）

| 用途 | 栈 | 理由 |
|---|---|---|
| UI 与中文正文 | `Segoe UI Variable Text → Microsoft YaHei UI → Noto Sans SC` | Windows 原生优先；雅黑保证中文；Noto 兜底 |
| 数据（页码/坐标/百分比/ID/错误码） | `Cascadia Mono → Consolas → Noto Sans SC` | 等宽 + tabular-nums，数字不跳动 |
| 少量标题（仅书架/空态） | `Georgia → Noto Serif SC` | 提供"出版物"气质，仅用于 24px 一处 |

**禁止**：装饰字体、超过 3 条字体栈、斜体表现强调、字重 700 以上（中文会糊）。

### 3.2 五级层级

| 级 | 字号 | 字重 | 行高 | 颜色 | 出现位置 |
|---|---|---|---|---|---|
| **Display** | 24px | 400（衬线） | 1.25 | primary | 空态标题、书架作品集标题 |
| **Title** | 18px | 600 | 1.3 | primary | 面板标题、抽屉标题、模态标题 |
| **Body** | 13–14px | 400 | 1.45 | primary | 正文、表格内容、译文 |
| **Label** | 12px | 500 | 1.35 | secondary | 字段名、按钮、标签、页签 |
| **Meta** | 11px | 400 | 1.35 | tertiary | 时间、计数、状态文字、提示 |
| **Data** | 11–13px | 400 mono | 1.3 | primary/secondary | 数字与标识符 |

层级差异**同时**靠三件事建立：字号（11/12/13/18/24 五档）、颜色（3 级文字）、空间（上下间距）。不靠下划线、不靠背景色块、不靠字重超过 600。

### 3.3 阅读顺序（每条内容的视觉路径）

桌面工具的标准扫描路径是 **Z 型 + 目标导向**：

1. **顶带**（我在哪、能去哪）—— 一行 36px，视线第一落点
2. **主区左上**（当前对象是什么）—— 面包屑末端、页号
3. **主区中心**（内容本身）—— 画布、表格、阅读页
4. **右栏上**（当前对象的细节）—— 检查器首屏
5. **底部**（全局状态）—— 流水线带、完成度

因此每一面的**首屏必须回答**：这是什么对象、处于什么状态、我下一步能做什么。三者缺一即为不合格。

## 4. 形状与比例：尺寸、圆角、边框

### 4.1 圆角（只有三档）

| 令牌 | 值 | 用在哪 |
|---|---|---|
| `radius.none` | 0 | 画布页面、表格、矩阵、分割线 |
| `radius.sm` | 2px | 按钮、输入、标签、卡片、浮层项（默认） |
| `radius.md` | 3px | 抽屉、模态、命令面板 |

**禁止**：圆角 > 3px、胶囊按钮、圆角卡片堆叠、圆形头像式装饰。桌面专业软件的形状语言是"接近直角"，圆角只用来软化边缘不刺眼。

### 4.2 尺寸体系

| 元素 | 尺寸 | 说明 |
|---|---|---|
| 顶带 | 36px | 全局唯一高度 |
| 工具条 / 子栏 | 32px | |
| 底部状态带 | 28px | |
| 按钮 | 24px 高（sm 20px） | 内边距 8/12，字号 12 |
| 输入框 | 26px 高 | 与行高对齐 |
| 图标 | 20×20 viewBox，1.25px stroke，显示 16px | 密集区 12px |
| 行高（密集/常规/舒适） | 22 / 26 / 28px | 矩阵 22、列表 26、卡片 28 |
| 缩略图 | 2:3 比例 | 与页面一致，最小 40×60 |
| 页面画布 | 2:3，高度优先 | 1200×1800 基准 |
| 检查器 | 40px（收起）/ 320px（展开） | |
| 抽屉 | 360px | |
| 命令行/模态 | 560px 宽 | |

### 4.3 边框

- 全站 **1px** 线宽（高 DPI 下用 1px 逻辑像素，不做 0.5px）。
- 两种用途：**分隔**（`line.subtle` / `line.default`）与**聚焦**（`border.focus = 2px` accent）。
- 表格用水平细线（账本感），不用竖线满格（会变 Excel）。
- 禁止：粗边框、双线边框、彩色边框（除状态与焦点）。

## 5. 材质与光影：表面质感、明暗关系

### 5.1 无阴影体系（核心决定）

**全站不使用 `box-shadow` 表达层级。** 层级完全由「明度差 + 1px 线 + 区域位置」表达：

| 层级手段 | 具体做法 |
|---|---|
| 空间深度 | 从 `sunken` 到 `overlay` 六级明度，越靠前越亮（暗色主题）/ 越白（亮色主题） |
| 边界 | 1px `line.default` 分隔相邻面板；`line.subtle` 分隔同面板内的行 |
| 浮层 | 明度提升 + 1px 强边框（`line.strong`），不加投影 |
| 焦点 | 2px accent outline（`outline-offset: 1px`），不是 glow |

**为什么**：阴影是"卡片式 Web 应用"的语法，在密集工具里会造成脏边、模糊、低 DPI 下发虚；且暗色主题下阴影几乎不可见、只能靠加亮，反而需要明度体系。统一去掉阴影后，两套主题能用同一套几何。

### 5.2 表面质感

- **无纹理、无渐变、无毛玻璃、无噪声**。
- 唯一例外：页面图像本身（漫画分格）是内容，不是 UI 材质。
- 填充色只有两种：纯色（背景层）与半透明（选中/悬停的 accent muted，透明度 ≤ 0.18）。
- 悬停反馈不用阴影，用 `bg.raised` + `line.strong`。

### 5.3 明暗关系（两主题的对应规则）

| 元素 | 黑夜（越前越亮） | 白天（越前越白） |
|---|---|---|
| 画布 | `#0F1012`（最深） | `#F4F3F0`（略灰） |
| 面板 | `#1A1C1F` | `#FFFFFF` |
| 浮层 | `#2A2E34`（最亮） | `#FFFFFF` + 强边框 |
| 文字 | 亮在暗上 | 暗在亮上 |

**注意**：白天主题的"面板比画布更白"是刻意为之——面板是操作区，需要比内容区更清晰；这与"卡片比背景亮"的常规做法方向一致但幅度极小（明度差 4–6%）。

## 6. 动效与反馈：出现、切换、点击；以及"静态时应该是什么样"

### 6.1 原则

**动效只做一件事：确认状态变化。** 不做入场动画、不做位移、不做缩放、不做弹性。专业工具里，任何"表演"都会在每天第 200 次重复时变成干扰。

### 6.2 时长与曲线

| 令牌 | 值 | 用途 |
|---|---|---|
| `motion.instant` | 0ms | 状态符号切换、颜色切换 |
| `motion.fast` | 90ms | hover、focus、选中、按钮按下 |
| `motion.normal` | 140ms | 面板展开/收起、抽屉、命令面板出现 |
| easing | `cubic-bezier(0.2, 0, 0, 1)` | 快出慢收，键盘交互的响应感 |

**只允许过渡的属性**：`opacity`、`background-color`、`border-color`、`color`、`outline-color`、`width/height`（面板尺寸）、`transform: none`。

禁止：`transform` 位移、`scale`、`rotate`、`filter`、`backdrop-filter`、循环动画、骨架屏闪烁。

### 6.3 各类反馈的具体规定

| 场景 | 反馈 | 时长 |
|---|---|---|
| hover 行/按钮 | 背景升一级 + 边框增强 | 90ms |
| 点击按钮 | 背景再升一级（按下态），松开回位 | 90ms |
| 选中对象 | 2px accent 描边 + accent muted 底 | 90ms |
| 焦点（键盘） | 2px accent outline，白/黑底上均可见 | 0ms |
| 面板展开/收起 | 宽度过渡（40→320px），内容不做淡入 | 140ms |
| 抽屉出现 | 从右滑入 **0px**（不做位移动画），直接出现 + 背景变暗（opacity 140ms） | 140ms |
| 命令面板 | 直接出现（无缩放），遮罩 opacity 过渡 | 140ms |
| 状态变化（如 done→stale） | 符号与颜色立即切换（0ms），不闪烁 | 0ms |
| 保存/确认成功 | 行内状态符号变化 + 底部一次性文字提示（2s 后淡出），不用 toast 弹窗 | 2s |
| 长任务进行中 | 进度条宽度变化（真实进度），步骤点阵符号变化；**不旋转、不脉动** | 实时 |

### 6.4 静态化：没有动效时，设计必须已经成立

这是关键要求——**骨架、层级、状态在静态截图中必须完整可读**：

1. **状态必须由符号 + 文字 + 颜色三重编码**。截断动效后，用户仍能分辨"过期"与"失败"（`▨` vs `✗`，且颜色不同）。
2. **层级必须由明度 + 线 + 位置表达**。无阴影、无 hover 时，面板边界依然清晰。
3. **当前焦点必须有持久的视觉标记**（选中描边、光标符 `›`、页签下划线），不能只靠 hover 提示。
4. **进度必须可见且可读**：百分比 + 分母 + 当前步骤名同时存在，不能只靠动画表示"在跑"。
5. **空态、错误态、加载态**都必须有静态可读的版面（文字 + 一个主操作），不能靠 spinner 占位。
6. **可访问性**：`prefers-reduced-motion: reduce` 时全部过渡归零，信息不丢失（因为本来就不靠动效传达信息）。

### 6.5 动效清单（实现范围）

只有 6 处允许动效，其余一律 0ms：

```
1. hover 背景/边框           90ms
2. 选中描边/底色              90ms
3. 按钮按下态                 90ms
4. 面板宽度展开/收起          140ms
5. 遮罩 opacity（模态/抽屉）  140ms
6. 进度条宽度                 实时（≤200ms 线性）
```

## 7. 主题切换规格

| 项 | 规定 |
|---|---|
| 默认 | 黑夜（专业工具在暗环境使用更多） |
| 切换位置 | 顶带右端（太阳/月亮图标），一次点击 |
| 持久化 | `localStorage['nm.theme']`，首帧前应用（`index.html` 内联脚本），**不得闪烁** |
| 过渡 | 切换瞬间不做全局颜色过渡（避免 300ms 的"呼吸"感），直接切换；只有 hover 等局部过渡保留 |
| 等价性 | 两套主题的**信息层级、对比关系、状态可辨性**完全等价；不允许某个功能只在一种主题下好用 |
| 图像 | 不做反色、不做滤镜；漫画页面在两种主题下显示一致 |

## 8. 验收清单（可直接用于 QA）

- [ ] 三面都能回答：当前对象 / 当前状态 / 下一步动作。
- [ ] 强调色面积 ≤ 3%（截图取色统计），且只出现在焦点/激活/选中/编辑。
- [ ] 状态全部为"色 + 符号 + 文字"三重编码。
