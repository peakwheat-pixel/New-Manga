# 方向 A · 暗房（Darkroom）设计档案

> 可交互原型：`index.html`（双击打开，零依赖、离线）
> 视觉令牌：`tokens.json` + `styles.css`
> 截图：`SCREENSHOTS/` 与 `../30-prototype/cmp-A-*.png`

---

## 1. 全局视觉语言

**隐喻**：专业暗房 / 修图台。画布是唯一主角，界面退到边缘。

| 维度 | 定义 |
|---|---|
| 基底 | 近黑炭 `#0F1012`（画布）/ `#141518`（应用）/ `#1A1C1F`（面板）/ `#22252A`（浮层） |
| 文字 | `#E9EAEC` / `#A3A8AF` / `#71767D` 三级 |
| 强调 | 安全灯琥珀 `#D9A04B` —— 只用于当前焦点、激活态、正在编辑、选中 Region 描边 |
| 状态 | 成功 `#6FA97D`、警告 `#D9A441`、危险 `#C9634F`、信息 `#6C93BF`、过期 `#B08A5A` |
| 层级 | **不用阴影**，只靠 `bg → panel → raised → overlay` 四级亮度差 + 1px 描边 |
| 圆角 | 2–3px（近乎方角） |
| 字体 | UI `Segoe UI Variable Text / Microsoft YaHei UI / Noto Sans SC`；数据 `Cascadia Mono`；标题 `Georgia / Noto Serif SC` |
| 字号 | 11 / 12 / 13 / 14 / 18 / 24 六档，行高 1.45 |
| 密度 | 列表行 26–28px，面板内边距 8–12px |
| 图标 | 1.25px stroke，20×20 网格，线性统一，仅当前项可用琥珀 |

**状态编码**：形状 + 颜色双编码（`.mark--ok` 实心、`.mark--err` 叉、`.mark--stale` 斜纹、`.mark--run` 半实心、`.mark--idle` 空框）。

## 2. 导航与工作空间组织

**没有全局侧边栏。** 三个空间以单键瞬切，切换保留全部上下文：

| 空间 | 快捷键 | 职责 |
|---|---|---|
| 资料柜 Library | `Ctrl+1` | 作品 / 章节 / 页 / 导入 / 回收站 / 阅读 |
| 工位 Studio | `Ctrl+2`（默认） | 画布、Region 编辑、校对、任务进度 |
| 控制台 Console | `Ctrl+3` | 任务队列、Provider/凭据、网络、模型、缓存、备份、插件 |

**Studio 布局（1600×1000 基准）**

```
顶带 36px：空间切换 · breadcrumb · 作用域选择器 · 命令面板 · 状态演示 · 主题
├ 胶片条 56px / 200px（页缩略 + 状态点）
├ 画布（剩余全部）：页面 / 成品 / 分屏；选中 Region 出现 HUD 环
├ 检查器 40px / 320px：文本 / 样式 / 修复 / 锁定 / 历史
└ 流水线带 28px / 240px：10 个步骤点阵 + 当前页 + 进度 + 暂停/停止
```

## 3. 核心任务流程

**导入 → 处理 → 精修 → 交付**

1. `Ctrl+1` 资料柜 → 拖入文件夹 → 识别为「第13话」→ 导入（导入进度在底部 dock）
2. 自动进入 Studio，流水线带显示当前步骤与页进度
3. `J/K` 在 Region 间移动，HUD 环随之切换动作位
4. `Enter` 确认 → 琥珀色描边消失、状态点变实心；`Shift+Enter` 重渲染当前 Region
5. `[` `]` 换页，胶片条同步高亮；失败页在胶片条上有 `!` 标记
6. `Ctrl+Shift+F` 跳到下一个失败单元 → 检查器显示错误码与建议动作
7. 完成后 `Ctrl+E` 导出

## 5. 典型交互

- **HUD 环**：选中 Region 后环绕出现 8 个动作位（确认 / 重渲染 / 编辑译文 / 版本 / 锁定 / 重跑全链路 / 编辑原文 / 更多），`Tab` 循环、`Enter` 执行，全程不碰鼠标。
- **作用域始终可见**：顶带显示「作用域 本章 23 页」，任何批量动作都带作用域后缀。
- **检查器四轨**：文本页签展示四级文本（原文 / 机器译文 / 人工译文 / final）+ review_state；样式页签展示字号与溢出策略；修复页签展示 Mask 面积与路线；历史页签是 r1–r5 的可回退列表。
- **状态演示**：顶带眼睛按钮打开 12 状态抽屉，点击即把整个原型切到该状态（运行 / 暂停 / 完成有失败 / 阻塞 / 中断 / partial / stale / 空态…）。

## 6. 优势与潜在缺点

**优势**
- 空间利用率与专注度最高：画布占据绝大部分屏幕，长时间工作不疲劳（暗色 + 低饱和）
- Region 级全键盘操作，图像精修路径最短（选中 → HUD → 执行）
- 四轨信息在同屏内可完整读取（画布 + 检查器 + 流水线带）
- 状态语义表达最细：`stale` 用斜纹而非颜色区分，符合"曾成功但过期"的独立语义

**缺点 / 风险**
- 发现性差：HUD 环、胶片条、快捷键都需要学习，首日上手成本高于 B/C
- 批量能力弱：胶片条适合单章流转，跨章/跨作品批处理不如 C 的矩阵
- 校对链路（逐条读原文/译文）不如 B 顺——文本在检查器里，不在画面主位
- 浅色主题属于"适配"而非"母语"，视觉说服力弱于深色
- 实现风险最高：细节控制稍松（多一个阴影、多一次动画）就会从"专业"滑向"廉价编辑器皮肤"

**最适合**：以图像精修为主要工作、单章作业为主、愿意花半天学习快捷键的个人译者/高端用户。
