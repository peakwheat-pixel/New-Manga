# 三套设计方向规格（冻结版）

> 本文件定义阶段 2 要交付的三套设计方向。三套必须**架构性不同**：主导航范式、主工作对象、信息组织方式三者至少两项不同。
> 判定：任意两套如果把导航骨架与主工作对象互换后仍可互换使用，即判差异不足。

---

## 0. 差异矩阵（先看这个）

| 维度 | **方向 A · 暗房** | **方向 B · 校阅台** | **方向 C · 工坊** |
|---|---|---|---|
| 一句话主张 | 把整个产品变成以画布为中心的专业图像工位 | 把产品做成一本双语工作稿，文本行是主角 | 把产品做成一条可观测的生产线，批次与状态是主角 |
| 主导航范式 | 单空间 + 三视图瞬切（Library / Studio / Console） | 三段式文档框架（工程树 / 工作稿 / 边注） | 阶段轨道 + 资源树（按流水线阶段组织工作面） |
| 主工作对象 | 画布上的 Region | 文本行（Region 条目） | 任务批次 + Page×Stage 状态单元 |
| 主视图 | 全屏画布 + 可收纳浮带 | 表格化对照工作稿 | 状态矩阵 + 阶段工作面 |
| 默认主题 | 深色（暗房） | 浅色（纸稿） | 深色（控制台） |
| 信息密度 | 高 | 中 | 极高 |
| 视觉隐喻 | 暗房安全灯 / 修图台 | 出版校样 / 装订工作稿 | 印刷工坊 / 生产调度台 |
| 批量能力 | 弱–中 | 中 | 强 |
| 校对效率 | 中 | 最强 | 中 |
| 图像精修 | 最强 | 弱–中 | 中 |
| 学习曲线 | 高 | 低 | 中–高 |
| 目标用户 | 个人高端 / 重图像编辑 | 校对为主 / 个人日常 | 工作室 / 批量生产 |

三套共同遵守：`10-ux/00_DESIGN_BRIEF.md`、`10-ux/10_UX_FOUNDATION.md`、`10-ux/12_USER_JOURNEYS.md`。

## 1. 方向 A · 暗房（Darkroom）

### 1.1 设计主张

界面本身几乎不存在。用户看到的是**页面**，其余一切（页列表、检查器、任务、命令）都是环绕画布的**可收纳浮带**。产品不按"页面"组织，按**空间**组织——用户在同一空间里完成绝大部分工作。

### 1.2 信息架构

三个空间，单键瞬切，切换保留全部上下文：

| 空间 | 职责 | 入口 |
|---|---|---|
| **Library 资料柜** | 作品/章节/页的浏览、导入、回收站、阅读 | `Ctrl+1` |
| **Studio 工位** | 画布、Region 编辑、校对、任务进度 —— 核心空间 | `Ctrl+2`（默认） |
| **Console 控制台** | 任务队列、Provider/网络/凭据、模型、备份、插件、缓存与历史清理 | `Ctrl+3` |

- 没有全局侧边导航栏。空间切换在顶带左侧以三个极简图标 + 快捷键提示呈现。
- 设置不是"页面"，是 Console 空间的一种列表形态（同一套左右分栏：左索引 200px / 右表单）。
- 阅读也在 Library 空间内实现（页面图 + 极简浮带），不单独设"阅读器页面"。

### 1.3 主工作空间（Studio）布局

基准 1600×1000，最小 1280×800。

**区域规范**

| 区域 | 尺寸 | 行为 |
|---|---|---|
| 顶带 | 36px | 三空间切换 / breadcrumb（可点击回上层）/ 作用域选择器 / 命令面板 / 设置 |
| 左胶片条 | 56px（收起）/ 200px（展开） | 纵向缩略图流，每项 = 44×56 缩略 + 序号 + 状态点；滚轮滚动；悬停显示页信息；展开时附加状态文字与失败标记 |
| 画布 | 剩余全部 | 支持 页面 / 成品 / 分屏 三种呈现；空格拖拽平移；滚轮缩放；双击 Region = 进入文本编辑 |
| HUD 环 | 围绕选中 Region | 8 个动作位（Tab 循环），显示当前可执行动作；无鼠标参与 |
| 右检查器 | 40px（收起）/ 320px | 收起时为竖排图标条（文本/样式/修复/锁定/历史/导出）；展开显示对应面板 |
| 底部流水线带 | 28px（收起）/ 240px（展开） | 收起=一行状态胶囊；展开=任务面板（页网格 + 失败聚合 + 控制按钮） |

**展开态（画布仍可见，不遮挡）**：胶片条展开时向画布内侧挤出，不用遮罩覆盖。

### 1.4 核心流程

1. `Ctrl+1` Library → 拖入文件夹 → 显示"识别到 N 页，作为第 X 章导入？" → 导入（进度在底带）。
2. 自动进入 Studio → 底带显示流水线运行 → 画布显示当前页。
3. 用户按 `J/K` 在 Region 间移动，HUD 环随之切换；`Enter` 确认；`E` 编辑译文；`Shift+Enter` 重渲染当前 Region。
4. 需要换页：`[` `]` 或胶片条点击/滚轮。需要换章：顶带 breadcrumb。
5. 遇到失败：底带红点数 → `Ctrl+Shift+F` 跳到下一个失败 Region。
6. 完成：底带显示"全部确认" → `Ctrl+E` 导出。

### 1.8 优点 / 缺点

**优点**：空间利用率最高；专业感与专注度最强；暗色适合长时间；图像编辑路径最短；键鼠效率极高。

**缺点**：发现性差（新手不知道 HUD 环和快捷键）；批量管理弱（胶片条不适合跨章作业）；校对流程不如 B 顺；浅色主题是"适配"而非"母语"。

**风险**：容易做成"花哨的编辑器皮肤"；需要极其克制的视觉细节才不显廉价。

## 2. 方向 B · 校阅台（Parlor）

### 2.1 设计主张

产品的核心产出是**译文**，所以界面应该以文本为主体，图像作为佐证。整个产品像一份可以逐行校对的**双语工作稿**：左边是工程，中间是稿面，右边是批注。

### 2.2 信息架构

单一"文档"框架，三栏常驻，不做页面级跳转：

| 区域 | 职责 |
|---|---|
| 左 · 工程树（240px） | 作品 → 章节 → 页；页状态点；底部章节进度摘要 |
| 中 · 工作稿（弹性） | 三种呈现：**对照**（默认）/ **画布** / **成品**；同一章节内的分页 |
| 右 · 边注（260px） | 当前条目的详情、术语冲突、四轨缩略、版本、锁定 |

- 导航不是"去另一个页面"，而是"换一份稿 / 换一种呈现"。
- 任务、导出、设置、Provider 作为**稿件级工具**，从顶部工具区以抽屉（sheet）形式打开，不离开稿面。

### 2.3 主工作空间布局

```
┌──────────────────────────────────────────────────────────────────────────────┐
│ 作品A · 第12章 · 工作稿    │ [ 对照 | 画布 | 成品 ]  │  [导出] [工具▾] [⚙]      │ 44px
│ ── 稿面工具：字体/字号 缩放 ── 筛选: 全部·待确认·失败·已锁定 ── 搜索 Region ── │

```

**区域规范**

| 区域 | 尺寸 | 行为 |
|---|---|---|
| 顶栏 | 44px | 稿件标题 / 呈现切换（分段控件，带快捷键提示）/ 主操作（导出）/ 工具抽屉 / 设置 |
| 稿面工具条 | 32px | 筛选（全部/待确认/失败/已锁定/过期）、Region 搜索、字号缩放、显示选项 |
| 工程树 | 240px | 作品/章节/页三层；页行显示状态符号；键盘可全导航 |
| 工作稿 | 弹性 | 表格行为主；行高 32px；列：序号/类型/原文/译文/状态；支持行内编辑 |
| 边注 | 260px | 当前行详情、术语冲突提示、四轨缩略图、Revision 列表 |
| 底栏 | 30px | 页内统计 + 「下一个待确认」 |

**三种呈现**（同一中栏）：

- **对照**：两列文本 + 状态列（默认，校对主用）。
- **画布**：中栏变为页面图，行与 Region 高亮联动（点击行高亮画布 Region，反之亦然）。
- **成品**：只显示成品页 + 页码，用于快速验收。

### 2.4 核心流程

1. 打开章节 → 直接进入工作稿「对照」呈现 → 光标默认落在第一个待确认行。
2. `J/K` 移动行光标；`Enter` 进入编辑；`Esc` 取消；`Ctrl+Enter` 确认并下一条。
3. 发现原文错：`O` 进入原文编辑 → 保存后该行标记为「上游已改，需重跑」。
4. 怀疑图像问题：`V` 切到画布，确认后 `V` 回来，光标位置不丢。
5. 需要批量：`Shift+J/K` 选行 → 右侧边注出现批量动作（确认/重译/重渲染）。
6. 全章确认完 → 顶栏「导出」→ 抽屉里选格式与范围。

`DocumentHeader` / `ViewSegment`（三呈现切换）/ `FilterBar` / `ProjectTree` / `ProofTable`（行光标 + 内联编辑 + 差异标记）/ `LineStatusMark` / `MarginNotes`（条目详情/术语冲突/版本）/ `CanvasDock`（画布呈现下的中栏）/ `Sheet`（导出/工具抽屉）/ `TermConflictList`

| `Ctrl+E` | 导出抽屉 |

### 2.8 优点 / 缺点

**优点**：校对效率最高；学习成本最低（像熟悉的文本/表格工具）；术语一致性最易管理；浅色纸稿适合长时间阅读；对 CJK 排版友好。

**缺点**：图像几何编辑弱（Region 画框/多边形不在主路径）；批量生产能力中等；画布操作需要切视图；"专业修图感"不足。

**风险**：容易滑向普通表格软件，需要靠排版细节（字体、细线、批注）维持气质；画布视图若设计不佳会破坏整体一致。

## 3. 方向 C · 工坊（Atelier）

### 3.1 设计主张

真正的瓶颈不是单页，而是**一条流水线上哪里卡住了**。所以界面以流水线阶段与批次状态为中心：一眼看到 240 页里哪 12 页失败、失败在哪个阶段，以及一次批量动作能否把它们推进。

### 3.2 信息架构

按**阶段**组织工作面（不是按页面）：

| 阶段（顶栏轨道） | 工作面 | 主操作 |
|---|---|---|
| `DETECT` 检测 | 页 × 检测结果矩阵 | 重检测、修 Region 几何 |
| `OCR` 识别 | 页 × 识别质量矩阵（置信度） | 重 OCR、改原文 |
| `VERIFY` 校对 | 对照复核面（批次内的待确认流） | 确认、改译、加术语 |
| `INPAINT` 修复 | 原图/修复对比面（批量前后对比） | 重修复、换路线 |
| `RENDER` 排版 | 成品预览矩阵 | 重渲染、调样式 |
| `QUEUE` 队列 | Run 列表 + 后台任务 | 暂停/继续/重试/取消 |

- 左侧固定资源树（作品/章节/批次/队列 200px）。
- 顶部阶段轨道同时是**进度条与门禁**：每个阶段有完成度环，未达标阶段有视觉警示。
- 任何下钻详情以右侧抽屉（360px）覆盖，不打断矩阵。

**区域规范**

| 区域 | 尺寸 | 行为 |
|---|---|---|
| 阶段轨道 | 40px（+ 18px 进度条） | 5 阶段 + 队列；点击或数字键切换；每阶段显示完成度与异常计数 |
| 资源树 | 200px | 作品/章节/批次/队列；可折叠；当前批次高亮 |
| 概览条 | 32px | 六个计数胶囊，点击即筛选矩阵 |
| 矩阵 | 弹性 | 行=页，列=阶段；单元格 18×18，四种符号；支持框选、Shift 多选、双击下钻 |
| 动作条 | 40px | 仅在有选中时出现；批量动作 + 作用域计数 |
| 后台带 | 24px | 当前 Run 摘要 + 控制；展开为任务详情抽屉 |
| 详情抽屉 | 360px | 从右侧滑出，覆盖矩阵右缘；不改变矩阵滚动位置 |

**矩阵单元格符号体系**（必须有图例常驻）

| 符号 | 含义 |
|---|---|
| `●` 实心 | completed（有效） |
| `○` 空心 | not_started |
| `◐` 半实心/脉冲 | running |
| `▨` 斜纹 | stale（曾成功已过期） |
| `✗` 叉 | failed |
| `–` 短横 | not_applicable / skipped |
| `·` 点 | pending（等待中） |

### 3.4 核心流程

1. 导入 → 自动创建批次 → 阶段轨道显示批次进入 DETECT。
2. 用户可停留在矩阵观察全批推进；也可切到 `VERIFY` 做校对。
3. 概览条显示「失败 12」→ 点击 → 矩阵筛选只剩失败行 → 框选 → 动作条「重试失败」。
4. 批量阻塞（全批 Provider 认证失败）→ 顶部出现阻塞横幅 → 一键打开 Provider 抽屉修复 → 返回后「恢复队列」。
5. 每阶段有门禁：`RENDER` 阶段提示「12 页未修复，导出将缺失成品」→ 提供「仍然导出」与「先修复」两条路径。
6. 完成后导出（批次级）。

### 3.8 优点 / 缺点

**优点**：批量与异常处置最强；状态最透明（矩阵本身就是状态真相）；阶段门禁避免半成品流出；适合工作室与规模化；可观测性极强。

**缺点**：单条精细校对不如 B；画面感弱，艺术感需要靠细节撑；对个人用户偏"重"；矩阵需要学习（图例承担教学）。

**风险**：容易做成"监控大屏/看板"而失去操作感；必须保证矩阵可直接操作而非只读展示。

## 4. 三套方向必须共同交付的内容

每套方向需包含：

1. `VISUAL_LANGUAGE.md`：视觉语言说明 + 令牌（DTCG 风格 `tokens.json`）+ 字体/间距/圆角/状态色/图标规范。
2. `IA.md`：信息架构、导航范式、空间/页面清单、可达性矩阵（能力 → 入口）。
3. `WORKSPACES.md`：主工作空间与次级空间的布局规范（含尺寸与行为）。
4. `FLOW.md`：核心流程走查（J1/J2/J4/J5/J6/J7 六条旅程如何在该方向中完成）。
5. `STATES.md`：12 个状态真相在该方向中的具体表现。
6. `INPUT.md`：该方向的键鼠映射（含与共享规范的差异说明）。
7. `PROTOTYPE/`：可交互高保真原型（静态 HTML，离线可开，深/浅主题）。
8. `PROS_CONS.md`：优势、缺点、风险、适配用户。
9. `SCREENSHOTS/`：关键界面截图证据。

## 5. 原型技术要求（三套统一）

- 纯静态、零外部依赖、离线可双击打开；单个 HTML 或 `index.html` + 同目录 `*.css` / `*.js`。
- 基准分辨率 1600×1000，同时验证 1280×800 与 2560×1440（用 CSS 弹性布局，不做固定像素画布）。
- 必须实现深/浅主题切换（默认主题按方向定义）。
- 必须可交互：至少覆盖「切换页面/空间」「选中对象」「打开检查器」「任务进度状态切换」「键盘快捷键演示」「命令面板开关」。
- 假数据必须**真实感**：中日韩原文与对应译文、真实页数/章节名、真实错误码（来自 `06` §92）、真实状态枚举。
- 禁止使用任何真实漫画图片或版权素材；页面内容用 CSS/SVG 自绘的抽象页面示意（分格线 + 文字块），保持"专业感"而非"插画感"。
- 必须包含一个 `index.html` 入口，展示该方向的可点击导航（进入各关键界面）。
- 必须内置一个「状态演示面板」（可切换 12 个状态真相），供评审快速比对。

## 6. 判定：差异是否足够

评审时用以下三个问题检验：

1. 把 A 的导航骨架换到 B 上，是否还是"能用的 B"？如果是，说明差异不足。
2. 三套的**默认主视图**是否互不相同（画布 / 表格 / 矩阵）？
3. 三套的**主操作路径**是否互不相同（HUD 环 / 行流 / 批量动作条）？

三项均需回答"否/是/是"才算合格。
