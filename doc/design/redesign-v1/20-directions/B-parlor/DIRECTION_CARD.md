# 方向 B · 校阅台（Parlor）设计档案

> 可交互原型：`index.html`（双击打开，零依赖、离线）
> 视觉令牌：`tokens.json` + `styles.css`
> 截图：`SCREENSHOTS/` 与 `../30-prototype/cmp-B-*.png`

## 1. 全局视觉语言

**隐喻**：出版校样 / 装订工作稿。产品产出的是"译文"，界面就该像一份可逐行校对的稿子。

| 维度 | 定义 |
|---|---|
| 纸面 | 纸白 `#FBFAF7` / 副面 `#F4F2EC` / 边线 `#E6E1D7` / 桌面 `#F1EEE7` |
| 墨色 | 墨黑 `#1D1B18` / 次级 `#57524A` / 弱 `#6E675D` |
| 强调 | 朱红 `#A8402F` —— **只**用于批注、差异、需注意、当前行 |
| 状态 | 确认 `#3F6B4F`、警告 `#8A6A1F`、危险 `#A8402F`、信息 `#3D5A7A`、过期 `#7A6A4F` |
| 字体 | 正文/对照 `Noto Serif SC / Songti SC / Georgia`；UI `Segoe UI Variable Text / Microsoft YaHei UI / Noto Sans SC`；数字 `Cascadia Mono` |
| 字号 | 11 / 12 / 14 / 17 / 22 / 28 六档；正文行高 1.6–1.75 |
| 密度 | 表格行 32px（阅读舒适优先于极限密度） |
| 线 | 账本式 1px 细线（hairline），无阴影、无卡片 |
| 纸感来源 | 留白节奏 + 细线 + 装订线导引（≤4% 不透明度），**不用纹理图和阴影** |

**状态符号**：`✓` 已确认、`●` 待确认、`⊘` 跳过、`!` 失败、`◌` 过期；行内还提供「术语」冲突标记与差异下划线。

## 2. 导航与工作空间组织

**单一文档框架，三栏常驻，不做页面级跳转。** 导航不是"去另一个页面"，而是"换一份稿 / 换一种呈现"。

```
顶栏 44px：稿件标题 · 三呈现分段（对照1/画布2/成品3）· 导出 · 工具抽屉 · 状态 · 主题 · 命令
工具条 32px：筛选（全部/待确认/失败/已锁定/过期）· Region 搜索 · 字号 · 差异/术语开关 · 结果计数
├ 工程树 240px：作品 → 章节 → 页（页行带状态方块）+ 底部本章统计
├ 工作稿（弹性）：对照表 / 画布 / 成品 三种呈现，同一中栏切换
├ 边注 260px：当前条目详情 · 术语冲突 · 版本历史 · 四轨状态
└ 底栏 30px：本章统计 + 光标位置 + 「下一个待确认 →」
```

**三种呈现**（同一中栏，`V` 键轮换）：对照（账本表格，校对主用）/ 画布（页面图 + Region 框联动）/ 成品（成品页 + 页码）。

## 3. 核心任务流程

**打开即校对，逐条确认**

1. 打开章节 → 直接落在对照表，光标在第一条
2. `J/K` 移动行光标；行内三列并列：原文（OCR）/ 译文 / 状态
3. `Enter` 进入编辑；`Ctrl+Enter` 确认并自动跳到下一条待确认
4. 发现原文错 → `O` 编辑 OCR → 保存后标记"下游将过期"
5. 怀疑图像问题 → `V` 切画布核对 Region 框 → `V` 切回，光标位置不丢
6. 术语冲突在右侧边注直接给出建议（車掌→列车长）并可一键「应用术语并重渲染」
7. 全章确认完 → `Ctrl+E` 导出，抽屉内先给出预检（未确认 3 / 过期 1 / 失败 2）

## 5. 典型交互

- **行光标流**：`J/K` 上下移动，当前行整行浅朱红底色 + 左侧 `›` 光标符，右侧边注同步更新（条目 / 版本 / 四轨）。
- **差异与术语双标**：机器译文与人工译文不同时显示差异下划线；命中术语冲突时右侧出现朱红「术语」标记，边注给出替代表述与一键应用。
- **预览抽屉不打断稿面**：导出、工具（任务/术语/设置）、键位速查都以抽屉覆盖，关闭后光标与原位保持。
- **命令面板**：`Ctrl+K`，命令带作用域标注（当前条目 / 第007页 6 条 / 本章 23 页 / 全局）。

## 6. 优势与潜在缺点

**优势**
- 校对效率最高：一条 Region 一个按键推进，无需鼠标、无需切视图
- 学习成本最低：表格 / 行光标 / Enter 确认，与用户熟悉的文本与表格软件同构
- 术语一致性与差异最易发现：四轨与冲突信息在边注常驻
- CJK 排版最友好（衬线正文 + 舒适行高），长时间阅读不累
- 落地风险最低：三套中最容易在现有 IPC 能力上实现，可渐进增强

**缺点 / 风险**
- 图像几何编辑弱：画框 / 多边形不在主路径，精细修图必须切画布
- 批量生产能力中等：没有 C 那样的跨页/跨章状态矩阵
- 视觉冲击弱：在"演示感"上不如 A 和 C 有辨识度
- 容易滑向"普通表格软件"，气质完全依赖排版细节（字体、细线、留白、批注红）
- 画布视图若做不好会破坏整体纸稿一致感

**最适合**：以译文校对与改稿为主、每天长时间坐在同一章里逐条推进的个人译者；也适合作为团队中新人的默认界面。
