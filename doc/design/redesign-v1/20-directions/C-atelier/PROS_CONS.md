# 方向 C · 工坊 Atelier —— 优势 / 缺点 / 风险

## 1. 优势（可被截图直接验证）

1. **批量与异常处置最强**：概览条一点即筛、矩阵框选、批量条一键重试/推进。12 页失败可以在一个屏内定位到"哪一页哪一阶段"，这是本方向的结构性优势。
2. **状态最透明**：矩阵本身就是状态真相，7 种符号三重编码；行级"主状态"可下钻到四轨。不存在"某个数字看不见"的情况。
3. **可观测性极强**：阶段门禁条把"完成度 / 异常数 / 是否可导出"压缩在 18px 高度内，RENDER 未通过时导出会被拦且有两条路径。
4. **适合工作室与规模化**：批次/章节/队列三层资源树 + 常驻 Run 带，多任务并行时不会丢失当前上下文。
5. **键鼠效率高**：`1`–`5`/`Q` 直达阶段、方向键二维导航、`Ctrl+K` 全动作可达；熟练用户几乎不碰鼠标。
6. **视觉纪律强**：无阴影/无渐变/无卡片，状态色是唯一彩色。截图放大后依然"像专业工具"而不是仪表盘皮肤。

## 2. 缺点（如实承认）

1. **单条精细校对不如方向 B**：VERIFY 只有 6 Region 的对照表，没有行级光标流、没有差异高亮、没有术语侧栏常驻。批量场景之外的逐字打磨会显得笨重。
2. **画面感弱**：主视图是数据矩阵，艺术感只能靠排版细节（等宽数字、1px 线、状态符号）撑；对"想要好看"的个人用户吸引力弱。
3. **对个人用户偏"重"**：资源树 + 矩阵 + 工作面 + 批量条 + Run 带的信息密度高，第一次打开会有认知负荷。
4. **矩阵需要学习**：11 列 × 7 符号必须靠常驻图例教学；不看图例的新手会把 ▨ 误认成灰块。
5. **图像精修不是主路径**：INPAINT 只做双栏对比与换路线，Region 多边形、画笔、局部重绘都不在主线。
6. **窄屏吃亏**：1280 下必须牺牲事件列与人工译文列；1152 以下基本不可用（`min-width:1280`）。

## 3. 风险（给 Lead / 评审）

1. **最容易滑成"监控大屏"**：矩阵天然像看板。红线是**可操作性**——点击/框选/下钻/批量必须全部可用，任何只读化的改动都会让这个方向失去存在理由。本次实现已把这条当作验收项（见 `SCREENSHOTS/matrix-selection.png`）。
2. **信息密度与可读性的平衡很脆**：11 阶段列在 496px 内每列只有 18px，列头只能放 3–4 字缩写（DET/OCR/CLR/…）。若后续要加阶段（如 `refine`、`proof`），矩阵必须先解决列宽策略，否则会挤到不可读。
3. **状态色一旦被滥用就崩**：本方向所有彩色都是状态色。任何人为了"好看"给按钮加个蓝色、给图标上彩色，整体气质立刻变成廉价看板。建议把 `PROS_CONS §4` 的反模式清单直接写进后续实现的 Review checklist。

## 4. 反模式清单（评审红线，复用 `spec.html §08`）

渐变 / 玻璃拟态 / 圆角 >2px / 装饰性阴影 / emoji / 彩色图标（除状态色）/ 卡片堆叠 / 纯展示大屏。

## 5. 适配用户

| 用户 | 适配度 | 理由 |
|---|---|---|
| 工作室 / 多语种批量生产 | ★★★★★ | 批次级观测 + 门禁 + 失败聚合 |
| 个人高频批量（一次一章） | ★★★★ | Run 带 + 批量动作足够；但校对环节会想去用 B |
| 个人精细校对为主 | ★★ | 对照表可用，但没有行流与差异标记 |
| 重图像编辑 / 单页精修 | ★★ | 画布与 Region 几何不在主线 |
| 完全新手 | ★★☆ | 图例与命令面板承担教学，但首屏认知负荷高 |

## 6. 与 A / B 的差异自证（回答 `00_DIRECTION_SPEC §6` 三问）

1. 把 A 的"单空间 + 三视图瞬切"骨架换到 C 上 → **不能**直接用：C 的面工作对象是批次与矩阵单元，A 的胶片条 + HUD 环无法表达"页 × 阶段"二维状态。
2. 默认主视图是否互不相同：A 画布 / B 表格 / C 矩阵 —— **是**。
3. 主操作路径是否互不相同：A HUD 环 / B 行流 / C 批量动作条 —— **是**。

## 7. 若只允许改三件事（后续迭代建议）

1. 矩阵列宽策略：允许 11 列在 496px 内自适应（当前靠缩写），或提供"列组折叠"（把 color/term/segment/mask 收成一组）。
2. VERIFY 工作面补一条"行光标 + 差异高亮"，把 B 的校对效率借过来，而不改 C 的骨架。
3. 命令面板补"最近动作"与"当前选中作用域"两个分组，让高频批量动作零学习成本。
