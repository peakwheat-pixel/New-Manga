## 1. 全局视觉语言

**隐喻**：印刷工坊 / 生产调度台。以流水线阶段与批次状态为中心，画布是下钻的详情。

| 维度 | 定义 |
|---|---|
| 基底 | 深色 `#15181A`（外壳）/ `#101314`（下沉区）/ `#1B1F21`（面板）/ `#232829`（浮层） |
| 文字 | `#E6E9E8` / `#9BA3A1` / `#6B7371` |
| 强调 | 青绿 `#3E9E8F` —— 只用于当前阶段、当前批次、可执行动作 |
| 状态系统 | 排队 `#6B7377`、运行 `#2F9EA8`、完成 `#4C9A6A`、失败 `#C0503F`、阻塞 `#C08A2E`、过期 `#8A7BA8`、跳过 `#555C5E` |
| 字体 | UI `Segoe UI Variable Text / Microsoft YaHei UI / Noto Sans SC`；数据 `Cascadia Mono` + `tabular-nums` |
| 字号 | 10 / 11 / 12 / 13 / 15 / 20 六档；行高 1.25–1.4 |
| 密度 | 矩阵行 22px、表格 26px、一般行 30px（三套中最高密度） |
| 图形语言 | 状态矩阵、点阵进度、微条形、阶段门禁；标尺 / 裁切标记只出现在图像相关面板边缘 |
| 层级 | 无阴影，靠 `sunken → panel → raised` 三级明度 + 1px 线 |

**状态三重编码**（硬要求）：色相 + 明度 + 符号。矩阵符号：`●` 完成 / `○` 未开始 / `◐` 运行 / `▨` 过期 / `✗` 失败 / `–` 跳过 / `·` 等待。图例常驻，不依赖记忆。

## 2. 导航与工作空间组织

**按阶段组织工作面，而不是按页面。** 顶部阶段轨道既是导航也是进度与门禁：

| 阶段 | 工作面 | 主操作 |
|---|---|---|
| 1 DETECT 检测 | 页缩略网格 + Region 数与安全区 | 重检测、修几何 |
| 2 OCR 识别 | 页 × 识别质量 | 重 OCR、改原文 |
| 3 VERIFY 校对 | 对照复核面 | 确认、改译、加术语 |
| 4 INPAINT 修复 | 原图 / 修复对比 | 重修复、换路线 |
| 5 RENDER 排版 | 成品预览矩阵 | 重渲染、调样式 |
| Q QUEUE 队列 | Run 列表 + 后台任务 | 暂停 / 继续 / 重试 / 取消 |

```
顶 40px：阶段轨道（每阶段完成度 + 异常计数 + 门禁警示）· 当前批次 · 队列计数
├ 资源树 200px：作品 / 章节 / 批次 / 队列（+ 底部本章统计与告警）
├ 主区：概览计数胶囊（240 页·完成182·失败12·过期6·待确认40·阻塞0）→ 页×阶段状态矩阵 → 批量动作条
├ 详情抽屉 360px：选中单元的页/阶段/错误码/重试次数/Provider
└ 底部 24px：Run 状态带（#R-8831 · running · 62% · 12:07 · failed 3）+ 展开
```

## 3. 核心任务流程

**建批次 → 推进阶段 → 治理异常 → 交付**

1. 导入 → 自动创建批次 B-012，阶段轨道显示进入 DETECT
2. 停留在矩阵观察全批推进，或直接切 `3` 进 VERIFY 做校对
3. 概览胶囊显示「失败 12」→ 点击 → 矩阵只留失败行 → 框选 → 动作条「重试失败」
4. 全批阻塞（Provider 认证失效）→ 顶部红色提示 + 右侧 BLOCK 卡「处理」→ 修复配置后回队列恢复
5. 阶段门禁：RENDER 提示「12 页未修复，导出将缺失成品」，给出「仍然导出 / 先修复」两条路径
6. 批次完成后按批导出（预检：未确认 / 过期 / 失败）

## 5. 典型交互

- **状态矩阵即可操作画布**：点击单元格选中、`Shift` 框选、`Enter` 下钻详情抽屉、动作条批量处置；矩阵不是只读大屏。
- **概览胶囊即筛选器**：六个计数（240 / 182 / 12 / 6 / 40 / 0）点击即过滤矩阵，从"全批 240 页"直接收敛到"失败的 12 页"。
- **阶段轨道即门禁**：每阶段有完成度与异常计数；未达标阶段给出警示，阻止半成品直接导出。
- **异常聚合**：BLOCK / WARN / OK 三类告警卡（`INPAINT 2 单元失败 ModelLoadError`、`VERIFY 3 页待确认`、`DETECT 23/23 页已检测`），每张卡带「处理」入口。
- **键盘**：`1`–`5` 切阶段、`Q` 队列、方向键在矩阵内移动、`Space` 选中、`Enter` 下钻、`Ctrl+Enter` 推进、`Ctrl+K` 命令面板。

## 6. 优势与潜在缺点

**优势**
- 批量与异常处置最强：240 页的失败分布一眼看完，且可直接框选批量重试
- 状态最透明：矩阵本身就是状态真相，不存在"界面说完成、实际失败"的偏差
- 阶段门禁避免半成品流出，适合交付纪律严格的工作室
- 三套中唯一能支撑"多章批量生产日"的形态
- 可观测性最强：告警卡、运行带、统计胶囊构成完整生产视图

**缺点 / 风险**
- 单条精修不如 A、逐条校对不如 B：矩阵优先于内容
- 信息密度最高，新手需要图例教学，首小时眩晕风险最大
- 画面感最弱，容易做成"监控大屏"而失去操作感（本原型以可操作的矩阵规避）
- 对个人单章作业偏"重"，很多功能用不上

**最适合**：需要同时推进多章、以异常治理为核心、追求可观测与交付纪律的工作室或批量生产者。
