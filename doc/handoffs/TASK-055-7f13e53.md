## 交付结果

- **诊断包组装**（`src/application/maintenance/diagnostics.py`，新增）：
  - `DiagnosticsReport` + `build_diagnostics_report(...)`：**固定五段字段清单**（AC ①，清单=Task/Handoff 本文件）——`application`（app_version, platform_python）、`database`（schema_version, database_path 显示路径）、`settings_summary`（调用方摘要）、`recent_errors`（有界错误摘要）、`environment_paths`（data_root/managed_root/log 目录显示路径）；`to_json_bytes()` 稳定序列化（UTF-8、indent=2、sort_keys）。
  - **脱敏**：白名单优先——报告只含调用方显式递交的字段，凭据对象**结构性不可达**本模块；另有防御层 `redact_value`（键名命中 token/secret/password/credential/api_key/authorization 等模式 → `[redacted]`；值形如 `Bearer ...`/`sk-...` 亦遮蔽；普通路径/URL 不受影响）。
  - `BoundedErrorLog`：进程内有界错误环（max_entries，新进旧出），AC ② 的"有界保留"语义同样覆盖内存错误面。
  - `DiagnosticsService.export(generated_at)`：**一次调用**产出完整包文件（AC ① "一键"=服务层单调用）；依赖两个端口：`DiagnosticsSnapshotProvider`（摘要供给）与 `DiagnosticsBundleSink`（落盘去向）。
- **有界轮转日志**（`src/infrastructure/filesystem/bounded_log_store.py`，新增）：`BoundedLogStore(root, max_files=5, max_bytes_per_file=512_000)`——写入前预判轮转（每文件 ≤ cap 的不变量在每次 append 后成立；单行超 cap 时写入新文件、文件数界仍成立）；prune 恒删最旧；`<stamp>-<4位序号>` 命名使名字序==创建序（prune 腾出低位号不复用）；`threading.Lock` 串行化轮转决策（并发 append 每行不丢，已测）。
- **错误码口径**（AC ③）：`RecentError.code` 承载**既有 typed error code 字符串**（如 `PROVIDER_AUTH_FAILED`），不新造错误码体系；与 TASK-052 的联动=同一 `code` 字段复用。
- **边界（AC ④ 白名单按实际结构收紧，记录）**：草案路径 `src/application/**`、`src/infrastructure/**`、`tests/**` 实际落地为 `src/application/maintenance/diagnostics.py`、`src/infrastructure/filesystem/bounded_log_store.py`、`tests/diagnostics/**`（新目录，conftest 自带 sys.path 引导，与其他套件零耦合）。**装配接线与 QML 入口不在本切片**：`src/bootstrap/app.py` 与 `src/ui/qml/**` 未触碰——UI 入口受 TASK-047 设计门约束；生产装配与线程化 SQLite 装配切片协调（避免写集合重叠），本切片交付**可装配的服务层 + 端口**，"生产可达"登记为 NOT_RUN（见下表）。
