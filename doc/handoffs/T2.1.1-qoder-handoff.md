## 3. 关键决策（Review 重点）

### 3.1 `bg-canvas` 在亮色模式仍是深色 → 文字必须落药丸

`bg-canvas` 亮色值 `#26262a`。实测 `ink` 叠其上 = **1.14:1**、`ink-2` = 1.86:1、`ink-3` = 2.54:1，
两种模式不可能同时达标。契约自己的答案是把 viewer chrome 浮成 panel 药丸
（`.vfloat { background: var(--bg-panel); border: 1px solid var(--border) }`）。
于是新增 `CanvasCaption`，承载：原图/译图角标、两处占位文案、Region 工具提示。
**这是对布局的一处新增，不只是换色**，请重点看是否符合你的设计意图。

### 3.2 阅读器页底 = `bg-page`，`bg-canvas` 只给分页视口（契约偏离）

参考稿写 `#page-reader { background: var(--bg-canvas) }`。但本页还有状态横幅
与阅读进度两行文字，直接落 canvas 就撞回 §3.1。故页底保 `bg-page`
（`ink-3/page` 是契约已审对），把 `bg-canvas` 给真正承载图像的分页
Rectangle。**这是一处有记录的、可读的偏离**。连带遗留：webtoon 分支的
`Flickable` 无 background 属性，长图滚动区因此落在 `bg-page` 上，与分页不一致
（见 §7）。

### 3.3 `st-ok` / `st-warn` 是点色，`st-ok-t` / `st-warn-t` 才是文字（真实缺陷修复）

契约对比度表把 7 组徽标逐对钉死（`ui-reference.html` 1446–1452 行）：
`ok→st-ok-t`、`warn→st-warn-t`、**`skip→ink-2`**，另两对 R3-001 扩展
（`st-skip-direct/panel`、`ink/selected-row`）。而 `st-ok`、`st-warn` 在参考稿
里只出现在 `.dot` 与 `border`。我初版在三处把点色当文字用（进度面板
`completed`、页面列表 `completed`、书架归档徽标 `skip`），并且把
`completed_with_failures` 放在 `ok-soft` 上（契约是 `warn-soft + st-warn-t`）。
`d35ea8e` 修实现，`bc49ef9` 补一条测试。为什么必须单独立规则：比值检查对这类
错**部分失守**——亮色 `st-ok × ok-soft` = 4.43:1 确实掉线（说明契约不是随便选的），
但 `st-ok × bg-raised` 亮色 5.08:1、深色 7.02:1，`st-warn × warn-soft` 深色
7.27:1 全都照样过 4.5。也就是说纯靠对比度断言会放走大部分此类违规，只有把
“哪个令牌画文字”写成契约规则才抓得住（M5/M6 见 mutation 记录）。

顺带：契约 JSON 自称派生自 `doc/design/ui-reference.html`，并写明 HTML 为准。
本 Task 的所有取值判断都按 HTML 参考稿的 CSS/状态表来定，JSON 只作 parity 源。

### 3.4 在 Control 上写 palette 会切断继承（真实缺陷修复）

`RegionOverlay` 两个工具按钮原本写 `palette.buttonText:`，实测其内部 Label
仍是 `#ff000000`——给 Control 赋 palette 角色会让它脱离 window palette。
`27135e4` 改为 `highlighted: true`，由样式取 `palette.highlight`（accent）+
`highlightedText`（on-accent，已审对），外层加 `.vfloat` 药丸底。

### 3.5 为什么必须绑 window palette

F 默认深色，但 `Button`/`TextField`/`Dialog` 仍按平台浅色样式自绘。实测
`Label` 无显式 color 时取 `palette.windowText`，因此在 `Main.qml` /
`ExportWindow.qml`（第二个顶层 Window，不继承前者）各绑 11 个角色。
Qt 的 QML palette **没有** `palette.light.*` / `palette.dark.*` 分组写法
（赋值即 “Cannot assign to non-existent property”，实测过）；
`placeholderText` 只在 Control 层有效，也不能再分组。

### 3.6 几何落值（可见变化）

`rail-w 68`（原 64）· `tb-h 52`（原 48）· `insp-w 288`（原 264）·
`card-w 158` cell（原 168）· `prog-h 150` · `rad-sm 8px`（原 3/4px）·
`fs-sm 12px`（原 10/11px）· `gap 12px`（原 8px）。全部来自契约 geometry。
