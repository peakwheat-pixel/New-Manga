**三项发现（全部如实登记，[ocr-smoke-results.md](../verification/M2-TA3-B/ocr-smoke-results.md)）**：
1. paddlepaddle 3.3.1 Windows CPU 默认 MKLDNN 路径必崩（PIR/oneDNN `NotImplementedError`）——`enable_mkldnn=False` 修复，阶段二 runner 必须携带；
2. webtoon 长条漫整图（690x62133）超 OpenCV `SHRT_MAX`——OCR 测量只能在 region crop 级（生产链路天然如此）；
3. **生产 adapter `ocr_local.py` 向 PaddleOCR 3.x 直传 bytes 被静默忽略（空结果、无异常）**——非 fail-closed，src/ 禁改未修；阶段二用 `engine_factory` wrapper 绕行（ndarray 化），并登记为后续修复 Task 候选（交 Codex 裁决）。

## known limitations

1. 阶段一**不产生任何质量数字**——阈值全部为提案（ko 两档无基线依据），实测与校准在阶段二。
2. 生产 adapter 的 PaddleOCR 3.x bytes 兼容缺口未修（src/ 禁改），阶段二以 wrapper 绕行；该缺口在纯生产路径（Settings UI 选 PaddleOCR）下会静默产出空 OCR——修复 Task 候选已在 phase2-plan §5 登记，待 Codex 裁决释放。
3. ja native GT 仅 2 case（J46/J47，官方仅这两页有 SVG text layer）；BJ 字形专项结论依赖 G2 人工 GT 的用户审核工作量（裁决点 O-2/O-3）。
4. P&C SVG 文本是排版源文本，与页面渲染字形存在空格/换行差异——CER 归一化规则吸收，残差方向已登记。
5. 阶段二运行环境需 venv 融合（OCR 栈+生产栈不同 venv），方案 A 有一次性的 requirements 安装耗时。
