# Handoff — SETTINGS-OPEN-B-2（批次 B-2：缓存/Revision 清理操作面）

## 1. 交付摘要

按 [SETTINGS 分区 Schema 设计](../design/SETTINGS_SECTION_SCHEMAS.md) §4.3，把"缓存/Revision"从禁用占位变成真实操作面：

- **Core**：新增应用层命令 `cleanup.preview` / `cleanup.run` / `cleanup.retry_pending`（与 `settings.get` 同型，走 StdioLibraryChannel；**不**加入 `_HOST_CONTROL_COMMANDS` 冻结集合）。`CleanupService` 在 assembly 中用 `WebtoonTileCacheSweeper` + `ManagedFileStorage`（`remove_managed`）+ 既有 `_JsonTrashManifest`（与回收站共享 pending 账本）构造并注入；缺失注入 → `CORE_UNAVAILABLE`（unavailable/retryable=true）；payload 非 object → `INVALID_REQUEST`；request_id 安全脱敏。
- **投影**：preview `{targets:[{relative_path,size_bytes}], total_bytes, pending_cleanups}`；run/retry `{items:{relpath:{status,reason}}, removed, failed, skipped}`。
- **Tauri**：production-only 命令 `cleanup_preview` / `cleanup_run` / `cleanup_retry_pending`；`PRODUCTION_COMMANDS` 54→57、`CLEANUP_PRODUCTION_ONLY_COMMANDS`、`command_allowlist` 过滤、`generate_handler!`、`capabilities/m2rc1-commands.json`、`build.rs` 同步；tauri-build 生成物（`permissions/autogenerated/cleanup_*.toml` 与 `gen/schemas/*`）随 commit 提交。
- **前端**：`CacheRevisionPanel` 挂载自动预览、显示可清理数量/字节与挂起项、执行/重试（防重复提交、失败明细）、空缓存与错误态安全提示；`cache_revision` 分类 open（9 开 3 关：回收站/备份恢复/Plugin 仍关）；只读说明"Revision 保留策略与自动清理未开放"。
- **不开放**：自动清理天数、Revision 保留策略（无调度/存储消费点）。
