六阶段按模式摘要：

| 模式 | Proxy | DNS | TCP | TLS | HTTP | ProviderAuth |
|---|---|---|---|---|---|---|
| Direct | `not_applicable/direct_mode` | Provider endpoint 主机名；IP literal 为 `not_applicable/provider_endpoint_is_ip_literal` | 到 Provider endpoint 的逻辑直连 | 仅 HTTPS endpoint；HTTP 为 `not_applicable/provider_endpoint_uses_http` | Provider adapter 最小探测 | OpenAI-compatible 认证挑战时用当前 Provider credential；无需认证为 `not_applicable/provider_auth_not_required` |
| System | 系统针对 Provider endpoint 选出的代理；系统判定直连为 `not_applicable/system_route_is_direct` | Provider endpoint 主机名 | 经同一系统路由连接 Provider endpoint | 仅 HTTPS endpoint；代理自身 TLS 属 Proxy | 同一 Provider endpoint 与路由 | 同 Direct；不切换 Provider、不重试 |
| HTTP | 请求 Network Profile 的 `proxy_endpoint` | Provider endpoint 主机名 | 经选定 HTTP 代理到 Provider endpoint 的逻辑连接 | 仅 HTTPS Provider endpoint；HTTP 为 N/A | 同 authority 的 adapter `/models` 探测 | 同 Direct |
| HTTPS | 请求 Network Profile 的 `proxy_endpoint`，代理 TLS/CONNECT 属 Proxy 阶段 | Provider endpoint 主机名 | 经选定 HTTPS 代理到 Provider endpoint 的逻辑连接 | 只验证 Provider HTTPS endpoint | 同 authority 的 adapter `/models` 探测 | 同 Direct |
| SOCKS5 | 请求 Network Profile 的 `proxy_endpoint`，执行 SOCKS5 协商 | Provider endpoint 主机名；代理解析属于 Proxy | 经 SOCKS5 到 Provider endpoint 的逻辑连接 | 只验证 Provider HTTPS endpoint | 同 authority 的 adapter `/models` 探测 | 同 Direct |

所有模式下 Proxy 或其他阶段失败都会保留唯一失败阶段，并令其后阶段 `not_run/upstream_stage_failed`；不会尝试其他 Profile 或 Direct fallback。`status=passed` 时 `failed_stage=null`。无目标、缺省/null、非法或不可解析 Profile ID 均返回 `INVALID_REQUEST`，不生成 `NetworkTestResult`。

安全与实现限制：HTTP/Auth 响应 body、请求头、credential、Profile 路径和异常文本不进入结果、错误或事件；仅支持 `openai-compatible`、`openai-compatible-vision`、`local-sakura` 的最小连接探测，未声明探测契约的 Provider adapter 在 HTTP 阶段失败关闭。既有 `StdlibTransport.resolve_route` 对 SOCKS5 URL 的 proxy host 解析与本命令的 wire 值不一致；本实现只在该探测器内修正 route，不改变 1A/1B 共享 transport 语义。
