### 产品缺陷与最小复现

**F1 — production settings 响应泄露 OS 路径。** Core 的 `settings.update_section` 接受除 `sfx.policy` 外的任意 section/key 并返回完整 projection；`settings.get` 可再读该 section。Tauri handler 和 Rust library bridge 都将 `serde_json::Value` 原样跨层返回。P15 settings contract §9 禁止文件系统路径进入 WebView 请求、返回、事件或错误。证据：`src/bootstrap/core_service.py:1210-1269`、`apps/desktop/src-tauri/src/main.rs:518-549`、`apps/desktop/src-tauri/src/library_bridge.rs:1665-1686`、`doc/contracts/P15_SETTINGS_IPC_CONTRACT.md:301-321`。

最小复现（使用合成值、不访问该路径）：

```powershell
python verification/P19-AC3-1/repro_settings_path_roundtrip.py
```

输入：`settings.update_section({section:"ocr", values:{path:"C:\\private\\synthetic-source.cbz", api_secret:"P19_AC3_SYNTHETIC_SECRET_SENTINEL"}})`；随后调用 `settings.get({section:"ocr"})`。两次 `result.settings.ocr.path` 都等于合成绝对路径；`api_secret` 没有被返回；`file_io_attempted=false`。原始请求/响应断言与 stdout 在 `raw/settings-path-roundtrip.stdout.txt`。

**F2 — 顶层未知 invoke key 被静默忽略。** 锁定的 Tauri `CommandItem::deserialize_json` 对声明的每个参数仅执行 `v.get(self.key)`；宏为每个 handler 参数逐项创建 `CommandItem`，没有对 JSON 对象剩余 key 做检查。因此额外 `path`/写入目标等顶层字段不会使调用 fail-closed。创建命令对 `payload` 本身有 `deny_unknown_fields`，但外层 `{payload, unexpected_key}` 仍未被该 DTO 覆盖。依赖版本和原始源码摘录见 `tauri-command-argument-excerpt.txt`；逐命令签名及格子见 `command-matrix.md`。该结论是对所有注册处理器的源码级反例，不是已运行的 58 次 GUI 请求。

**F3 — 30 条 production 错误路径不使用封闭 error code enum。** Host `decode_response` 接受 Core 返回的任意字符串 `err.code`，相应命令只把该字符串作为 IPC rejection。当前未观察到 raw exception/path 文本泄露，但实现没有满足 AC4 要求的 host-side closed projection。`command-matrix.md` 逐条列出 30 条命令的处理器证据；Coordinator 可把它与 F1/F2 一并纳入独立修复 Task。
