## 设计取舍（Review 关注点）

1. **detect 插入条件收窄**：只对"页级 + steps 含 ocr"的命令前置 detect。最初无条件插入导致 rerender 页级计划多出 detect 单元、`missing_clean_artifact` fail-closed 守卫被 detect 失败遮蔽（既有用例红）；收窄后 rerender 语义不变。区域级（region 非 None）任务不插。
2. **回填策略**：detect 提交成功后，把**同一 task 内** `region_id=None` 的后续单元统一绑到首个新 Region。`task.units` 是 tuple，故 `execute_run` 循环改为索引式 while（旧 for 迭代器看不到重建后的元组；`task.units[:]=` 会 TypeError）。回填不落库（只改内存 task），后续单元各自的 step commit 才持久化 region 绑定。
3. **reuse 分支**：页已有 live Region 时复用（不重复检测）。注意：页有 Region 时 catalog 本会把任务展开为区域级（region 非 None、无 detect 单元），故该分支实际只在 plan 与 execute 之间的竞态窗口可达，用例按此时序构造（`test_detect_reuses_existing_live_regions`：detector.requests==[]）。
4. **detector=None 但 region_creator 注入**：fail-closed 检查是 `detector is None or region_creator is None` ⇒ 生产仍 typed 失败。region_creator 先注入是为：真实检测器接入（后续切片）时零装配改动即可落库。
5. **provenance 直传**：detection 的 provenance dict 原样进入 create_region 的 revision 元数据，不加工。
