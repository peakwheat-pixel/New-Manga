### AC1 定案与依据

Coordinator 于 2026-10-17 的裁决已解除硬门，未修改契约：

1. **WebView→Tauri 命令名为 `credential_put` / `credential_clear`。**契约 rev 2.7 §2/L27 的表头规定新增 WebView→Tauri 命令名，映射表 `Tauri command` 列列出这两个 snake_case 名称；同表其余命令也使用此命名面。
2. §4.1/L112–117 的 `PutCredential` / `ClearCredential` 是消息/DTO 类型名。它们分别映射至 §2 表中的 Tauri command；与 §3.2 的 `CreateProviderProfile` ↔ `settings_provider_profiles_create` 同一约定。
3. `credential_put` 只接收 `{ target: CredentialTarget, intent: create|replace }`，返回 `{ state: configured, masked_hint?: string }`；实现不返回 hint。`credential_clear` 接收 `{ target: CredentialTarget }`，返回 `{ state: missing }`。两个 WebView payload 都不含 Secret、明文或 `CredentialRef`。
4. 按 §4.1/L109、L119：无 Secret invoke 触发 Windows Host 外置 CredUI 对话框；Host 将一次性输入直接写 Windows Credential Manager，生成引用后经现有受信 Host→Core stdio 调用绑定。成功只回固定状态；取消和错误使用 §9 封闭投影。
5. §4.1/L121：`create` 要求当前 `missing`，`replace` 要求当前 `configured`；Host 在输入前和 Core 绑定前检查状态。冲突返回 `conflict`，不覆盖旧绑定。一次调用只调用一次输入面，操作串行；CredUI/Credential Manager 调用后，Host 的 UTF-16 输入缓冲由 `Drop` 清零。
6. `BindProfileCredential` / `ClearProfileCredential` 是 Host→Core 私有 route。它们未进入 Tauri command registry、production `generate_handler!`、build manifest、capability、生成 ACL/schema 或 autogenerated permissions。

### WebView 与 Host-only command 面

| 面 | 命令 / 形状 | 可见内容 |
|---|---|---|
| WebView→Tauri | `credential_put({ target, intent }) -> { state: "configured", masked_hint?: string }` | `target` 为 Provider API / Proxy Auth 目标；`intent` 为 `create` 或 `replace`。严禁 Secret 和 `CredentialRef`；当前实现不提供 `masked_hint`。 |
| WebView→Tauri | `credential_clear({ target }) -> { state: "missing" }` | 只传目标，无 Secret / 引用。 |
| Host→Core（非 Tauri） | `BindProfileCredential({ target, credential_ref }) -> { state: "configured" }` | 仅在受信 Rust→Core stdio exchange 内传递引用。 |
| Host→Core（非 Tauri） | `ClearProfileCredential({ target }) -> { state: "missing" }` | 仅在受信 Rust→Core stdio exchange 内调用。 |
