## 关键技术点

1. **F-4 的修法是 AC 的选项①**（裁到 `[content_top, content_bottom)`，overlap 仅作解码上下文）。这使"代码、注释、断言"三者一致：模块注释里的"exclusive content bands / dedup by construction"现在对**落盘文件**也成立（此前只有几何成立，文件含 overlap）。QML delegate 的 `PreserveAspectFit` 因此不再 letterbox（文件宽高比 == 声明盒宽高比），delegate 无需改动。
2. **新发现（P1 级、先于 TASK-045 存在）**：`ReaderView.qml` 的 `Repeater { model: visible ? model.tiles : [] }` 中，**限定名 `model` 在 Repeater 作用域内解析为 Repeater 自己的 `model` 属性**，故 `model.tiles` 为 `undefined` → delegate 一个都不创建；同时 `tilesHost.visible` 为真把整图 `<Image>` 隐藏 ⇒ **分块（webtoon tiled）视图自 TASK-020 交付起从未渲染任何瓦片**（用户看到空带，而非 F-5 描述的"旧图"）。修复：`model: visible && rv.model ? rv.model.tiles : []`。定性与隔离证据见 `pre-fix-delegate-diagnosis.txt`；`childItems()`（视觉层级）才能看到 delegate，`findChildren()` 看不到——测试因此按视觉层级断言。
3. **F-5 的两半**：VM 侧（换页重建行）+ QML 侧（delegate 的 source 随换页清空并刷新）。AC 允许"若只能真机观察须声明局限"——本次**做到了机器可验证**（QML 对象树级断言），无需声明该局限；但**仍未做真机截图**，见「风险与遗留 ②」。
4. **F-14**：内容寻址的代价是对已常驻源字节多做一次 `sha256`（该源本来就被 `__init__` 整体读入；对 AC ⑪ 的 96MB 夹具实测影响在噪声级）。旧键无法区分"同尺寸原地改写"，这正是 R-004/F-14 的缺陷。
5. **AC ⑩ 的实测与 AC 的前提相反**：`visible_tiles` 升序保证的是"不向后跳"，但 overlap 让**同一次调用里的每个后续块**都回跳一次。这不是"最多一次 rewind/调用"，而是 **O(块数) 次 rewind、总成本 O(块数²)**。TASK-042 Handoff 的"生产视口访问模式使全页只需一次顺序扫描"仅在 `overlap=0` 时成立。
6. **AC ⑨ 的构成项**：`_pump` 同时持有当前 IDAT 块与解压器的 `unconsumed_tail` ⇒ 块项按 **2×** 计。单块编码（整个载荷一个 IDAT）时峰值 ≈ 3× 源，分块编码（libpng ~8KB）时 ≈ 源 + 数倍带宽。
