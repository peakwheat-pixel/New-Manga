## 关键技术点

1. **F-1 根因**：`page.render()` 的缓冲是 BGR 字节序（`stride == width*3`），旧码把它包成 `Format_RGB888`（期望 R,G,B）→ 每页 R/B 互换，且**错误像素被写入 Managed Copy 并计入 `source_hash`**。修法即换格式名，但断言必须落到像素上——这正是 TASK-023 只核尺寸（`(1224, 1584)`）时漏掉它的原因（本条已按 TASK-043 AC ①「验收惯例」固化：**光栅化适配器必须有像素级断言**）。
2. **BGRA 分支**：不可达但不可含糊。`Format_ARGB32` = 32 位字 `0xAARRGGBB`，little-endian 下内存字节序即 B,G,R,A，与 pdfium 的 `BGRA` 一致；已用字节级探针钉住（见上表）。大端平台下该等价不成立，但本产品目标为 Windows。
3. **F-3 语义裁定（请 Reviewer 确认）**：
   - 失败后余页写入 `pending_after_cancel`。该字段名来自**共享的图像导入端口** `application/importing/images/ports.py`，而该文件**不在本 Task 白名单内** → 未改名，仅在 docstring 说明其语义已扩展到"未开始的页"。
   - `cancelled` 由 `bool(pending)` 改为"确实发生过取消"（`was_cancelled`）。原实现在失败余页非空时会把一次**损坏页**报成"已取消"，属误导；既有取消用例（`cancelled is True`）不受影响。这是本 Task 的一处**主动行为收紧**，请 Reviewer 裁定是否接受。
   - 0 页文档用 AC ② 给出的示例码 `INVALID_DOCUMENT` + detail `"document contains no pages"`（未新造码，避免与"损坏"混淆的额外枚举）。
4. **F-9 码位选择（请 Reviewer 确认）**：新报告码 `MISSING_DEPENDENCY`（大写，与同族 `INVALID_DOCUMENT`/`ENCRYPTED`/`UNSUPPORTED_FORMAT` 同形）。若沿用 `INVALID_DOCUMENT`，用户会得到"文件无效"的**误导诊断**；仓库另有小写 `missing_dependency`（Provider readiness，`src/ports/providers/errors.py:257`）为同义词汇。捕获范围取 `(ImportError, OSError)`：绑定未安装是 `ImportError`，原生库加载失败通常是 `OSError`，两者都是"依赖不可用"，且原始信息保留在 `detail` 中。
