**关键设计决策**：

1. **「单一写者」（P0 约束）**：`RenderService` 是 `translated` 页面指针的**唯一写者**——它经既有 `_commit_translated` → `commit_revision(expected_current_revision_id=...)` 以乐观 CAS 提交；render handler 的 `StepResult.revision_updates={}`，seam 不再翻转同一指针（与 mask/clean 的既有"handler 内 CAS、seam 只记 stage"模式一致）。测试证明：每次 render 恰好 +1 个 translated revision、current 恰指向最新、三次 render 后 `[1,2,3]` 无抖动、run 无 candidate（`test_render_is_the_single_translated_pointer_writer`）。**未改 seam**。
2. **fail-closed**：三 handler 在服务未装配时抛 `PROVIDER_NOT_CONFIGURED`；render 在缺上游 Clean 时抛 RenderService 自己的 `MISSING_REQUIRED_INPUT`；`needs_fallback` 是 color 的**输出**（冻结回落规则），不是静默降级。
3. **`content_decoder` 适配理由**：pipeline 制品用 provider 层 `NMFR` 容器（`application/x-newmanga-frame`，TASK-018 有意设计的非共享格式），渲染组合需要 PNG——两种已审格式之间的桥接只能发生在装配面。选择 opt-in 参数而非改 `NMFR` 格式或让 application 层 import infrastructure（S-1 分层守卫禁止），默认行为完全不变、已存制品不动。
