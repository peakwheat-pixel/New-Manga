## R-011 裁决（httpx vs stdlib 架构偏差）

**事实**：D02 §2 把 HTTP 外呼技术选型记录为 `httpx`，实现采用 stdlib（`socket`/`http.client`/`ssl`）；Task 文件中没有批准的偏差记录。

**Reviewer 裁决：接受 stdlib 实现，但偏差登记必须由 Codex 在 D02 内完成。**

理由：①本切片所需的全部外呼能力（HTTP/HTTPS、HTTP 与 SOCKS5 代理、CONNECT 隧道、absolute-form、双向 TLS、连接/读/写超时、typed 错误分类、显式 fallback 与阶段 trace）均已实现并有 91 项通过的测试覆盖，`httpx` 的相对优势（异步、连接池、HTTP/2、自动重定向）在本切片与当前产品路径中**均未被使用**；②实现**零新增第三方依赖**，与项目"精确锁定依赖"的策略一致；③改回 `httpx` 需要重写 transport 层及其错误映射与代理 seam，成本与回归风险显著，而产品行为不变。

**但本裁决不等于关闭该 finding**：偏差仍是"文档与实现不一致"的事实。请 Codex 在 D02 §2 以架构偏差记录的形式固化"TASK-009 起采用 stdlib 实现 HTTP 外呼"及其理由（或走范围变更流程改回 `httpx`）。**在 D02 完成登记前，R-011 保持 P2 open**；该项不阻塞本 head 的集成，但不得在未登记的情况下把偏差视为已批准。
