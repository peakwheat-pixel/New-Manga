## Architecture（executed）

- **触发面归属（用户裁定项）**：**接受"放在 VM"**。理由（读码 + 探针双重支持）：瓦片行与 rasterizer 都归 `ReaderViewModel`，QML 只做 `rv.model.tiles` 的响应式渲染；VM 侧物化后 QML 绑定自然刷新（B1/B3 已证）。若 QML 再加 `tilesChanged` 触发，会对同一视口产生**二次物化**——在 `overlap>0` 的现行解码策略下每次物化都要 rewind（正是 TASK-046 要收敛的成本），故不叠加触发更稳。**代价与不变式**：VM 自此必须拥有**所有**会改变页面来源的入口（打开/翻页/跳页/继续阅读/重开/切模式）——本切片已在这 5 处调用 `_rebuild_tiles`（首轮 + 本轮一致），应作为后续新增 slot 的硬约束。
- **服务/通知时序**：`_rebuild_tiles` 末尾 `_serve_viewport(..., notify=False)` 后**一次性** `tilesChanged`；`_serve_viewport` 内部仅在成功且 `notify=True` 时发信号 ⇒ 无重复通知、无中间态广播 ✓
- **失败路径**：rasterizer 构建失败时清空行并立即 `tilesChanged`（回退整图路径）✓；`_serve_viewport` 的解码异常被 `except (OSError, ValueError)` 兜住（R-004 的 `OSError` 正落在其内）⇒ 单块解码失败不会让翻页崩掉，只会少服务 ✓
- **状态卫生**：`openChapter` 把 `_viewport_page` 清空（新章节由 QML 的 offset 恢复去请求真实窗口）✓；`_viewport_page` 仅保存"页像素"窗口，不跨章节串味 ✓
- **观察（P3，非缺陷）**：bootstrap 调用会令 `_viewport_page = (0, 0)`；此后 `_viewport_for_new_page` 的 `span = max(1, 0) = 1`，即"记忆窗口"退化为 1 行。生产 `prefetch=1`（`src/bootstrap/app.py:548`）下服务集合仍是 tiles `{0,1}`（VM 用例已钉住），故**当前行为正确**；但语义上 `(0,0)` 同时承担"无记忆"与"页首窗口"两种含义，建议将来改为 `None` 或显式 `_BOOTSTRAP` 常量。
- **分层**：改动全在 `ui/viewmodels`、`ui/qml/reader`、`infrastructure/imaging`；QML 仍不直接访问文件/DB（只消费 url 与行数据）✓
