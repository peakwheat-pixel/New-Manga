#### N-1 (P1) — SC-10 被回标为 [现行]，但「应用内数据默认包含」不成立（v1 原本正确）

- 位置：草案 `:50`（SC-10 状态列 `[现行]（不含外部原件已成立）`）。对照 v1（`491dfa0cc`）该条为 `[新增]（需扩展备份清单）`。

- 事实核验（代码在 r1 与本轮间未变，结论可复用）：
  1. 前半成立：`.nmbak` 包成员固定为 `manifest.json` + `library.db` + `library.db.sidecar.json` + `managed/…`（`nmbak.py:3-10,50-53`），模块文档明写 never touches user source files ✅。
  2. 后半**不成立**：清单**只**覆盖 DB 与 `managed/`（`nmbak.py:197-226`），`settings/*.json`、`catalog.sqlite` 未入包 —— FEA-01 C-09（`doc/plan/FEA-01_CONTRACT_DRAFT.md:58`）把它们明确列为「备份覆盖清单（`settings/*.json`、`catalog.sqlite` **现状缺失项**）」；「Run 快照」「源引用与授权元数据」当前连数据结构都不存在（AD-003 §4：sources 系列表未定；`DatabaseId`/`SourceAccessRegistry` 0 命中）。
- 影响：状态列是**整条**条款的标签，标 [现行] 等于把「应用内数据类别默认全覆盖」记为已具备；这与 r1 F-05（SC-08）同类的过度声明，且**相对 v1 是回退**（v1 的 [新增] 是对的）。若按此冻结，C-09 的备份覆盖清单缺口会失去契约依据。
- 建议：拆两段 ——「默认不含外部原文件」`[现行]`（证据 `nmbak.py:3-10,50-53`）+「应用内数据类别默认全覆盖（含 `settings/*.json`、`catalog.sqlite`、Run 快照、源引用/授权元数据）」`[新增]`（证据 FEA-01 C-09 现状缺失项）。也可保留 [现行] 但必须把第二半显式移出该条。
