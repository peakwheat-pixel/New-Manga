## Architecture 轴

**分层与 seam**：设计把 SQLite 细节严格留在 Infrastructure，Application 继续只依赖既有消费侧 Protocol，并拒绝巨型 Repository——与 TASK-006/007/008 已集成的方向一致，无逆向依赖。§2.2「复用而不是改写现有基础设施」明确 v1 迁移不可编辑、继续使用现有 `open_database()`/`MigrationRunner`/Artifact commit 语义，避免了两套 current/checksum 语义。

**与 TASK-002 契约的一致性**：§3.4 的 Region 约束（`UNIQUE(region_id, revision_no)`、current 复合外键、`restored_from_revision_id` 复合外键、首次原子创建、current 不可清回 NULL、Pin 只改标志、恢复新增 Revision）完整覆盖契约 §2.1 并给出更细的落库形态；§4.2 的冲突结果映射（`INPUT_REVISION_CHANGED`/`LOCK_CHANGED`）与契约 §10 的错误层级一致。Region 的「current 不可清回 NULL」与 TASK-006 为 `media_artifacts` 建立的触发器方案同构，属可复用的既有模式。

**待补的架构细节**：Region 的 current 复合外键**未注明 `DEFERRABLE INITIALLY DEFERRED`**——TASK-006 的 `media_artifacts` 正是依靠该属性才能在同一事务内先插 Revision、后更新 current pointer（见 `schema.py:67-68`）；设计若不同步该属性，"首次 Revision 与 current 的原子提交"在 SQL 层无法成立（F-02b）。
