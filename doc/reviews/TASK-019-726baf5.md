## 重点项核查

### R-1 prepare-only 写入与 seam 收编的并发窗口 —— **接受（残余风险，已缓解、已登记）**

`step_writes.py` 的语义是"handler 准备内容 revision，指针由 seam 的守卫事务翻转"，与 TASK-013 的乐观提交契约一致；region 作用域单元无法在 `StepResult.revision_updates` 表达 page artifact 指针，故 `ArtifactStepWriter.adopt_current` 自行做同型 CAS 并明确声明。写入侧新增 `expected_current_revision_id` 期望校验（含 `UNCHECKED` 哨兵区分"未提供期望"与"期望 NULL"）。

残余窗口真实存在但后果有界：窗口内并发写最多导致**该步骤 CAS 失败并记为 candidate**，已提交的内容 revision 保留、指针不会回退（无数据损坏、无越权写）。彻底消除需要 seam 提供"内容+指针同事务"入口（`src/infrastructure/pipeline/**`），**超出本 Task 允许路径**，故登记为残余风险，不阻塞。

### R-2 AC-RFULL-001 的 `color`/`term_extract`/`render` 归属 —— **Codex 裁决：不属于 TASK-019，AC 保持 BLOCKED 并登记后继**

D08 §AC-RFULL-001 明确要求完整链 `OCR → Color → Term Extract → Translate → Segment → Mask Refine → Inpaint → Render → Save`。本 Task 的允许路径只覆盖 Provider 集成层（`src/infrastructure/providers/**`、四个能力端口、`src/application/translation/inpaint/**`、`src/bootstrap/app.py`、`tests/providers/**`），`color`/`term_extract`（翻译域）与 `render`（渲染域，TASK-014 已交付的渲染切片）**不在其中**。

**裁决**：不扩展 TASK-019 允许路径去吞并其他 Task 的领域；**AC-RFULL-001 在本 Task 内保持 `BLOCKED`**，作为后继切片/Task 的输入，需用户批准释放后方可实施。实测部分链（`segment → mask_refine → inpaint`，含页面级 `REINPAINT_ALL` 展开为 3 个 Region 单元并累积 Clean）已通过，属真实进展，不作为完整链通过。

### R-3「彩色/高复杂度不接受单色基线」 —— **产品取舍待用户裁决，当前 fail-closed 保持**

`acceptable_routes()` 对 `is_color_webtoon` 或高复杂度背景只接受彩色路线，否则 `BLOCKED` 并在 provenance 记录 `router_reason`/`router_color_route_selected`。D06 §21 只给策略示例，未规定必须降级；本裁决与项目"不可用候选明确禁用、不得静默降级"的原则一致。**是否允许用户在设置中显式开启降级属产品需求取舍，按协作协议由用户决定**，本轮维持现状（不静默降级）。

### R-5 `sfx_policy` 默认 `skip` 使链路在真实使用中被 SKIP_POLICY —— **经本 Reviewer 独立坐实，属既有跨 Task P0 缺陷，登记后继（不得由本 Task 修复）**

本 Reviewer 独立复核（不依赖作者描述）：

- `src/domain/regions/entities.py:230`：`sfx_policy: SfxPolicy = SfxPolicy.SKIP`；
- `src/infrastructure/sqlite/schema.py:229`：`sfx_policy TEXT NOT NULL DEFAULT 'skip'`；
- `src/application/editing/service.py:254`：新建 Region 的**默认参数**同样是 `SfxPolicy.SKIP`，且 `src/ui/**` 与 viewmodels **无任何**写入 `sfx_policy` 的路径；
- `src/application/tasks/service.py:353-361`：planner 只要 `sfx_policy in {"skip","manual"}` 就对 `translate/segment/mask_refine/inpaint/render` 一律返回 `PlanDecision.SKIP_POLICY("sfx_skip")`——**该判断没有检查 `region_type`**（`region_type` 默认 `SPEECH`，见 `entities.py:223`）；
- `tests/pipeline/test_pipeline.py:47` 的测试辅助默认值是 `"translate"`，因此既有 640 项测试**照不到**真实默认值下的行为。

**影响**：以真实默认值新建的普通（SPEECH）Region 会在规划阶段被跳过整条链路——即使 TASK-019 的 provider 全部就绪，端到端重翻译在这套默认下也不会执行。这是**既有缺陷**（涉及 `domain/`、`application/tasks`、`application/editing`、`infrastructure/sqlite/schema.py`、`tests/pipeline`，全部在本 Task 允许路径之外），本 Task **不得**顺手修复。

**处置**：登记为跨 Task P0 缺陷，需用户/Codex 裁决两件事——① `sfx_policy` 是否只应作用于 SFX 类型 Region（若是，planner 需加 `region_type` 门控）；② 新建 Region 的默认策略应是 `skip` 还是 `translate`（含 Schema 默认与快照默认的不一致：`sqlite/pipeline.py` 的 snapshot 默认与实体/Schema 默认口径不同）。裁决后作为独立 Task 释放，并在 `tests/pipeline` 用真实默认值补回归用例。

### R-6 `src/ports/providers/errors.py` 是否越界 —— **本 Review 追加授权为允许（附带流程提醒）**

该文件是**纯新增模块**：本 Review 确认 `profiles.py` 之外没有任何既有文件被改动，新增模块不被既有类型继承/依赖，四个新能力端口与适配器共同使用它作为单一错误/就绪分类家。任务文本对该 glob 的限定（"只允许扩展 capability 常量与新增可选字段"）本意是禁止改变既有 profile/capability 语义，而不是禁止在同一包内新增独立模块。

**裁决**：**批准该范围追加**（`src/ports/providers/**` 内的新增独立模块，零既有语义改动），并在 Task 文件登记为范围变更。流程提醒（P3）：新增模块应**先**申请范围变更再落盘；本次为事后追加。

### R-8 页级 mask artifact 与 Region 一对多 —— **接受（数据模型限制，已登记）**

页面级命令按 D06 §48 展开为 Region 单元后，同页多个 Region 各自产生 mask revision，而 mask artifact 行是"一页一行"，因此指针最终只指向最后一个 Region 的精修 mask（历史 revision 均保留；Clean 侧因累积上游不受影响）。这是 D03 §16 的既有归属模型限制，按 Region 查看 mask 需要 Schema/数据模型裁决，**超出本 Task 允许路径**。本 Reviewer 确认作者已用真实用例取证（页面级展开 3 个 Region、生成 6 个 mask revision、Clean 串联递增）。
