## 四项重点答复（本次 Review 指定）

1. **`search` 化 + 左守卫只挡字母数字，误伤面是否可接受**：**可接受**，且当前现实危害为零（唯一消费者是尚未接线的诊断包）。
   依据：良性侧被 5 条用例钉住（含 `task-live-run/comic-sketch.png`、反斜杠路径、`1.0.0+build.7`）；
   我的对抗集里"该留的"全留、"该遮的"全遮。但两处记账：**(a)** 注释给的原理只覆盖**字母数字**邻接，
   `_` 与 `.` 邻接照样命中——实测 `provider_sk-abcdefgh1234`、`pkg.sk-abcdefgh1234`、`C:/Users/sk-1a2b3c4d/…` 均被遮，
   所以"why it doesn't bite"那句论证比实现窄；**(b)** ≥8 token 门槛使 `sk-abc1234` 放行，短键不遮是有意的但没写在 docstring 里。
   → R-003（P3：把这两条写进 docstring，或把守卫扩到 `(?<![A-Za-z0-9_.])`——注意扩大守卫会**降低**保护，
   被引号/反斜杠包裹的凭据会漏，所以我**不**建议改，只建议写清）。
2. **整值替换是否牺牲过多可诊断性**：**方向正确，代价被多算了一段**。composite key 里的时间戳+source 通常不含凭据
   因而幸存（实测 `'2026-09-19T08:12:03+00:00 provider.translation.openai'` 完整保留），报告于是仍知"何时/哪个组件"；
   但 value 是 `f"[{error.code}] {error.message}"` **拼接后才过屏**，一次命中就把 `[PROVIDER_AUTH_FAILED]` 这个
   **本来就是摘要、永不可能是凭据**的错误码连同整条消息一起变成 `[redacted]`——丢的恰是"为何"。
   我在探针里演示了同一行的 span-only 结果（保留 401/endpoint/提示，只遮 token）。
   建议：code 与 message **分别**过屏（code 直接保留），或改 `sub`；趁 TASK-055 未接线，现在改代价最低。→ R-002（P3）。
3. **"先断言夹具非全 filter-0"能否报警而非静默通过**：**能**——断言位于字节同一性之前，libpng 若退化为全 filter-0，
   该用例会红且消息直接写明 `fixture is all filter-0: R-001 would stay open`，不会给出"通过但零覆盖"的假绿。
   两个残留须知情：**(a)** 这类红是**环境信号**不是产品缺陷（换 libpng 版本/图样可能无关地变红）；彻底解法是补一条
   **手工多过滤器页**（`test_streaming_png.build_png(..., filter_type=4)` 现成可用，我上轮实测 400×2000 成本 <1s），
   它既穷尽 `Up`/`Average`，又把这条断言从"必需"降级为"可选保险"。**(b)** 辅助函数自身没有健全性检查
   （不验 `len(raw) == height * stride`、不防 interlace）：解析一旦走偏，返回的集合可能既小又非 `{0}`，
   "报警器"自己被骗过。加 1 行长度断言即可闭环。→ R-004、R-006（均 P3）。
4. **R-009 以"记录 + 待集成方落改"处置是否可接受**：**可接受，且是这里正确的做法**。范围约束是真的：
