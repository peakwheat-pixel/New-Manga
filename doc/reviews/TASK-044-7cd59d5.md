## Architecture（必覆盖）

**`executed`**。

- **删除语序与真实 FK 图一致**：`purge_pages` 的单事务顺序为「清悬空 provenance → `step_result_candidates → step_runs → pipeline_tasks → pipeline_run_targets` → `artifact_revisions` → `media_artifacts` → `region_revisions` → `regions` → `pages`」，并额外清 **无 FK 键**的 `pipeline_stage_states`（page 与 region 两种 target）。我逐条比对 E0a/E0b 的枚举 ⇒ **未漏表**。
- **破环手段正确**：不清 `current_revision_id`（触发器禁止），而是依赖 `DEFERRABLE INITIALLY DEFERRED` 的"同事务两侧同删"；自引用（`artifact_revisions.source_artifact_revision_id`、`region_revisions.restored_from_revision_id`）在同一语句删除链上不构成阻碍（E3/E4 实测）。

- **分层**：新方法都挂在既有 `SqliteLibraryRepository` / `PageTrashStore` 契约上；`ports.py` 只增方法契约；未引入反向依赖。
