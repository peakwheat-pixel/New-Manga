## Architecture（轴状态：executed）

- **`purge_pages` FK 删除顺序正确**：`regions.page_id → pages(page_id)`、`region_revisions.region_id → regions(region_id)`（schema.py:226/249），故顺序必须 region_revisions → regions → pages，实现一致。`regions(current_revision_id, region_id) → region_revisions(...)` 为 `DEFERRABLE INITIALLY DEFERRED`（schema.py:242~245），同事务内先删 revisions 再删 regions 合法（事务提交时 regions 行已不存在）；`trg_regions_current_not_clearable` 是 UPDATE 触发器，DELETE 不受影响。
- **`soft_delete_pages` 语义**：`WHERE ... AND deleted_at IS NULL` 只影响未删行，返回 `cursor.rowcount`；reader/import 视图经既有 `list_pages`/`get_page` 的 `deleted_at IS NULL` 过滤天然隐藏（library.py:327~352，含注释声明回收站视图走独立查询）。
- **manifest 与 DB 一致性窗口**：作者风险 1（soft-delete 侧：DB 已写、manifest 未记录→页仍可恢复，非数据丢失）**评估属实、严重度低**。但 `purge_batch` 的对称窗口（文件已删→行未删→manifest 未清，崩溃命中时 restore 会恢复指向已删文件的活页）未在 Handoff 声明，见 R-003（P3）。`get_pages_by_ids` 不过滤 `deleted_at` 且对缺失 id 静默跳过，符合 trash 视图需要；由此产生的孤儿文件残留（行先丢、文件后删失败）为理论窗口，量级 P3 以下，随 ledger 子集一并处理。
- 轴小结：1 个 P3（R-003），无 P0/P1；核心不变量（FK 顺序、单值时间戳、防逃逸）全部成立。
