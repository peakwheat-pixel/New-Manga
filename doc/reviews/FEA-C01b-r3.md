#### P1-1 (P1) — 文档控制字段未随 v3 同步：仍自述「DRAFT v2 / 已过 r1」，冻结条件仍引用已完成的 r2

- 位置：草案 `:3`（状态行）、`:6`（依据行）、`:122`（§4 冻结条件第 1 条）。
- 事实：
  1. `:3` 写「状态：**DRAFT v2 / 已过 r1 独立复核（`changes_requested`，P0×1 / P1×7 / P2×6 已处置）**」——但 §5（`:135`）与提交 `89aa61849` 均为 **v3**，且 **r2 已跑并返回 `changes_requested`（P0×0 / P1×1 / P2×8）**，状态行未记录。

  3. `:122` 冻结条件仍写「（**r1 已跑，本轮 v2 修订后需 r2**）」——把一轮**已完成且未通过**的复核写成"待进行"。
- 影响：本草案的全部价值在于「冻结时其文本与状态可被引用」。按现状冻结，冻结记录会引用一份**自述为 v2、自述只经过 r1** 的文档，且冻结门禁引用一个已被判 `changes_requested` 的轮次；这与 §5 的 v3 行直接矛盾（同一文件内两个版本号）。v1→v2 时该字段是**同步更新**过的（v2 状态行写「已过 r1」），v3 的遗漏属回退。
- 建议（三处一行级改动）：①`:3` 改为「DRAFT v3 / r1（P0×1/P1×7/P2×6）与 r2（P0×0/P1×1/P2×8）已处置 / 待 r3 / 未冻结」；②`:6` 补 r2 报告链接；③`:122` 改为「r1/r2 已跑，本轮 v3 修订后需 r3」。

### P2

#### P2-1 (P2) — SC-09 归入「文档级约束」掩盖了「盘点 + 可预览清理任务」的能力缺位

- 位置：草案 `:47`（SC-09 状态列与验证列）。
- 事实：SC-09 条款含两部分 —— ①禁止性（「不得绑定到界面切换或 Schema 升级自动执行」）＝文档级约束成立；②能力性（「须另行盘点备份/任务/引用并**形成可预览的清理任务**」）＝**当前无实现**（v2 原文自述「亦无盘点功能」，v3 移到验证列仍写「当前无该任务面」）。按 §1 判据「有代码但保护/清理能力缺位 → [新增]」，第②半应为 `[新增]`。
