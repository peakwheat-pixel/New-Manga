## Architecture 轴

- **分层纯净**：`git grep -E '^\s*(import|from)\s+(PySide6|shiboken6|sqlite3|infrastructure)'` 在 `src/domain/tasks`、`src/application/tasks`、`src/application/translation/pipeline` 三处**均无命中**——领域层不含 Qt/sqlite，应用层不反向依赖基础设施。
- **seam 显式且最小**：`application/tasks/store.py` 以 `TargetCatalog` / `SnapshotProvider` / `PipelineStore` 三个 Protocol 定义可注入边界，并给出 `InMemoryTargetCatalog` 实现。这与 TASK-006/029 的"消费侧 Protocol + 基础设施适配"惯例一致，且在 TASK-011 明确禁止触碰 Schema/共享 Port 的前提下，是**在不扩范围的同时保持可测**的正确取舍。
- **不可变快照**：`freeze_snapshot` / `_freeze` / `_clone` 使 scope 与 target 快照具备防御性拷贝语义，测试直接断言其不可变性，满足"不可变目标/配置快照"。
- **不动共享面**：`src/infrastructure`、`src/ports`、`src/bootstrap`、`requirements*.txt`、`AGENTS.md` 以及 TASK-010 已审的 `translation/{context,knowledge}` **零改动**；无 Schema/migration 新增。Handoff 亦声明"本交付没有新增 Schema、共享 Port、bootstrap 或依赖"。
- **控制面与执行面分离**：`PipelineService` 持有生命周期（plan/execute/control/recover/retry/progress），`StepExecutor` 只负责单步工作且以注入方式提供——调度器不内嵌任何 Provider 语义，这使 AC-RETRY / AC-CRASH 的失败路径可在无 AI 依赖下完整验证。
- **可改进**：默认 store 为内存实现，因此"崩溃恢复"目前只在进程内被证明（R-003）；4 个项目状态文档越出白名单（R-002）。
