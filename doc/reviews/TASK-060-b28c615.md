## Architecture 轴：executed

`ThreadRoutedConnection` 把"两线程各自 commit/rollback 同一事务"变成**结构上不可表达**——这是正确的收敛层级：
repository/服务层零改动，facade 转发 `execute/cursor/commit/rollback/with/__getattr__`，registry + 锁统一 close，
`check_same_thread=False` 的作用被限定为"跨线程关闭"并写明。取舍（放弃单写者串行化）与风险（WAL 跨连接可见性、
busy_timeout）在模块 docstring 与 Task 内都有据。原 TASK-048 docstring 里那段"有界交错/自愈"的缺陷自述被删除而非
留成第二套说法，是对的。

两点结构性后果需要下游知情：**(a)** `in_transaction` 等每连接属性的含义静默从"这个库"收窄为"本线程"（实测见 R-004），
facade 公开面只剩 `close/commit/cursor/execute/rollback`，**没有任何聚合"是否还有别的线程在写"的视图**；
**(b)** 每线程惰性建连使连接生命周期与线程生命周期绑定，而驱逐点不存在（R-002）。这两点决定 TASK-057 前置①
的写法（见"四项重点答复"①）。

分层与边界：未见越层（QML 不碰 DB/文件；`ports.py` 只加协议方法；Schema/migration/依赖清单零改动）。

## 四项重点答复（Handoff 指定）

1. **能否作为 TASK-057 前置① 的结构基础**：可以，但**不能只靠连接对象**。`shutdown() -> bool`（drained）是正确的排空谓词，
   且 `run_controller.py:96-116` 把"纯线程清理"与"cancel + 清理"分层，超时路径不 `deleteLater`、不清 `_active_run`，
   语义诚实。但 restore 若要问"此刻还有别的线程在写吗"，facade **答不出来**（S3 实测：`in_transaction` 已为本线程视角，
   公开面只有 5 个方法）。且 `backup.py:50` 的 `self._conn.backup(destination)` 经 `__getattr__` 绑定到**调用线程**的连接——
   今天恰好只有一个 run worker 会并发写，所以"drained==True ⇒ 无其他写者"成立。建议：TASK-057 的门显式写成
   `workbench.shutdown() is True and controller.is_running is False`，并在 facade 上补 `any_in_transaction()` /
   `release_current_thread_connection()`（后者同时是 R-002 的驱逐点）。
2. **PAUSED 的 cancel 写在 VM 层**：归属划分**正确**——worker 在 `pause` 时 `_persist` 后 return，`_on_finished` 已把
   `_active_run` 清空，controller 确实不再持有该对象，只有 VM 的 `self._run` 还在。**但该写入无人持久化**（见 R-007）：
   库里那行仍是 `paused`，下次启动可继续。所以 AC⑥ 的 PAUSED 子句在"结构上请求了停止"成立、在"有可观察后果"上不成立。
3. **`list_live_managed_refs` 软删行也算活**：语义正确且有意为之（`library.py:472-485` 无 `deleted_at` 过滤——
   软删行仍可恢复，其文件当然不能被 sweep）。我另查了一个残留面：该查询只看 `pages.managed_original_ref`，
   而 purge 清单里还含 artifact 文件——不构成 fail-open，因为同一条目的 batch-id 路由一旦命中就整条跳过，
   而 id 不可恢复时页行必已随 purge 删除。**判定：非缺陷。**
4. **判别用例的交错方案与 CHECK 合法值**：方案成立且是我见过的对该机理最干净的复现（Event 强制调度、纯 `commit()` 无 DML、
   judge 用独立连接）；我在 `a2b23ad` 独立复算 ×2 均为 2 failed，失败断言文本就是归属机理本身。
   fixture 的 `origin='user'`/`review_state='confirmed'` 满足 `schema.py` 的 CHECK——**作者踩过的"CHECK 违规静默吞线程异常**
   **造成假阳性"这一课值得留在 Handoff 里**。缺口不在这里，而在"同一把尺子没量到 trash 面"（R-001）。
