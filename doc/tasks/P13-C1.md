# P13-C1：Runtime IPC 契约修订

## 来源与目标

- 来源：**P13 的 `BLOCKED_WAITING_EXTERNAL_DECISION`**（`verification/P13/blockers.md`，P13 实现 head `2d65f7f8`）。
  P13 依据 `doc/contracts/P11_LONG_TASK_LIFECYCLE_CONTRACT.md` 要实现 durable acceptance / 控制 / 查询 / 投影 / 事件，
  但**冻结的 `doc/contracts/M2-C1_TYPED_IPC_CONTRACT.md` 不提供合法的 wire 面**：
  - §5 `StartRun` 输入仅 `{command, scope, overrides?}` —— **没有幂等键**，而 P11 §2.1 要求调用方提供 `idempotency_key`；
  - `CoreServiceServer.dispatch_request` 无 `StartRun` / `ControlRun` / `GetRunSnapshot` / `GetTaskProjection` / `RetryFailedTargets` handler；
  - 没有 Run 状态事件面（P11 §7.3 要求重要状态事件立即刷新）；
  - §12 声明该契约**不授权 Python IPC Runtime**。
- 目标：作为 **P13 的前置契约 Task**，先冻结 Runtime 的 wire 行为与授权边界，使 P13 能在**不改 wire 之外**实现；
  本 Task **只做契约设计**，不实现 runtime、不改产品代码。

## Acceptance Criteria

- [ ] AC1 **StartRun 幂等键 wire 表达**：定义 `idempotency_key` 的字段名、类型、必填性、作用域与语义
      （同键同请求 → 返回既有 Run；同键不同 fingerprint → 拒绝），并与 P11 §2.1/§2.2 逐条对齐。
      必须明确：**请求关联 ID（如 `request_id`）不得被偷换为幂等键**。
- [ ] AC2 **Run 控制面**：定义 `ControlRun`（pause / continue / stop / restart / abandon）的 wire 表达，
      与 P11 §4.2 合法转换表、§4.5 非法转换拒绝清单**逐条映射**；明确非法动作的返回错误类别（如 `INVALID_RUN_TRANSITION`）。
- [ ] AC3 **Run 查询与投影面**：定义 `GetRunSnapshot` / `GetTaskProjection` / `RetryFailedTargets` 的 wire 表达，
      与 P11 §3.2–§3.3、§7.2 对齐（投影为只读视图，与 PageList 同源）。
- [ ] AC4 **Run 状态事件面**：定义最小事件集（至少覆盖 Task Failed / Run Paused / Run Completed / Current Page·Step Changed），
      与 P11 §7.3 的"重要状态事件立即推送"对齐；说明与既有 stdio 协议的关系。
- [ ] AC5 **授权边界与兼容性**：显式更新 §12 的授权声明（是否授权 Python IPC Runtime 实现），
      并写明本次修订的 **破坏性变更** 与 **向后兼容** 影响（既有消费者是否需要改）。
- [ ] AC6 **逐条对照**：产出 P11 逻辑接口面（§3.1）与 D08 `AC-PAUSE/STOP/CRASH/RETRY/PROGRESS` 的对照表，
      证明新增 wire 面足以承载这些 AC，且**不发明产品行为**。
- [ ] AC7 **不越界**：除本契约文件外不改任何文件；不实现 runtime、不改 Schema/产品代码/依赖；
      不改变既有命令的既有语义（除 AC5 显式声明的破坏性变更）。
- [ ] AC8 固定 head 非作者 Review、Coordinator 集成；未完成项标 `NOT_RUN`。
