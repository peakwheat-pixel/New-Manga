## Acceptance Criteria

- [ ] **AC1 — 五入口安装与清理断言：** packaged clean-start runner 的安装文件断言包含 `sfx_detect_probe.exe`；退出检查对五个 sidecar 均断言无存活进程。新增的定向测试检查第五入口不会从任一清单遗漏；既有 `--output-dir` 防历史 raw 覆盖行为保持通过。
- [ ] **AC2 — packaged 第五入口正向与预期失败对照：** 从同一份 P03 fresh NSIS 安装包启动安装后的 `sfx_detect_probe.exe`。正向使用下列固定 K07 页面，进程 exit=0、恰有一条可解析的 `SFX_PROBE_JSON: `、`python.frozen=true`、`error=null`、检测候选数大于 0，且权重文件 SHA 与 JSON 声明的 pin 一致；记录 device / `sfx_ep` / fallback，不隐去运行时回退。失败对照使用隔离目录下保证不存在的 PNG 路径，进程 exit=1、恰有一条可解析 JSON、`python.frozen=true` 且包含错误信息。两种场景的 stdout、stderr、结构化 JSON 与退出码均保存到 P03 隔离证据目录，并由 Gate 记录为 PASS/FAIL；不能只断言 exe 文件存在。
- [ ] **AC3 — 固定 fresh 构建输入：** Owner 在自己的实现提交上确认 worktree clean，记录完整 source `HEAD`、frontend / sidecar / NSIS 构建命令、解释器/工具版本、NSIS 路径及 64 位 installer SHA-256；在写入 source/installer 指纹后才运行验收。fresh installer 是本 Task 的新产物；历史 installer、P01 结果和 Runner Debt 证据不能代替本轮验收。Packaged Gate JSON 内记录的 installer SHA 必须与同一证据组的 SHA 完全一致。
- [ ] **AC4 — 完整受影响 Gate：** 在该同一 installer SHA 上运行现有完整 M2-AC5 clean-start Gate，既有所有场景通过，AC1/AC2 第五入口场景也通过；受影响的 Runner Snapshot oracle 与 packaging 定向测试通过。每个命令有 shell、解释器、完整命令、逐项 `passed` / `skipped`、EXIT 和保存的日志；skip 单独说明原因，不把 NOT_RUN/BLOCKED 写成 PASS。
- [ ] **AC5 — 范围、数据与独立 Review：** 固定 delivery/review head；实现差量严格在允许路径内，`git diff --check` EXIT=0，`src/**`、`apps/**`、contracts、Schema、依赖与 build spec/script 零修改。非作者 DeepSeek Harness 完成固定 base/head Review 且无未解决 P0/P1；Codex 完成集成范围、installer/source 绑定、证据、集成后受影响 Gate 检查后才可置 `done`。
