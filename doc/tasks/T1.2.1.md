## Acceptance Criteria

- [x] R3-B001：一个声明了多种能力的 profile 同时绑定 `translate` 与
  `ocr` 等支持的 step 时，每次按 step/capability 解析到正确固定 slot，
  不发生最后一次 alias 覆盖；旧固定 ID 绑定保持兼容。
- [x] R3-B002：Provider mirror 保留 `proxy_policy`；`direct` 忽略命名网络，
  `profile` 使用自身命名网络且缺失/不存在时 typed fail，`inherit` 使用
  生效的 `network.profile_id`，仅在未配置时直连。缺失网络、代理失败
  不得静默直连；与既有 `ProviderNetworkResolver` 语义一致。
- [x] R3-B003：生产 bootstrap 构造的 `StdlibTransport` 能解析已保存代理
  `credential_ref`；用可控凭据仓与本地/录制 transport 验证真实装配路径，
  不写入或记录明文。缺凭据时保持 typed fail。
- [x] R3-B004：禁用的 profile 即使 ID 与固定 registry slot 相同，也不可
  解析或执行；未知 ID 同样 fail-closed。
- [x] R3-B005：`saveBinding` 拒绝 profile 未声明的 capability；运行时
  对旧/外部写入的非法绑定亦拒绝，不仅依赖 QML 过滤。
- [x] 重启后的 SQLite `pipeline_defaults` / settings mirror → 生产
  `build_provider_runtime` → registry → transport 探针覆盖以上策略、
  多能力、禁用和凭据路径；输入 mapping 不被修改，Secret 不出现在镜像、
  日志或 verification 产物。
- [x] 新 Handoff 逐条列出 AC 证据，并纠正 R3 focused/full 的
  `403 passed + 6 skipped + 1 failed` / `1117 passed + 6 skipped + 1 failed`
  口径差异；新运行需记录实际结果，不沿用旧计数。已知 torch readiness
  环境断言和逐条 OpenSSL skip 与产品回归分开归因。
