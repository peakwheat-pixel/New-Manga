# P02：真实 Workbench WebView 行为、300ms 刷新与对比度验证

## 来源与目标

来源：[权威路线 P02](../REBASELINE_PLAN.md)、P08 已确认的 D1–D7 与视觉方向 F、[React parity visual contract](../design/M2-UI1_REACT_FEATURE_PARITY_VISUAL_CONTRACT.md)、[UI/UX GUI design contract](../contracts/UI_UX_GUI_DESIGN.md) §6C、§7.2、§9，以及现有 Workbench 实现和完成的 debounce Tasks。

目标是在 Windows 上建立并运行针对当前 Workbench 的真实 Tauri WebView2 验证，记录实际鼠标/键盘输入、可见 DOM/焦点、300ms quiet-period、写后刷新和当前前景/背景颜色。证据必须区分真实 Tauri/WebView2、真实 WebView2 + mock Tauri IPC/Core、现有 JSDOM/Vitest。普通 Vite/Chrome、JSDOM、SSR、fake timers、静态源码分析和只检查 packaged runner 进程存活，均不能单独作为真实 Workbench WebView2 通过证据。

## Live 源码与基线事实

- P08、M2-RESOLVE-DEBOUNCE-1、M2-REGION-DEBOUNCE-1 已集成；验证基线为 main 241ff3b70b6fc0490ea238efd486cc707f849031。
- apps/desktop/frontend/src/App.tsx 仅在交互式生产路径显示 Console/Workbench 导航；切换视图会卸载 Workbench。
- WorkbenchPage.tsx 默认 resolveDebounceMs=300、regionDebounceMs=300；Page ID 变化时的 resolve 和 region effect read 使用 quiet-period；retype/undo/restore 写成功后直接刷新。
- WorkbenchPage.test.tsx 用 JSDOM、mock invoke 与 fake timers；写后即时刷新既有用例以 regionDebounceMs=0 运行，不是 300ms 写后刷新判别证据。
- 前端没有 Workbench WebView DOM/键盘自动化 harness。packaging/m2ac5/run_clean_start_e2e.py 会启动 Tauri/WebView2 并运行既有 probe/AC1 与生产窗口存活检查，但不操作 Workbench 控件。已有 EXE/dist 是否对应当前源码 HEAD 未核实，不能沿用旧 Hash。
- React 颜色以内联样式为主，当前没有设计契约对应的独立 token CSS/ThemeProvider。P02 只记录实际呈现并对照已选 F token，不补 token 系统或修正设计。

## Acceptance Criteria

- [ ] **AC1 真实 WebView2 harness**：从固定源码 HEAD 启动 Windows Tauri 窗口，证明交互发生于嵌入式 WebView2，而非 Vite/外部浏览器/JSDOM。记录 OS、WebView2 Runtime、源码与二进制 Hash、构建/启动命令、进程/窗口身份、隔离测试数据和驱动；标明 mock 面。
- [ ] **AC2 导航与操作**：用真实鼠标和键盘操作 Console/Workbench、Workbench 页面选择、输入、按钮和状态；记录可见结果、焦点/可访问性状态和截图。预期行为缺失时登记 finding，不在 P02 修复。
- [ ] **AC3 300ms quiet-period 与失效窗口**：真实 WebView2 连续输入/切换 page ID，分别观察 resolve_page_resource 与 list_regions；中间前缀不得提前读取；300ms 未到不得触发，到期后仅对最终 page ID 各触发一次；页面变化取消旧 timer，旧 page 迟到响应不得覆盖当前状态。记录单调时钟和可见结果。
- [ ] **AC4 写后刷新即时性**：在真实 WebView、默认 `resolveDebounceMs=300` / `regionDebounceMs=300` 下，对 retype、undo、restore 三种操作分别构造合成状态并判别写后刷新；逐项记录 write 返回与随后 `list_regions` 的次序/单调时钟，确认读回不再等待 300ms。允许 IPC/Core 使用明确标注的 mock（`REAL_WEBVIEW_MOCK_IPC`），但不得声称验证了真实 Core/SQLite 持久化。三种操作均是此 AC 的必要覆盖；任一项不能安全或可靠执行时，保留该项为 `BLOCKED` 并阻止 P02 进入 `done`，不得以 `NOT_RUN` 满足 AC4。
- [ ] **AC5 键盘与焦点**：以真实按键检查选择/输入/按钮/对话框的 Tab、Shift+Tab、Enter/Space、Escape 及焦点位置。限定于 P02 Workbench 操作面，不声称完成全应用 WCAG 审计；观察缺失只登记 finding。
- [ ] **AC6 F token/对比度**：采集真实 WebView2 代表性状态的 computed foreground/background、F token 映射状态、算法和 contrast ratio。将 `token_mapping`（`MAPPED` / `UNMAPPED` / `NOT_APPLICABLE`）与 `contrast_result`（`PASS` / `FAIL` / `NOT_VERIFIABLE`）分开记录。只要实际前景、背景及必要的合成底色可确定，就必须计算 contrast ratio；token 未映射或 CSS fallback 不得跳过计算。只有无法确定实际合成背景时，ratio 才可为 `NOT_VERIFIABLE`，并附原因。按 UI/UX GUI design contract §7.2/§9：文本至少 4.5:1，禁用文字/非文本至少 3.0:1，状态不得仅靠颜色表达。不另定阈值、不改视觉样式。React 当前无浅色主题入口时记录 `NOT_APPLICABLE`。
- [ ] **AC7 固定证据与发现处置**：逐场景记录 PASS/FAIL/BLOCKED/NOT_RUN、真实/模拟层、命令、环境、源码/二进制 Hash、退出码、时序/颜色数据、截图/日志和 skip 原因。产品缺口单独登记 finding 与建议后继路线；测试脚手架 Gate PASS 不等于产品 UI 质量 PASS。固定 head 经独立 Review、Codex 范围/验证/集成 Gate 后才可 done。
