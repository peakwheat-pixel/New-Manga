# P09-FU1：同步 legacy stub decoder 测试到真实 decoder 语义

## 来源与目标

- 来源：**P09 独立 Review 的 F2（P1，基线破坏）**——见 `verification/P09/dsh-review-r1.md` §2。
- 事实：
  - P09 让**生产装配**注入真实 decoder：`src/bootstrap/core_service.py` 第 370 行
    `image_decoder=QtImageDecoder()`（真实实现位于 `src/infrastructure/importing/importing.py` 的 `QtImageDecoder`）。
  - `src/bootstrap/core_service.py:313` 的 `_PassthroughImageDecoder` **保留**，docstring 已标注
    `Legacy test double; production assembly uses QtImageDecoder`。
  - 但 `tests/core/test_stub_decoder.py::test_production_stub_decoder_returns_valid_decoded_image`
    仍断言**生产装配**的 decoder 把非法输入 `b"fake"` 解成 `1×1` —— 该断言与 P09 之后的真实语义**直接矛盾**，
    导致仓库测试基线为红。
- 目标：把该测试同步到 P09 之后的真实语义，**恢复测试基线**；不改动任何产品实现。

## Acceptance Criteria

- [ ] AC1：`test_production_stub_decoder_returns_valid_decoded_image` 的断言与当前生产装配一致：
      生产装配注入的是 **`QtImageDecoder`**；对**合法图片字节**返回**真实 width/height**，
      对**非法字节**必须**拒绝**（抛异常或等价错误），不得再断言 `1×1`。
- [ ] AC2：`test_stub_decoder_passthrough_any_payload_does_not_raise` 按其真实定位处理：
      若 `_PassthroughImageDecoder` 仍是保留的 legacy test double，则测试可保留，但必须在 docstring 中
      明确它**只覆盖 legacy double**、**不代表生产装配语义**；若该类已不适用于当前实现，则删除该测试并说明理由。
- [ ] AC3：`python -m pytest tests/core -q` **全部通过（exit 0）**，附原始输出。
- [ ] AC4：扩大验证：`python -m pytest tests/core tests/import_formats tests/library -q` **全部通过（exit 0）**，附原始输出。
      （使用既有环境 `G:/CODEX/New Manga.task-envs/T1.1.1-impl-py312/Scripts/python.exe`，它含 PySide6 6.11.2。）
- [ ] AC5：固定 head 非作者 Review、Coordinator 集成；未跑项标 `NOT_RUN`。
