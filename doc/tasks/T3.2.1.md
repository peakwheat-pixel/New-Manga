# T3.2.1：Windows Packaging and Clean-Machine Release Gate

**Decision：PASS TO START（2026-09-22）。** 本 Gate 只释放打包工程化、发布包
验证和独立 Review 的实现范围，不代表已经生成可发布包，也不代表干净 Windows

## 来源与目标

来源：D02 §1/§13、D07 §2/§3/§81～§85/§104/§106/§111、D08
AC-PKG-001～003、AC-SMOKE、AC-OPTIONAL-001、AC-PERF-001、数据安全 Release
Gate §72～§76，以及当前代码事实：

- `src/bootstrap/app.py` 是生产入口，使用 `QML_PATH` 加载 `src/ui/qml/Main.qml`；
- 用户数据默认位于 `%LOCALAPPDATA%/New Manga`，可由 `--data-root` 覆盖；
- `requirements.txt` 锁定 Core 依赖，`requirements-dev.txt` 已锁定
  `pyinstaller==6.22.3` 与 `pyinstaller-hooks-contrib==2026.7`；
- 当前不存在生产 `packaging/**`、PyInstaller `.spec` 或发布构建脚本；
- TASK-004 仅证明最小 Qt 实验 onedir 可运行，干净 Windows E12 明确为 BLOCKED，
  不能替代本 Task 的生产包验收。

目标：生成可复现、可诊断的 Windows x64 PyInstaller onedir 包，使其在不依赖
Python、venv、源码目录或开发机 PATH 的条件下启动，并完成最小业务主流程和重启
恢复验证；所有结果绑定固定 commit、构建依赖、artifact hash、测试环境和原始日志。

## Acceptance Criteria

- [ ] **AC1 固定构建输入**：记录被测 commit、应用版本、Schema/migration 版本、
  Python/Qt/PySide6/PyInstaller 精确版本、构建命令和依赖快照；构建不读取工作区
  外的未声明文件。
- [ ] **AC2 onedir 产物**：从固定输入生成 PyInstaller onedir，产物目录结构、
  文件清单和 SHA-256 manifest 可复现；不把源码 checkout、venv、测试缓存或用户
  数据目录打进包内。
- [ ] **AC3 独立启动**：在无 Python、无项目源码、无项目 venv、无开发机 PATH
  依赖的 Windows x64 测试环境启动成功；安装/解压目录可按只读程序目录处理。
- [ ] **AC4 Qt/QML 资源闭包**：真实生产 `Main.qml`、四个一级页面、Qt DLL、
  `qwindows`/必要插件和 QML imports 均随包可用；不得出现
  `PySide6.QtCore DLL missing` 或 Qt plugin missing。
- [ ] **AC5 Core/可选依赖边界**：不安装重型可选模型时 Core/UI 仍可启动；缺失
  Provider 依赖只禁用对应能力并给出诊断，不使主程序启动失败。
- [ ] **AC6 发布包主流程**：干净 Windows 完成“解压/安装 → 启动 → 默认书架 →
  创建 Book → 创建 Chapter → 导入 Page → 工作台 → Mock/Local Pipeline → 阅读
  → 导出 → 关闭 → 再启动恢复”，并保存可复核的状态与日志。
- [ ] **AC7 数据与源文件安全**：测试过程中用户源文件 hash 不变；Managed Copy、
  Lock、current/pinned Revision、SQLite 数据和人工确认内容不被错误覆盖、删除或
  回滚；Secret 不进入 artifact、日志或诊断输出。
- [ ] **AC8 路径与退出**：Unicode Windows 路径、`%LOCALAPPDATA%` 用户数据根、
  只读程序目录和显式 `--data-root` 均有证据；关闭后无残留产品进程或 SQLite 文件锁。
- [ ] **AC9 性能与支持矩阵**：按 D07/D08 记录冷启动多次测量，至少报告 P50/P95；
  D07 的推荐硬件和 Windows 11 x64 为主验证矩阵，Windows 10 x64 作为 best effort
  单列，不以未测平台推断通过。无用户批准的性能豁免。
- [ ] **AC10 Review/集成闭环**：提供 Handoff、DeepSeek Harness 独立非作者 Review、
  固定 head 验证日志、artifact hash 和 Codex integration evidence；Review 未
  `approved` 前禁止集成；不自动发布、push 或删除历史包。

## 允许修改范围

- `packaging/**`：`.spec`、构建/manifest/资产检查脚本和最小打包入口。
- `src/bootstrap/**`：仅为 frozen resource path、用户数据路径或可诊断启动错误所需
  的最小调整；不得改业务装配语义。
- `tests/packaging/**`、`tests/core/**`、必要的 `tests/ui_shell/**`：只添加打包
  contract、资源闭包、启动/退出和数据安全守卫。
- `requirements-dev.txt`、`requirements.txt`：只有构建复现证明确需改依赖时才允许，
  且必须在 Task 中记录版本、原因和完整复验；默认不改。
- `verification/T3.2.1/**`：原始构建日志、manifest/hash、包内资产检查、开发机
  与干净 Windows 结果、主流程和性能证据。
- `doc/tasks/T3.2.1.md`、本 Task Handoff、`doc/STATUS.md`、
  `doc/REBASELINE_PLAN.md`、`doc/00_INDEX.md`、`doc/tasks/README.md`，以及本 Task
  的 implementation plan。

  由 contract test、artifact inspection 和真实 Windows 证据共同覆盖。
