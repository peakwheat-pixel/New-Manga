## Acceptance Criteria

- [ ] **AC1 固定构建输入**：记录被测 commit、应用版本、Schema/migration 版本、
  Python/Qt/PySide6/PyInstaller 精确版本、构建命令和依赖快照；构建不读取工作区
  外的未声明文件。
- [ ] **AC2 onedir 产物**：从固定输入生成 PyInstaller onedir，产物目录结构、
  文件清单和 SHA-256 manifest 可复现；不把源码 checkout、venv、测试缓存或用户
  数据目录打进包内。
- [ ] **AC3 独立启动**：在无 Python、无项目源码、无项目 venv、无开发机 PATH
  依赖的 Windows x64 测试环境启动成功；安装/解压目录可按只读程序目录处理。
- [ ] **AC4 Qt/QML 资源闭包**：真实生产 `Main.qml`、四个一级页面、Qt DLL、
  `qwindows`/必要插件和 QML imports 均随包可用；不得出现
  `PySide6.QtCore DLL missing` 或 Qt plugin missing。
- [ ] **AC5 Core/可选依赖边界**：不安装重型可选模型时 Core/UI 仍可启动；缺失
  Provider 依赖只禁用对应能力并给出诊断，不使主程序启动失败。
- [ ] **AC6 发布包主流程**：干净 Windows 完成“解压/安装 → 启动 → 默认书架 →
  创建 Book → 创建 Chapter → 导入 Page → 工作台 → Mock/Local Pipeline → 阅读
  → 导出 → 关闭 → 再启动恢复”，并保存可复核的状态与日志。
- [ ] **AC7 数据与源文件安全**：测试过程中用户源文件 hash 不变；Managed Copy、
  Lock、current/pinned Revision、SQLite 数据和人工确认内容不被错误覆盖、删除或
  回滚；Secret 不进入 artifact、日志或诊断输出。
- [ ] **AC8 路径与退出**：Unicode Windows 路径、`%LOCALAPPDATA%` 用户数据根、
  只读程序目录和显式 `--data-root` 均有证据；关闭后无残留产品进程或 SQLite 文件锁。
- [ ] **AC9 性能与支持矩阵**：按 D07/D08 记录冷启动多次测量，至少报告 P50/P95；
  D07 的推荐硬件和 Windows 11 x64 为主验证矩阵，Windows 10 x64 作为 best effort
  单列，不以未测平台推断通过。无用户批准的性能豁免。
- [ ] **AC10 Review/集成闭环**：提供 Handoff、DeepSeek Harness 独立非作者 Review、
  固定 head 验证日志、artifact hash 和 Codex integration evidence；Review 未
  `approved` 前禁止集成；不自动发布、push 或删除历史包。
