# EXPORT-REVEAL-1：导出后"打开所在文件夹"（G20）

## 来源与目标

- **来源**：设计基线 §7 **G20**（[AD-001 四页 UI/UX 设计基线](../design/AD001_FOUR_PAGE_UI_BASELINE.md)）：
  「导出后『打开所在文件夹』」——§10.3 **明文要求**必须经**独立 host command**、按**不透明 export_id** 操作；
  既有 `GetExportHistory` 的 `output_path` **仅 host 可见**，host 不向 WebView 转发路径。
- **Coordinator 只读复核确认缺口真实（2026-10-16）**：
  - `apps/desktop/src-tauri/src/main.rs:902` 只注册了 `tauri_plugin_dialog`；
    `Cargo.toml` 仅有 `tauri-plugin-dialog = "2"`（**无** opener/shell 插件）；
  - Rust 源码中 `explorer|reveal|show_in_folder|open_folder` **0 次命中**；
  - 生产命令表（`command_allowlist`）中**没有**任何打开目录的命令。
- **目标**：冻结并实现一个**按不透明 `export_id`** 打开导出输出所在文件夹的 host 命令，
  使 P17（阅读/导出 UI）具备完整的导出后体验。
- **边界**：本 Task **只**做"打开所在文件夹"这一件事；导出本身的契约与实现（`StartExport`/`ExportTargetRef`/`GetExportHistory`）**已完成且只读**。

## 依赖、风险与阻塞

- `depends_on` 均已 `done`（导出契约与 host 选择器已具备）。
- 风险一：**无头/沙箱环境无法真实弹出资源管理器** → 不得因此伪造"已打开"；应给出分层证据
  （命令存在性 + 拒绝面 + 解析正确性）并如实标注端到端 `NOT_RUN`/`BLOCKED`。
- 风险二：**打开动作的注入风险**——`export_id` 必须经 Core 可信解析，禁止拼接 shell 命令或用未校验路径调用系统 API。
- 风险三：新增官方插件会触及 capabilities/manifest → 必须四处同步并证明 probe/AC1 面形状不变。
- 阻塞条件：若 §10.3 要求的信息（按 export_id 解析输出目录）在 Core 侧**没有可用来源** → 如实 `BLOCKED`
  + 原始证据，交 Coordinator 裁决（可能需要 Core 侧小改动作为独立 Task）。
