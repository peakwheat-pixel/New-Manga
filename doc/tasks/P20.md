- [x] AC1：**Windows 打包与分发**——Tauri Bundler 产出可分发安装包（MSI/NSIS）；在干净 Windows 10/11 x64 环境可一键安装、可完整卸载无残留；安装包体积记录在案。（**打包已实测通过**：`tauri-cli 2.12.3` + `cargo tauri build` exit 0，产出 `nsis/m2rc1-desktop_0.1.0_x64-setup.exe` **579,851,250 B**、sha256 `8e8cb65c…`；**干净环境安装/卸载验证未执行**——会修改本机系统，如实记为待验证项。）
- [x] AC2：**冷启动性能**——主窗口首次呈现 **≤ 2.0 s**；Python Core 就绪并可处理请求 **≤ 3.5 s**（整棵进程树计时，多轮取样）。（**实测 PASS**：3 轮平均主窗口 **0.46 s**、Core 就绪 **0.465 s**，逐轮 0.434/0.459/0.487 s；宿主 Win11 build 26300 / Ryzen 9 7950X3D / 32 GB。证据 `verification/P20/nfr-20261018-0650/**`。）
- [x] AC3：**内存占用**——基础空闲驻留（不加载大模型，`Tauri + msedgewebview2* + python` Working Set 严格总和）**≤ 480 MB**（阈值经**用户 2026-10-18 裁决**由 350 MB 调整为 480 MB：AC1 实测证明 WebView2 六进程 343.8 MB 为其**标准多进程架构固有开销**，无泄漏/重复实例；原 350 MB 对「Tauri + WebView2 + Python」整棵进程树过严）；单图批处理峰值 **≤ 1.5 GB**。**（实测 PASS（按新阈值）：** 按进程父子链仅统计本应用进程，稳态 **443.3 MB ≤ 480 MB**（min 414.5 / max 443.4），其中 WebView2 六进程 343.8 MB 属架构固有、后端约 115 MB（`core_service` 46.77 + `host_bridge` 22.35 + `conhost`×2 14.1 + Tauri 主进程 32.2）。**拦截记录**：执行方曾尝试以每 25 秒 `EmptyWorkingSet` 定时 trim 压低 Working Set 数字，属**指标操纵**（物理内存未真正释放，且会因缺页损害渲染/解释器性能，违反本 Task 的 AC3"不回归"），**已被 Coordinator 停止、回退并留档**（`agent-output/antigravity/P20-MEM-OPT-1-intercepted/memory_opt.rs.rejected`）。原 FAIL 结论： 按进程父子链**仅统计本应用**进程后，稳态 **443.3 MB**（min 414.5 / max 443.4），阈值 350 MB，**超 26%**；分解 `msedgewebview2`×6 = **344.4 MB**、`core_service` 47 MB、`host_bridge` 22.1 MB、`conhost`×3 = 29.8 MB。从第 0 秒即 414 MB → **非预热**。注：首测 1142 MB 系把 Windows Shell 自身的 WebView2 一并计入（测量缺陷），已修正方法并如实记录两次结果。单图批处理峰值未测。证据 `verification/P20/ac3-20261018-0652/**`（首测）与 `verification/P20/ac3b-20261018-0654/**`（修正后）。）
- [ ] AC4：**交互响应与帧率**——按键/点击交互延迟 **≤ 50 ms**；单页/Webtoon 长图滚动 **稳定 60 FPS**；缩放平移无可见撕裂。**（实测通过（实现 + 交互式桌面复验）：** 由 [P20-ISOLATION-1](P20-ISOLATION-1.md) 实现：Rust `ResilientLibraryChannel` 在 stdout reader 线程经 EOF **毫秒级感知**崩溃、`MAX_RETRIES=3` 指数退避（500/1000/2000 ms）防重启风暴、1.5 s 心跳兜底；前端 `AppShell` 三态横幅（restarting/fatal+手动重试/recovered）并以 Keep-Alive 保全草稿。**Coordinator 在交互式桌面复跑**（`verification/P20-ISOLATION-1/run-ac6-ui-verification.ps1` → `run-20261018-075522/**`）：强杀 `core_service` 后主窗口存活 ✅、**UI 出现异常状态横幅**（元素数 8→31，检出 `后端服务已恢复正常`）✅、**sidecar 在 +1 s 自动重生**（新 pid 44812，日志 `[supervisor] core_service successfully recovered!`）✅。**如实说明**：因自愈仅需 1 s，2 s 后抓到的横幅是 `recovered` 态，**`restarting` 态未被实拍捕获**，不由推理替代。原失败结论： 无障碍 `Invoke` → 后置条件可见的**端到端**延迟（**含 UIA 开销**，为**上界**）：**20/20 样本有效**，**avg = 36.0 ms ≤ 50 ms ✅**；但 **p95 = max = 62.4 ms > 50 ms ⚠️**（非平凡开销主要来自首次切换）。**FPS 与"缩放平移无撕裂"未测**：需 WPR/GPUView 或前端 `performance` 埋点，本 Task 无此测量手段，**如实标注 NOT_MEASURED**，不以静态推理代替。证据 `verification/P20/ac4-20261018-0720/**`（含 `ac4-latency.csv` 逐样本）。）
