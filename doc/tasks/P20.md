### 为什么不能声称「DWM 下撕裂不可能」

r32 明确否掉了这个便利的推理：

> **DWM 会降低常见窗口路径的撕裂风险，但不能证明所有呈现路径都不可能撕裂。**
> 微软文档说明了窗口化 flip、Independent Flip 与 tearing/VRR 呈现路径。

即：现代 Windows 的合成路径确实让撕裂在**典型窗口化场景**下极罕见，
但**存在绕过合成的呈现路径**（例如 Independent Flip / 直接 flip 到显示器、
以及 VRR 下的 tearing 呈现），这些路径上撕裂不是理论上的不可能。

**所以 limitation 的措辞必须是「未观察」，不是「已证明不可能」。**

### 本轮未能观察的原因（r32 的归因）

r32 把本轮的三次失败归为 **Agent 桌面工具 / 会话链路未建立**，
**不足以认定执行者做错**。

记录在 `verification/P20/ac4-tearing-attempt.md`：
`Start-Process` 超时后 job 回收带走应用；CUA `get_desktop_state` 只截到
Edge 的抖音页面，`list_windows` / `launch_app` 反复报
`this session has ended`；枚举窗口确认当时无 `m2rc1-desktop` 进程。

### AC4 为什么保持未勾选

AC4 含四项子要求，**前三项已实测 MET，第四项从未被观察**：

| **缩放平移无撕裂** | **未观察** | 人工观察 | **`LIMITATION`** |

**16.681 ms ≈ 59.9 FPS；17.527 ms ≈ 57.1 FPS。**
证据：`verification/P20-AC4-FPS-1/ac3-real-desktop/`。

**撕裂维持未观察的理由**（Codex r32 裁定）：
- **不允许**以「DWM 合成使撕裂不可能」推断通过——
  r32 指出微软文档记载了窗口化 flip、Independent Flip 与 tearing/VRR 呈现路径，
  **常见路径罕见不等于所有路径不可能**；
- 本轮**三次尝试均未能让应用窗口出现在前台**
  （`Start-Process` 超时后 job 回收带走进程；CUA `get_desktop_state` 只截到其它应用；
  `list_windows`/`launch_app` 反复报 `session has ended`）；
- 因此**不能声称「已验证无撕裂」，也不能声称「观察到撕裂」**。
