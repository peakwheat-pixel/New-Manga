# GOV-DEBT-CLEANUP-1：治理债务清理（历史 pin 失效与未入库证据）
## 背景（由 Coordinator 于 2026-10-18 实测登记）

用户 2026-10-18 裁决：**另立 Task 彻底清理**治理债务。此前 Coordinator 对 `doc/tasks/P*.md` **逐个**执行
`pwsh -NoProfile -File tools/governance/check.ps1 -TaskPath doc/tasks/<X>.md`，发现 **41 个历史 Task** 校验失败，
失败类型集中在四类：

1. **Evidence SHA-256 不匹配**（数量最多）：如 `doc/contracts/M2-C1_TYPED_IPC_CONTRACT.md`（P09-FU2、P12-C1、P13-C1、
   P15-C1、P16、P16-C1 等多处引用）、`apps/desktop/src-tauri/src/library_bridge.rs`（P22-REBASE-1）、
   `apps/desktop/frontend/src/settings/SettingsPage.test.tsx`、`src/bootstrap/core_service.py`。
   根因：**源文件在该 Task 关闭后被后续合法变更修改**，当时的 pin 是正确的，只是**时效已过**。
2. **当前 DAG 未登记非终态 Task**：如 P02-NEW-TIME-X6 系列、P02PRE 系列、P15-CORE-1、P19-AC3-1、P19-UI-FIX-3。
3. **失效的本地引用**：如 `doc/tasks/P19-BOOT-1.md`、`P15-CORE-1A/1B`、`P22.md` 使用 `../` 相对路径，从
   `doc/tasks/` 出发无法解析。
4. **Resource manifest 不存在**：如 P12、P15-C1-FU2 指向不存在的 `resource-manifest.json`。

另有 `verification/` 下 **1,185 个未跟踪文件**（经 Coordinator 实测，分布以 `P02*` 家族为主：P02 1072、
P02-NEW-TIME-BASELINE 33、P04 36、P03-PACKAGED-SFX-ENTRY 11、P19 9，其余零散），需逐项分类处置。

**注**：本 Task 是**低优先级治理工作**，不阻塞 P20 发布；其存在是为了让未来的审计者不再重复遇到同一困惑。

## 验收标准

- [ ] AC1：**未入库证据分类清单（逐项）**——对 `verification/**` 下全部未跟踪文件逐项给出判定：
      ① 被当前 READY/在飞 Task、Canonical Evidence pin、机制文档或脚本引用 → **保留**（记录引用来源）；
      ② 无引用但具独立证据价值（原始运行日志、截图、DB 快照等）→ **入库**（说明为何有保存价值）；
      ③ 无引用且可再生产（脚本可一键重跑）或纯临时产物 → **可清理**（须指明再生产脚本）。
      清单必须**逐文件**（可用表格 + 分组计数），不得只给汇总数字。
- [ ] AC2：**41 个失败 Task 根因清单（逐项）**——对每个失败 Task 记录：失败类型、涉及文件、根因分类
      （源文件后续合法变更 / DAG 未登记 / 路径写法 / 缺 Manifest）、以及**不破坏可追溯性**的处置建议。
- [ ] AC3：**执行 AC1/AC2 的判定动作**，且**严禁改写历史证据**：

      ② 若需标注失效，只能**追加**说明（例如"该 pin 自 `xxx` 提交起失效，因源文件被后续合法变更修改"）；
      ③ 清理只允许删除**已证明无引用且可再生产**的文件，删除前逐项留证。

- [ ] AC5：**用户数据与用户未提交内容零触碰**——不得移动/删除/改写任何 `tracked dirty` 文件（43 项）；
