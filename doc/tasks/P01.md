# P01：台账元数据与Review载体取证

## 来源与目标

来源为 [Project Rebaseline Plan](../REBASELINE_PLAN.md) 的 P01。对四个历史 Task 的 commit 字段、集成证据和独立 Review 载体做只读取证；只在 Git 对象与集成证据足以证明时修正 P01 允许的元数据字段。缺失证据必须如实记录为 `NOT_VERIFIED`，不得依据正文叙述、台账短 hash、作者自述或 Review 引用代造批准。

## Acceptance Criteria

- [ ] **AC1 — 固定检查点**：从本 Task 的 `base_commit` 和指定 worktree 恢复；记录实际 branch、HEAD、dirty 集合与 common-dir。root checkout 中已存在的用户/Qoder/Agent dirty 与 untracked 不得改动。
- [ ] **AC2 — GC2 元数据**：检查 `doc/tasks/M2-DERIVED-GC-2.md` 的 `integration_commit: null`、正文/Plan 的 `cea610ed`、候选完整对象 `cea610ed3f3349f1d76361d151815445e991f7d7`、祖先关系和集成证据。仅在交付/集成证据吻合时把 frontmatter 字段更正为完整 commit SHA；否则保持原值并记录 `NOT_VERIFIED`。
- [ ] **AC3 — DETECT3 元数据**：核验当前 frontmatter SHA `8fe5199c44b06e679a2f0e6ee47767032217eb47` 是否为有效对象；独立核验候选 `8fe5199c6d05d144052141ad02ed054bbaa90645` 的对象、祖先关系、Handoff/集成证据。只在证据吻合时修正该字段；不得只因 inventory 值不同就覆盖。
- [ ] **AC4 — ANNOTATE-R2 Review 载体**：追踪 Task、Handoff、提交和版本化 `doc/reviews/` 报告；记录每个可定位载体的 base/head/decision/hash。找不到独立报告则记录 `NOT_VERIFIED`，不得将 Owner 数据报告或 Task 内的文字当作独立 Review。
- [ ] **AC5 — SYNTH Review / 状态冲突**：追踪真实独立 Review 载体及 fixed head；逐项记录重复 `integration_commit` 与 `status: in_review` 的来源。若集成证据证明重复字段之一陈旧，可只修正该字段；不得因修正 commit 元数据而把来源 Task 标成 `done`；没有可核验载体的结论记 `NOT_VERIFIED`。
- [ ] **AC6 — 产品裁决保护**：记录但不裁决 ANNOTATE-R2 的 challenge 空集与 T2 是否释放；不得更改这两项用户裁决。不得修改 SYNTH 的登录/人工冒烟要求或冒充已完成。
- [ ] **AC7 — 交付 Gate**：版本化 P01 证据与 Handoff；将固定最终 head 派给 DeepSeek Harness 做非作者 Review；Codex 按 `base_commit..reviewed_head` 核实 allowed paths、commit/报告指纹、`git diff --check`、无越界和本 Task 各 AC。只读证据不足项可保持 `NOT_VERIFIED`，但不能改写来源 Task 的状态或 Review 结论。
