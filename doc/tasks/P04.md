# P04：生产命令族与同通道桥接并发定向验证

## 来源与目标

来源为 [REBASELINE_PLAN 的 P04 路线项](../REBASELINE_PLAN.md)；PAGE-NAV 依赖 `M2-PAGE-NAV-PROJECTION-1` 已集成。代码证据静态核验基于 `main@88579622d85ff6d0dfd509c6f21931bd91d0881b`。

可观察目标：直接固定 `PAGE_NAV_PRODUCTION_ONLY_COMMANDS` 的精确成员，并以可控 sidecar 诊断 `StdioLibraryChannel` 同一实例上的并发请求/响应归属及现有协议字段。当前观察到 `main.rs` 已固定整张 15 项生产命令面，并在 probe/AC1 上扫过生产专属组；但该组常量缺少自身的精确成员断言，等长误替换可能漏过现有检查。`library_bridge.rs` 的 `round_trip` 分别锁 stdin 与 stdout，尚未核验并发调用下响应是否仍归属正确调用方；这是待复现风险，不是已确认缺陷。

协议核验以 [M2-C1 Typed IPC Contract §3–4](../contracts/M2-C1_TYPED_IPC_CONTRACT.md) 与当前 Core sidecar 的实际响应为证据；仅记录当前实现，不借本 Task 冻结新的产品协议语义。

## Acceptance Criteria

- [ ] AC1：Rust 测试精确断言 `PAGE_NAV_PRODUCTION_ONLY_COMMANDS` 恰为 `list_chapters`、`list_chapter_pages`，无重复；并确认两项仍在生产面且不出现在 probe/AC1 面。测试应能捕获常量被等长错误替换的情况。
- [ ] AC2：使用确定性同步的测试 sidecar，在同一 `StdioLibraryChannel` 实例上并发发起至少两条可区分的 `round_trip`，核对每个调用方拿到的结果/错误与对应请求一致，并记录请求/响应的 protocol、version、request_id 字段。不得只依赖 sleeps 或概率性压力循环；不新增生产协议校验逻辑。
- [ ] AC3：若 AC2 复现响应错配或其他缺陷，保留最小复现证据、逐项记录实际与预期，并由 Codex 拆成独立修复 Task；本 Task 不修改生产行为。若现有测试无法在不改生产行为的条件下确定性构造场景，则如实记录 BLOCKED，并另立测试 seam Task，不降低 AC。
- [ ] AC4：DeepSeek Harness 对固定交付 head 作非作者独立 Review；修订后复审；Codex 仅在 Review 与测试 Gate 满足后集成，并在集成后按本 Task 再跑可运行的定向验证。
