# P04：生产命令族与同通道桥接并发定向验证

## 来源与目标

来源为 [REBASELINE_PLAN 的 P04 路线项](../REBASELINE_PLAN.md)；PAGE-NAV 依赖 `M2-PAGE-NAV-PROJECTION-1` 已集成。代码证据静态核验基于 `main@88579622d85ff6d0dfd509c6f21931bd91d0881b`。

可观察目标：直接固定 `PAGE_NAV_PRODUCTION_ONLY_COMMANDS` 的精确成员，并以可控 sidecar 诊断 `StdioLibraryChannel` 同一实例上的并发请求/响应归属及现有协议字段。当前观察到 `main.rs` 已固定整张 15 项生产命令面，并在 probe/AC1 上扫过生产专属组；但该组常量缺少自身的精确成员断言，等长误替换可能漏过现有检查。`library_bridge.rs` 的 `round_trip` 分别锁 stdin 与 stdout，尚未核验并发调用下响应是否仍归属正确调用方；这是待复现风险，不是已确认缺陷。

协议核验以 [M2-C1 Typed IPC Contract §3–4](../contracts/M2-C1_TYPED_IPC_CONTRACT.md) 与当前 Core sidecar 的实际响应为证据；仅记录当前实现，不借本 Task 冻结新的产品协议语义。

## Acceptance Criteria

- [ ] AC1：测试必须执行字面断言 `assert_eq!(PAGE_NAV_PRODUCTION_ONLY_COMMANDS, &["list_chapters", "list_chapter_pages"]);`，不得从该常量自身派生期望；同时确认这两个字面命令仍在生产面且不出现在 probe/M2-AC1 面。
- [ ] AC2：使用确定性同步的测试 sidecar（`M2RC1_PYTHON` 路径与版本须来自 P02 批准环境并记录到证据），在同一 `StdioLibraryChannel` 实例上并发发起至少两条可区分的 `round_trip`，得到可复现的响应归属结论。只有每个调用方均拿到其对应结果/错误时记录行为 `PASS`；若响应错配，记录行为 `FAIL`、精确请求和回包，并按 AC3 阻断本 Task。不得只依赖 sleeps 或概率性压力循环；不新增生产协议校验逻辑。请求/响应 `protocol`、`version`、`request_id` 只在 sidecar 边界旁录到 `verification/P04/**`，该记录本身不代表 PASS，也不冻结合同中的 PROPOSAL 语义。
- [ ] AC3：若 AC2 复现响应错配或其他缺陷，只把最小复现与 sidecar 记录写入 `verification/P04/**`，不提交会失败的测试或修改生产行为；P04 置为 `blocked`（previous=`in_progress`）。Codex 建立独立修复 Task，明确其不依赖 P04=`done`，避免依赖环。修复 Task 集成后恢复 P04，补入/启用回归测试并复跑 AC2；修复和复测完成前不得把 P04 标为 done。若不能在不改生产行为的条件下确定性构造场景，则 P04 同样保持 blocked，由 Codex 另立测试 seam Task。
