## Acceptance Criteria

- [ ] AC1 **质量口径缺失清单（逐项，禁止编造）**：从既有报告逐项列出**检测 / OCR 真值 / 翻译相似度评测方式 /
      无字页 F4 / 复杂背景修复标准**的缺失项；每条须给出既有来源与缺口描述。
      **不得**编造统一的"90% 通过率"；**不得**把 BJ13 `0.90`（检测阈值）当作整体产品质量分数。
- [ ] AC2 **JA / KO 分别的实验方案**：为 JA 与 KO **分别**定义样本集、真值来源、阈值及其来源、
      以及 `version / device / model / endpoint` 的责任归属与记录方式（对齐 DOC 的 AC4 证据责任）。
- [ ] AC3 **逐步 terminal 一致性判别方案**：定义每个 pipeline step 的终止状态与产物如何被判定为一致，
      明确 **`export OK` 不能替代 terminal 状态一致性**；给出判别所需的记录字段与失败判定。
- [ ] AC4 **素材许可与指纹**：复用**已允许**素材与许可，**不重新获取 Manga109**；对使用到的素材记录来源、
      许可证据与 SHA-256（对齐 `doc/WORKSPACE_GOVERNANCE.md` 的 registry 要求）。
- [ ] AC5 **最小真实实验切片**：执行 JA 与 KO 各至少一条端到端链路（导入 → 检测/OCR → 翻译 → 修复 → 渲染 →
      终止状态），归档**原始**日志、退出码与逐步 terminal 证据；规模可最小，但必须**真实运行**、不得以静态分析代替。
      若因模型/素材/环境缺失无法执行，**标 `BLOCKED` 并给出原始失败证据**，不得伪造。
- [ ] AC6 **不越界**：**不修改任何产品实现**（`src/**`、`apps/**`、`packaging/**`）；
      **生产修复须另立 Task**；不新增第三方依赖；不改 Schema。
- [ ] AC7 **可复核性**：所有阈值、真值与结论必须可由第三方用归档素材与命令复算；不得只给结论不给证据路径。
- [ ] AC8 固定 head 非作者 Review、Coordinator 集成；未跑项标 `NOT_RUN` / `BLOCKED`。
