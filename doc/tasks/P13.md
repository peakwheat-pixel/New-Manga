## Acceptance Criteria

- [x] AC1 **Durable acceptance 与幂等**（P11 §2、§3）：`StartRun` 使用持久**幂等键**；同键同请求返回原 Run，
      同键不同 fingerprint **拒绝**；只有 Run + 目标集 + 执行快照**原子提交**后才算「已接受」。
- [x] AC2 **快照与目标冻结**（P11 §2.3、§3.2–§3.3）：接受时冻结命令类型、目标成员与顺序、settings / Provider / context；
      接受后不得重新解析或扩大目标集。
- [x] AC3 **唯一 scheduler 与所有权**（P11 §7.1）：同一时刻只有一个 scheduler owner 消费并推进持久化 Run；
      **MUST NOT** 造第二 scheduler、第二 task store、影子队列，或绕过 `PipelineStore` 直接更新 Run；
      工作线程与 SQLite 连接所有权必须明确且可验证。
- [x] AC4 **控制转换 + 4 项缺口修正**（P11 §4.2/§4.5，缺口见 P11 Review §8；**破坏性变更**）：
      **(a)** `Pending` 上的 `pause` 必须**拒绝**（当前 `control_run` 允许并直接置 `PAUSED`）；
      **(b)** `Blocked` 上的 `stop` 必须到达 `Cancelled` 终态（当前只写 `cancel_requested` 后卡住）；
      **(c)** `restart` 必须**原子**记录 `interruption_disposition` 与 child Run 来源（当前两次 persist）；
      **(d)** 失败目标重试必须有**状态门**（仅 `CompletedWithFailures` 可 `RetryFailedTargets`）。
      另需覆盖 P11 §4.5 的完整非法转换拒绝清单。
- [x] AC5 **失败与重试**（P11 §5）：网络自动重试最多额外 2 次、退避 1s/2s、遵守 `Retry-After`；
      `Authentication`/`InvalidInput`/`MissingCredential`/Lock 与人工保护冲突**不得**自动重试。
- [x] AC6 **启动恢复**（P11 §6）：启动只把此前 `Running` 的 Run 标 `Interrupted`；`Continue`/`Restart`/`Abandon`
      语义分离；只重放未安全提交的工作；不得把未提交临时产物晋升为 current。
- [x] AC7 **TaskProgress 权威投影**（P11 §7.2–§7.3）：提供只读投影（Run 状态、进度、当前 Page/Step、
      完成/失败/跳过/阻塞统计与原因、错误与 retry 元数据、按状态可用的 controls）；与 PageList **同源**；
      普通更新约 4 Hz、重要状态事件立即。
- [x] AC8 **范围锁定**：不改变 D04 / D08 产品语义；**不新增第二 scheduler**；**不修改冻结 IPC 契约**
      `doc/contracts/M2-C1_TYPED_IPC_CONTRACT.md`；**不做 P14 UI**；不新增第三方依赖。
- [x] AC9 固定 owner head、写 Handoff、提交固定 commit；未跑项标 `NOT_RUN` / `BLOCKED`，不得以总测试数替代逐项证据。
