# T3.2.1-REPAIR-17：无重型权重的确定性 Mock/Local Pipeline 烟测

状态：**proposed / NOT_RELEASED**。本 Task 只登记 AC6 的后续缺口，未释放实现。

## 来源与 Codex 裁决

R-003：固定包在无 Provider 配置时产生
completed_with_failures / PROVIDER_NOT_CONFIGURED。这证明缺依赖时 fail-closed
诊断及错误状态持久化，支撑 AC5；未证明 AC-SMOKE 所需的成功 Mock/Local
Pipeline 结果，因此 AC6 继续 PARTIAL（11/12）。

## 目标

为打包后的主流程提供不下载重型权重、可重复的成功 Mock/Local Pipeline 烟测，
验证 Pipeline 执行、结果保存、Reader 查看与导出路径。默认生产 Provider 行为仍须
fail-closed；mock 能力必须限制在显式测试配置中，不得冒充真实 docTR 权重成功或模型质量。

## 建议验收标准（释放时冻结）

- AC1：从隔离 fixture 启动固定 onedir 包，使用明确标识的 deterministic Mock/Local 测试配置，至少一个 Pipeline run 正常成功并留下可复核产物。
- AC2：保存、重启恢复、Reader 查看与 ZIP 导出都在同一隔离数据根完成；源文件 hash 不变，Lock、Revision 和人工确认数据未被错误改动。
- AC3：产品默认 Provider 未配置时仍 fail-closed；测试通路无法由普通发布启动参数无意开启。
- AC4：交付固定 head、测试代码、原始日志、manifest/hash、Handoff；DeepSeek Harness 独立 Review 与 Codex 集成后复验通过。
