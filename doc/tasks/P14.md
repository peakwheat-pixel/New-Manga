## 依赖、风险与阻塞

- `depends_on`：UI-DESIGN-1（done）、P12（done，Shell/书架）、**RUN-IPC-1（done）**、**EXPORT-IPC-1（本 Task 的释放前置）**、EVENTS-FWD-1（done）、P13（Run 运行时，done）、P16（Reader/Export Core，done）。
- 风险一：**把 Run 发现/G15 误当已就绪**（见上文关键区分）——那是本页最容易犯的错。
- 风险二：把禁用入口做成"看起来能用但点了没反应"——必须有可理解的禁用原因。
- 风险三：用事件 payload 直接驱动 UI 状态（跳过快照重查）——违反 §6.4 与 P11 §7.1/§7.3。
- 阻塞条件：若实现中发现某 W 绑定在 host 侧**仍不可达**（应已由前置 Task 关闭）→ 立刻 `BLOCKED` + 证据，交 Coordinator；**不得**自行绕道或发明 wire。
- 工具约束（Coordinator 实测）：本仓 **ZCode 的 headless CLI 拒绝所有 shell 命令**（`No permission client configured for Bash`）→ 若由 ZCode 承担 Owner，则 `npm test` / `npm run build` / `git commit` **无法执行**，AC5 证据与交付无法完成；此时应改派 **codex / antigravity**（或由 Coordinator 兼任 Owner）。派发前必须确认 Owner 能执行命令。
