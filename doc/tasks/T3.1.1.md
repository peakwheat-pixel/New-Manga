## 来源与目标

来源：D03 §29 `ReadingProgress`、D03 §31 `ExportHistory`、D08
`AC-READ-002`/`AC-EXPORT-002`、REBASELINE_PLAN T3.1.1，以及当前代码证据：

- `src/application/reading/ports.py` 的 `JsonProgressDocumentStore`；
- `src/application/export/ports.py` 的 `JsonHistoryDocumentStore`；
- `src/application/reading/service.py` 的 `ReadingProgress` 全字段与
  `(book_id, chapter_id, mode)` 语义；
- `src/application/export/service.py` 的 `ExportRecord` 全字段、repeat 依赖的
  `scope_snapshot_json` 与 `render_profile_snapshot_json`；
- `src/bootstrap/app.py` 当前以 `reading_progress.json` 和 `export_history.json`
  装配生产服务；
- `src/infrastructure/sqlite/schema.py` 当前最高 Schema 为 v3。

目标：在现有 SQLite 数据库中新增最小 v4 持久化面，使阅读进度和导出历史在重启
后可恢复、事务失败可回滚，并对现有 JSON 做一次安全导入；导入后 SQLite 是唯一
生产写入真值，遗留 JSON 保留为只读恢复材料。

## 冻结的实现边界

- 复用现有 `ProgressDocumentStore` / `HistoryDocumentStore` 的应用层调用形状，
  优先新增 SQLite adapter，避免无必要地改写 `ReadingService`、`ExportService`
  的业务语义。
- 新增一个位于 v3 之后的 additive migration。不得编辑 v1/v2/v3 SQL；迁移必须
  复用现有 `MigrationRunner` 的 checksum、事务、新 Schema 拒绝和迁移前备份语义。
- ReadingProgress 至少完整保存 `progress_id`、`book_id`、`chapter_id`、`mode`、
  `last_page_id`、两个 scroll offset、`progress_percent`、`last_read_at`、
  `total_read_seconds`、`updated_at`，并保持 Original/Translated 与 Webtoon
  offset 独立。
- ExportHistory 至少完整保存 `ExportRecord` 的全部字段，包括 repeat 所需的两个
  JSON snapshot 和失败/取消的 `detail`；SQLite 中 JSON 仍以文本快照保存，不写入
  凭据或文件二进制。
- 遗留 JSON 只导入一次：缺失文件视为空；合法文件在一个受控事务中导入；已有但
  损坏或结构非法的文件不得删除、覆盖或静默标记为成功，必须保留原文件并给出
  可诊断失败。导入标记使用现有 metadata 能力或等价的最小 Schema v4 机制，必须
  防止重启重复导入。
- 导入成功后不得再写两个 JSON 文件；原文件保留且内容/mtime 不应被生产写路径
  改写。数据库写入必须是短事务，失败时既不留下半行数据，也不破坏遗留文件。
- Bootstrap 必须把同一生产 SQLite 数据库接入两个 adapter；测试必须走真实生产
  装配路径，不能只证明独立 fake 可用。

## Acceptance Criteria

- [ ] **AC1 Schema/迁移**：v3→v4 和空库 v4 均可迁移；迁移前备份、checksum、
  单迁移事务、失败回滚及旧程序面对新 Schema 的拒绝行为均有证据；v1/v2/v3
  migration 文本无修改。
- [ ] **AC2 ReadingProgress**：所有字段 round-trip；同一
  `(book_id, chapter_id, mode)` 不产生重复行；Original/Translated、Webtoon
  `last_page_id`/`scroll_offset_y`、阅读时长与重启恢复均有测试。
- [ ] **AC3 ExportHistory**：所有字段 round-trip；completed/skipped/cancelled/
  failed 记录、最新优先历史、repeat 使用原 snapshot、非法/缺失 JSON 不破坏既有
  记录均有测试。
- [ ] **AC4 遗留导入**：合法 progress/history JSON 各只导入一次；导入后重启不重复；
  缺失、损坏、错误顶层结构和单行非法数据的行为可诊断；遗留文件不被删除或覆盖。
- [ ] **AC5 生产装配**：`assemble_services`/`assemble_engine` 使用 SQLite adapter；
  生产路径不再把两个 JSON store 作为写入真值；现有 Reader/Workbench 行为测试
  仍通过。
- [ ] **AC6 原子性与数据安全**：注入 DB 写入失败、导入失败、重启和并发/锁冲突时，
  不丢已有数据库行、不破坏遗留 JSON、不写用户源文件、Managed Copy、Lock、
  current/pinned Revision 或 Pipeline schema。
- [ ] **AC7 范围与证据**：无新增依赖；无 QML/UI、Provider、Pipeline graph、
  backup UI 或打包改动；提供 Handoff、DeepSeek Harness 独立 Review、固定 head
  验证日志和 Codex integration evidence。
