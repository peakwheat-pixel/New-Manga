# M2-P1 — Regionless Detection Fan-out and Guard Rebinding

## 目标

修复 [DIAG-M2-REGIONLESS-LOCK-CHANGED-001](DIAG-M2-REGIONLESS-LOCK-CHANGED-001.md) 定位的 regionless 缺陷：`_backfill_detected_regions` 在 detect 提交后只重绑 `PlanUnit.region_id`、未重绑 `target_id`，导致后续 `ocr` 步骤的 `StepRun.input_refs` 冻结自 Page target（无 `region` 键 ⇒ `None`），`RegionStepWriter._persist`（`src/infrastructure/providers/step_writes.py:219-231`）以 `None` 比对 Region 真实 current revision，抛 `LockBlocked`（`error_code="LOCK_CHANGED"`）。

修复语义（来自[诊断报告](../research/DIAG-M2-REGIONLESS-LOCK-CHANGED-001.md) §5.1，为权威依据）：

1. **不变式**：`PlanUnit.target_id ≡ 该步骤的写目标`（Region 步骤 ⇒ Region id；Page 步骤 ⇒ Page id）。
2. **唯一修复点**：`src/application/tasks/service.py` 的 `_backfill_detected_regions`（base 上 L921-946）。对仍 regionless 的后续 unit 同时 `replace(item, region_id=primary, target_id=primary)`，时机在 detect 提交成功之后、`_record_step_attempt(ocr)` 之前（现状时序已满足，函数被 `commit_step_result` 在 backfill 时机调用）。
3. **不改 `unit_id`**：`unit_id` 是 `run.terminal_unit_ids` 的键且 plan 阶段已标记终态；改动会丢终态或双计。`unit_id` 内嵌 page id 与真实 target 不一致是已知展示层债务，本 Task 记录不修。
4. **不得扩大范围**：多 Region 页面只绑 `region_ids[0]`（primary）的既有语义保持——非 primary Region 停在 `NOT_STARTED`，`outputs["region_ids"]` 全量保留审计；fan-out 调度属后续切片，禁止混入。半修（只改 snapshot 来源不改 target_id）会把 `LOCK_CHANGED` 变成 `TARGET_NOT_FOUND`，负向测试 N1 必须固定该判别。
