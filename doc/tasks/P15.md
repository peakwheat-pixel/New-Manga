## Acceptance Criteria

- [ ] **AC1 布局与分类（设计 §5.2）**：Nav Rail 64px + SettingsCategoryNav 200px 固定 + SettingsContentPanel；**十二分类顺序固定**（Provider、网络/代理、OCR、翻译、图片修复、排版样式、模型/GPU、任务/并发、缓存/Revision、回收站、备份/恢复、Plugin/Hooks）；分类切换为 React 本地状态，**无子路由**。
- [ ] **AC2 可编辑范围（核心）**：**仅**实现 **P15-C1「可编辑分区清单」**中列出的节（释放本 Task 时该清单原文嵌入此处）。**其余分区一律禁用**：分类**可见**、内容为**占位说明 + 禁用原因**（如"等待 section schema 冻结"）；**必须包含**：**G2 回收站**（本轮未授权）、以及所有未列入清单的节。**禁止**为未冻结节发明键域、禁止用本地推断或 mock 填充。
- [ ] **AC3 数据面与 Secret 边界（设计 §5.3）**：读写只经 `settings_get` / `settings_update_section`（**整节 upsert，一次往返返回最新全量**）；**null 与空对象可区分**（frozen-None 通道），某节未设置时显示"未设置"占位并提供默认值填充动作；**任何设置界面不得把 Secret 写入或读自普通 settings DTO**；错误与日志只走**稳定错误类别 + 失败阶段 + 可采取动作**的脱敏文案，**不得**含原始响应/认证头/路径；TLS 校验关闭类危险操作须**明确危险确认且状态可见**（若 P15-C1 冻结了该面）。
- [ ] **AC4 状态矩阵（设计 §5.4）**：`loading` 骨架、`empty` 未设置占位、`error` 就地错误条 + code 本地化（`INVALID_REQUEST` 高亮对应字段、`CORE_UNAVAILABLE` 通道失败）、`disabled` 灰置分区、`progress` 保存 busy 态（按 07 §4 即时反馈）；**保存失败时表单保持用户输入不丢失**。
- [ ] **AC5 范围与证据**：**只做前端**（`apps/desktop/frontend/src/**`）；`npm --prefix apps/desktop/frontend test` 与 `run build` 归档**原始日志 + 退出码**；`tests/core/**` 与 Rust 套件**不回归**（原样归档）；**如实声明 GUI e2e 未运行**（无头 Windows 无法取得 WebView2 窗口句柄 `0x80070578`），**不得**把 DOM 单测表述为 e2e。
- [ ] **AC6 交付**：固定 commit + [Handoff](../templates/HANDOFF.md) + Canonical Evidence（sha256 按**磁盘字节**；**BL-17**：commit 列填**原样** `git rev-parse HEAD`；**BL-15**：`delivery_head` 不自引用即将产生的 SHA；**状态词法**：交付用 `in_review`，勿自造值；**BL-18**：**不得**把自请的审查写成"独立 Review"）。**不得**自行接收交付或合并主线。
