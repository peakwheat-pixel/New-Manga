# M2-S2 — Resource Channel Security Verification Spike

## 来源与目标

来源：[M2-S1 研究报告](../research/M2-S1_RESOURCE_CHANNEL_SPIKE.md) §8.2 的 **S1-B11**（检查→打开竞态 TOCTOU 产品级防护，`UNVERIFIED`）与 **S1-B12**（引用不透明性/路径保密性，`UNVERIFIED`），以及 [M2-S1 §7 产品阈值裁决](../../verification/M2-S1/product-thresholds-ruling-67c3d56.md)（2026-09-26，用户授权代行裁决）T5 的分层信任模型。M2-S1 交付记录明确要求"针对 S1-B11/S1-B12 冻结后续安全验证 Task"。

M2-S1 已实测两项缺口：①引用解析的 check-then-use 窗口在探针中为开（F-03/F-04/F-05/F-06），"先打开再从句柄校验"方向仅在隔离对照中拦截过一次替换（F-07/F-08），无系统性负向验证；②签名引用可无密钥解码出相对路径（F-01），而裁决 T5 要求 WebView 层引用保密（Core 侧映射 ID 方案已选定）。

本 Task 在隔离原型层（非产品代码）关闭这两项的验证缺口：

1. **S1-B11 防护验证**：实现"打开一次、从句柄校验身份+大小+包含性、读取只用该句柄"的参考解析器原型（Python/Win32），并按 S1-B11 解除条件①②③完成系统性负向探针：检查与打开之间并发替换文件内容、目录组件换 junction/符号链接、**等大小**替换内容（F-06 已证明仅大小复检不够），覆盖对手可写 scope root/父目录/卷前提；全部必须类型化拒绝；正向对照合法资源可读。
2. **S1-B12 映射 ID 验证**：实现 Core 侧随机映射 ID 参考原型（前端可见部分为不透明 ID，Core 查表解析），探针证明：无 Core 参与时无法从引用还原任何路径或资源标识（含字典攻击/ID 格式分析）；日志、错误与遥测中不泄漏映射表。

本 Task 不实现产品通道，不预选序列化库或 Tauri command 形态；验证结论供未来 Contract 修订与 runtime Task 引用。
