# P12-C1：导入侧 IPC 契约修订

## 来源与目标

- 来源（已冻结）：
  - **P18 真实运行暴露的缺口**：`ImportPages` 返回 **`UNKNOWN_COMMAND`**，端到端链路第一步即阻断
    （证据：`verification/P18/terminal-matrix.csv`、`verification/P18/raw/ja-r3/sidecar-stdout.jsonl`）。
  - 契约现状：`doc/contracts/M2-C1_TYPED_IPC_CONTRACT.md` §5 的 `ImportPages` 行**仍为未冻结**，
    原文写明"未来 IPC 必须由 Tauri host 授权并传递不透明、受限、可过期的 `ImportSourceRef`"；
    `ImportProgressChanged`（§6.2）仍为 **UNKNOWN / PROPOSAL**。
  - P08 [SCOPE_DRAFT §69–86](../../verification/P08/SCOPE_DRAFT.md) 需求表**第 32 行**（图片/文件夹/PDF/MOBI 导入）
    与工作包 **P12**（第 78 行）；P09 的"真实尺寸/受控来源/Managed Copy；损坏、加密、逃逸、重复、中断与 Unicode；源 hash 零变化"。
  - P16-C1 已确立 `ExportTargetRef`（**写**引用）并声明其与 `ImportSourceRef`（**读**引用）同源；
    本 Task 负责把这个**读**引用正式冻结。
- 目标：冻结导入侧的 wire 面与授权边界，使 **P12（书架导入）** 与 **P19（四页 E2E）** 有合法 wire 可用。
  本 Task **只做契约设计**，不实现 runtime、不改产品代码。

## 依赖、风险与阻塞

- `depends_on`：P09（`closed_with_limitations`，应用层导入已集成）、P16-C1（`done`，契约 rev 2.1 已集成）。

  本契约必须能承载 P09 的**全部**安全语义（源零写、逃逸拒绝、中断无坏 Page）。
