# M2-AC5-BUILD-FRESH-CHECKOUT：fresh checkout 构建链根治

## 来源与目标

- REBASELINE_PLAN §38 与 M2-AC5 integration checkpoint 登记候选：「fresh checkout 须先跑 build_sidecar.ps1」的构建顺序脆弱性——M2-AC5 集成 i1 首跑 EXIT=101 的实际后果（tauri `bundle.resources` 指向 gitignored `target/core-sidecar/core-sidecar`，缺失时 `generate_context!` 编译期失败且报错不可操作）。
- Goal 追溯：doc/GOAL.md（2026-09-30）清算集合 T2。
- 一个可观察的交付结果：fresh checkout（无 sidecar 产物）时 `cargo check/test/build` 失败并给出**可操作指引**（运行 `packaging/m2ac5/build_sidecar.ps1`）；sidecar 已存在时构建行为与现基线逐字节一致。

## 方案冻结（编排裁决，代理裁决留痕、用户可撤销）

1. **build.rs 前置探测**：`tauri_build::try_build` 之前探测 `apps/desktop/src-tauri/target/core-sidecar/core-sidecar` 是否存在；缺失则 `panic!` 输出可操作指引（脚本路径、README 路径、原因一句话）。不自动执行 PyInstaller（build.rs 内跑重构建魔法多、耗时不可控、依赖 build venv 存在性——fail-closed + 可诊断优先）。
2. **build_sidecar.ps1 增量短路**：目标 onedir 产物已存在且未传 `-Force` 时直接输出 skipped 并 EXIT=0（为自动化调用铺路；`-Force` 全量重建）。不改变现有构建产物布局与参数。
3. **不加 `beforeBuildCommand`**：它只在 tauri CLI 流程生效，覆盖不到 cargo check/test 主路径；build.rs 方案已覆盖全部路径。理由记录于 packaging/m2ac5/README.md。

## Acceptance Criteria

- [x] AC1（可诊断失败）：模拟缺失态（临时改名 target/core-sidecar）后 `cargo check` 失败且 stderr 含 `build_sidecar.ps1` 指引；恢复后构建正常（红绿证据）。
  - 实测注：本 worktree 为天然 fresh 态（无 sidecar、无 frontend dist），红证①直接 `cargo check` 取得，无需改名模拟；报错为 tauri-build 内部 `resource path ... doesn't exist`、无任何指引（与 i1 形态一致）。
  - 热态边界实证（DSH r1 P2-3，2026-09-30，r2-05）：热 target（曾成功构建）下改名 core-sidecar→core-sidecar.bak 后 `cargo check` **触发**指引——不 touch 对照与 touch 重跑两个分支均 panic `missing sidecar bundle` EXIT=101；触发机制（集成方按 DSH r2 P2-1 改正，依据 pinned 依赖源码）：`tauri.conf.json` 把 `target/core-sidecar/core-sidecar` 声明为 bundle resource → tauri-build 对非 glob 资源路径无条件发射 `cargo:rerun-if-changed` → cargo 规则「被 watch 的路径缺失 ⇒ 每次 fingerprint 检查都 dirty」使 build script 确定性重跑。原「tauri-build 重写 gen/schemas 等文件 mtime」的 churn 解释与 pinned 源码相抵（write-if-changed + gen/schemas 不在发射清单），已废弃；该确定性机制对 AC1 是更稳支撑。观察项保留：若上游改变资源 watch 行为，热态静默通过为理论边界。还原零残留。AC1 字面按 fresh checkout（冷 target）口径成立，热态场景同证成立。
- [x] AC2（增量短路）：`build_sidecar.ps1` 在产物存在时跳过（EXIT=0 + skipped 输出）；`-Force` 触发全量重建；脚本其余行为不变。
- [x] AC3（回归）：存在态下 `cargo test` 全套 EXIT=0（T1 后基线 44 passed/1 ignored）；`cargo build` 正常。
  - 实测注：以 `cargo check` EXIT=0 覆盖"构建正常"口径（dev profile Finished）。
- [x] AC4（文档）：packaging/m2ac5/README.md 记录 fresh checkout 流程与 beforeBuildCommand 不采用的理由。
- [x] AC5（范围纪律）：diff 仅触及允许路径；`diff --check` EXIT=0。
  - 实测注：try_build 运行重写的 `gen/schemas/**`、`permissions/autogenerated/**`（仅行尾表示）已按惯例 `git checkout --` 还原，未入提交。
