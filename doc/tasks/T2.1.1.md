## 来源与目标

This is Roadmap order 4 in the [Project Rebaseline Plan](../REBASELINE_PLAN.md),
after the integrated and verified T1.1.2 Region Canvas & Creator and T1.2.1
Settings UI & ViewModel contracts. The design source is the selected F ·
Graphite Atelier direction in
[`UI_UX_GUI_DESIGN.md` §6C](../contracts/UI_UX_GUI_DESIGN.md#6c-候选-f--graphite-ateliernd-1-已选方向),
with machine-readable values in
[`tokens-cand-f.json`](../design/tokens-cand-f.json). The current production
QML now consumes the F token layer; the verified integration record below
closes the implementation gap released by this Task.

The implementation must preserve the four existing top-level pages:
Bookshelf, Workbench, Reader, and Settings. This Task is visual/theme/layout
work only; it must not add a page, business behavior, data access path, or
new product interaction paradigm.

## Token delivery decision

Use mechanism **(a) `pragma Singleton` + `qmldir`**. Qoder must add one QML
theme module under `src/ui/qml/**`, register its token object in `qmldir`,
and make the production QML import path load the singleton through the real
`Main.qml`/`AppShell.qml` path. Do not add a Python bootstrap registration or
another parallel token source. The singleton must represent F exactly:

- color modes are byte-for-byte the F/A palette, including status and
  `*-soft` tokens;
- geometry is the F/B geometry set, including `card-w = 158px`;
- F excludes C glass, D top navigation, and E command palette behavior.

## Acceptance Criteria

- [x] The QML singleton loads through its `qmldir` module on the real
  production QML path; focused load coverage proves the module is not only a
  standalone file.
- [x] All four top-level pages and their shared visual components consume the
  F token source for palette, typography, spacing, radii, controls, and
  panel geometry. Existing object names and ViewModel context contracts stay
  intact.
- [x] The Bookshelf uses the F/B `card-w` token at exactly `158px`; the
  geometry test compares the production value with the F token rather than
  checking only a copied literal.
- [x] Accepted/completed and other state badges use the contract's semantic
  tokens and triple encoding (glyph + color + text). F contrast evidence
  covers the 24 F pairs, including the selected-row composite and direct
  `st-skip` pair: text `>= 4.5:1`, disabled/non-text `>= 3.0:1`.
- [x] A new focused guard test fails when a production QML visual property
  reintroduces a hard-coded color or token-governed size, and the test's
  evidence includes one mutation proving that it is discriminating. Only
  documented structural/data-driven exceptions may be allowlisted.
- [x] QML has no direct database, filesystem, provider, or model construction
  access; no ViewModel, port, Schema, provider/runtime, Settings, or bootstrap
  contract is changed.
- [x] Existing four-page navigation, object names, context-property loading,
  source-file protection, and fresh-data-root bootstrap behavior remain
  intact.
- [x] The delivery contains the implementation tests, a fixed delivery HEAD,
  a complete Handoff, and verification evidence. Qoder does not merge master.

## 依赖、风险与阻塞

Hard dependencies T1.1.2 and T1.2.1 are integrated and verified at the
Release Gate. The selected Design F contract is a design/reference input;
its HTML/Chromium audit is not Qt/QML implementation evidence. The main
implementation risks are a token module that loads only in a test fixture,
partial four-page adoption, and a source guard that catches only text or
文案 rather than actual color/size regressions. These are release criteria,
not reasons to expand scope.

If a requested fix requires bootstrap, ports, Schema, provider/runtime,
dependency, or Roadmap changes, stop that portion and return it to Codex for
scope reconciliation. Do not silently widen this Task.
