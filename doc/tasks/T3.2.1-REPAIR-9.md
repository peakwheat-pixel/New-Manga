# T3.2.1-REPAIR-9：修复阻断干净 Windows 启动的 Qt/ICU 依赖闭包

## 来源与目标

T3.2.1 AC3/AC4 的 2026-09-24 Windows Sandbox 实测在导入 `PySide6.QtCore`
时失败。固定候选源码 tree/base 是
`37d5488ebf8e33f897e802b4147cbd5fb1ad8e04`；产品打包实现来自该 tree 中的
`7d687f51567d4f947fee9b3f6eff4bc95e2b6413`。失败、SHA、PE 符号和单文件诊断
证据见 [`clean-sandbox-ac3-20260924`](../../verification/T3.2.1/clean-sandbox-ac3-20260924.md)。

包内 `icuuc.dll` 的 SHA-256 为
`93CC29031627A72A12C79328F441359CF0570F8E7341D9C4F4555F34D49BB779`，与宿主
Codex Poppler PATH 项同一文件；它不提供 `Qt6Core.dll` 导入的 20 个 ICU 名称。
Sandbox 自带 `System32\icuuc.dll` 提供这些符号；用它临时替换 Sandbox 副本中的
DLL 后 smoke 才 exit 0。该替换只用于定位原因，不能作为验收流程或最终方案。

目标是在固定构建输入下确定性地选择兼容的 Qt/ICU 依赖，使原样 onedir 包在干净
Windows Sandbox 启动，不依赖开发机 PATH 或诊断时替换文件。Task 只修复打包运行时
闭包，不代表 T3.2.1 AC3/AC6 全流程或最终 Release Gate 已通过。

## Acceptance Criteria

- [ ] PyInstaller 构建不再从未声明的宿主 PATH 注入不兼容的 `icuuc.dll`；Task
  记录所选 ICU 的来源、兼容性判断和目标 Windows 支持范围。不得未经验证就假设
  任意 Windows 版本都提供兼容的系统 ICU。
- [ ] 增加可重复的 packaging 检查：核对 `Qt6Core.dll` 的 ICU imported symbols
  均能由最终选定的依赖解析；遇到缺项时检查必须失败。检查不依赖固定机器上的
  Poppler 路径或固定 ICU hash。
- [ ] 从本 Task 固定 delivery 构建的新 onedir 包，在原样、不替换 DLL、不追加
  PATH 的 Windows Sandbox 中通过 `NewManga.exe --smoke-test --data-root <isolated>`，
  exit 0 且数据库创建；记录 Sandbox OS、无 Python/source/venv/developer PATH 的
  检查、exe/package hash、stdout/stderr 和 exit code。
- [ ] 包中 Qt/QML 资源检查通过，`PySide6.QtCore` 可导入。至少两次构建的原始日志、
  manifest 和差异说明入库；不宣称两次产物字节一致，除非 manifest 比较确实为零差异。
- [ ] 修复范围、验证证据和剩余 Gate 如实写入新 Handoff；DeepSeek Harness 对固定
  Delivery Head 独立复审 `approved`。在 Codex 完成 T3.2.1 全量 Release Gate 前不
  得合并 master。
