### 2026-10-16 导出目标写入边界的架构裁决（Coordinator, dsh, epoch 5）

**阻塞事实**（Owner 上报，`verification/P16-C1/decision-blocker.md`）：D04 §37 要求用户选择导出目标位置、D08 `AC-EXPORT-002` 要求记录输出路径；
而 `M2-C1` §10 规定"前端路径本身不是写权限"，且既有 resource reference 是为 **Core 控制的读取**设计的，未覆盖导出写目标。

**裁决：采用「可信 host 中介」方案（Owner 提出的选项 1）。** 依据：

1. **与 AD-001 冻结原则一致**：React/WebView 不直接访问任意 OS 路径，路径能力经 Tauri IPC 与 Python Core 的冻结契约表达。
2. **与既有模式架构同源**：`M2-C1` §5 `ImportPages` 行已冻结"由 Tauri host 授权并传递**不透明、受限、可过期**的 `ImportSourceRef`"，
   且 §10.1/§10.2 的大媒体/安全语义已由 M2-C2 ruled。导出目标应复刻同一套 host 授权原则，而非发明第二套。
3. **属技术实现边界决策，不是产品取舍**：产品需求（选择目标、记录路径、完成后可打开文件夹）已在 D04 §37 与 D08 `AC-EXPORT-002` 冻结；
   待决的是"如何安全表达写授权"，属架构职责范围。

**对 P16-C1 的强制约束**：

- `StartExport` 的目标**不得**是任意路径字符串；必须是 **Tauri host 签发的不透明、受限、一次性（或可过期）写引用**；
- 引用必须在契约中定义 **issuer（Tauri host）、scope（单次导出目标）、过期/一次性语义、以及 Core 侧的解析与拒绝规则**；
- **React/WebView 不得接收或使用**该引用或其背后路径；
- Core 必须**拒绝非 host 签发的目标**，并保持**源零写**；
- 该模式必须在契约中与 §10 的既有 import 授权模式**显式对齐**，并在 AC6 对照中说明二者的一致性与差异（读引用 vs 写引用）。

**若 Owner 认为该裁决与 AD-001 / §10 冲突、或确需先建立独立宿主能力契约**，须给出**具体冲突证据**（引用 AD-001 条款与 §10 原文）
并重新上报；**不得以"未冻结"为由空转**。
